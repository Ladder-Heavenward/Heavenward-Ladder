Can a Program Be Checked by Running a Blurred Copy?

Can a program be checked by running a blurred copy? Rung 41 proved that no machine decides what programs do. Yet the software that flies airliners is checked by machine. The trick is to blur: replace each number by its sign, run the program on signs, and whatever the blurred run proves is true of every real run. That works because blurring and sharpening are a pair of rung 47, one left of the other, and soundness falls out of the pair in three lines. Signs are coarse; intervals are finer, and a technique called widening makes the analysis of a loop stop. Rung 41 still forbids an exact check, so every such check sometimes raises a false alarm. The method dates from 1977; from 2003 to 2005 it showed the flight-control software of two airliners free of run-time errors, with no false alarm.

Blur α sends a set of numbers to the least sign covering it; sharpen γ sends a sign back to its numbers. α(A) ≤ s exactly when A ⊆ γ(s): α ⊣ γ. The blurred operation f♯(s) = α(f(γ(s))) is sound: f(A) ⊆ γ(f♯(α(A))). Intervals with widening make loops stop. By 41e2 no check of a property of what programs do is exact, so a sound check has false alarms.

inf6.1Running on Signs

Replace every number by its sign: −, 0 or +, with one more value ⊤, “sign unknown”. Multiplying signs is exact: the sign of xy is the sign of x times the sign of y. Adding is not: + plus + is +, but + plus − can be anything, so it is ⊤.

Sign-run technique: for x · x + 1, the blurred run gives + for every input sign, so x · x + 1 is positive for every number x.

x \in \{-, 0, +\} \Rightarrow x \cdot x \in \{+, 0, +\} @@ minus times minus is plus; 0 times 0 is 0
x \cdot x \in \{0, +\},\ 1 \text{ is } + @@ the sign of the constant
0 + (+) = +,\quad (+) + (+) = + @@ the sum table, both cases
\htmlClass{new}{x \cdot x + 1 \text{ is } + \text{ for every } x} \quad \blacksquare @@ three blurred runs cover all numbers

Three runs on signs did the work of endless runs on numbers. For x · x − 1 the blurred run ends at 0 + (−) = − and (+) + (−) = ⊤: the blur cannot decide, and rightly, since the real answer depends on x.

inf6.2Blur and Sharpen

Order the signs by “says less”: −, 0 and + each lie below ⊤, and add ⊥, “no number”, below them all. Order sets of numbers by ⊆. Both are categories by 47a2. Sharpen γ sends a sign to its numbers: γ(+) is the positive numbers, γ(⊤) is all numbers, γ(⊥) is none. Blur α sends a set A to the least sign whose sharpening holds A.

Blur-pair technique: α(A) ≤ s exactly when A ⊆ γ(s): blur is left of sharpen.

\alpha(A) = \text{least } s \text{ with } A \subseteq \gamma(s) @@ the definition: such an s exists, since γ(⊤) holds every A
\alpha(A) \le s \Rightarrow A \subseteq \gamma(\alpha(A)) \subseteq \gamma(s) @@ γ keeps order
A \subseteq \gamma(s) \Rightarrow \alpha(A) \le s @@ α(A) is the least such s
\htmlClass{new}{\alpha(A) \le s \iff A \subseteq \gamma(s)\text{: } \alpha \dashv \gamma} \quad \blacksquare @@ 47f3: between orders, left of says exactly this

47f3 found that between two orders a left-and-right pair is just this “exactly when”. Blur loses information and sharpen cannot restore it: γ(α({1, 2})) is all the positive numbers.

inf6.3Soundness in Three Lines

Each operation f on numbers acts on sets of numbers: f(A) is the set of f(x) for x in A, and A ⊆ B gives f(A) ⊆ f(B). Its blurred copy is f♯(s) = α(f(γ(s))): sharpen, apply, blur.

Blur-sound technique: f(A) ⊆ γ(f♯(α(A))) for every set A: whatever the blurred run says covers every real run.

A \subseteq \gamma(\alpha(A)) @@ the blur-pair technique with s = α(A)
f(A) \subseteq f(\gamma(\alpha(A))) @@ f keeps ⊆
f(\gamma(\alpha(A))) \subseteq \gamma(\alpha(f(\gamma(\alpha(A))))) = \gamma(f^{\sharp}(\alpha(A))) @@ the first line again, for the set f(γ(α(A)))
\htmlClass{new}{f(A) \subseteq \gamma(f^{\sharp}(\alpha(A)))} \quad \blacksquare @@ the two inclusions in a row

Run a program step by step, and the same holds for the whole run, since each step’s output covers the next step’s input. Nothing about signs was used: any blur that is left of a sharpen gives sound checks. The arrows carry the plan, and the choice of blur is let go.

inf6.4Intervals and Widening

A finer blur keeps a least and greatest value, an interval [a, b], with −∞ and ∞ allowed. Take the loop “x ← 0; while x < 100: x ← x + 1”. The analysis looks for a set of values that the loop’s entry holds every time. Starting at [0, 0], each round adds one more value: [0, 1], [0, 2], and so on for a hundred rounds; with a test x < 10⁹ it would take a billion.

Widen technique: widening, which sends an end that keeps moving to ±∞, makes the loop analysis stop after finitely many rounds, and the result still covers every run.

[0, 0] \to [0, 1] @@ the upper end moved
[0, 0] \mathbin{\nabla} [0, 1] = [0, \infty) @@ widen: a moving end jumps to ∞
x \in [0, \infty),\ x < 100 \Rightarrow x + 1 \in [1, 100] \subseteq [0, \infty) @@ one more round changes nothing: stopped
\htmlClass{new}{\text{at the exit } x \ge 100 \text{ and } x \in [0, \infty)\text{: } x \in [100, \infty)} \quad \blacksquare @@ each end can jump at most once, so at most two widenings

The answer is sound but blurred: the true exit value is exactly 100. A second pass that narrows, running the loop once more on [0, ∞) and keeping the test, recovers x ∈ [100, 100] here. In general widening trades sharpness for stopping.

inf6.5What Rung 41 Forbids

“This program never divides by zero, on any input” is a property of what a program does, and it is not trivial: some programs have it and some do not.

False-alarm technique: a machine check that never says “safe” for an unsafe program must say “unsafe” for some safe one.

\text{suppose the check is also never wrong about safe programs} @@ no false alarm
\text{then it decides which codes } \langle M \rangle \text{ are safe} @@ it is right both ways
\text{safety is about what machines do, and not trivial} @@ two programs computing the same function agree on it
\htmlClass{new}{\text{contradiction with 41e2: some false alarm}} \quad \blacksquare @@ the behaviour technique

41e2’s behaviour technique leaves exactly one door open: a check that may wrongly say unsafe, never wrongly safe. The blurred run is such a check. The art is a blur fine enough that the false alarms are rare on the programs people write, and coarse enough to run fast.

Open questions

These are open: the field is still asking them. There is no key; a good attempt is a reason, a guess, or a better question.

∞r.oq.1Which blurs are both cheap and sharp? For code full of real-number arithmetic, as in physics and control, the known blurs either run slowly or raise many false alarms, and finding ones that do neither is open. The same method is now used to check machines that learn, by running a blurred copy of a network on a whole region of inputs at once; how far that can scale to large networks is open.
A short history · told from more than one side

How we got here

In 1977 two computer scientists set out the method: a program’s meaning is a set of runs, a blur is one half of a pair of order-keeping maps, and every blurred run is sound. Widening was part of the method from the start, so that loops could be analysed in finitely many steps.

From 2001 a team built an analyzer aimed at the flight-control software of airliners, programs of over a hundred thousand lines written in a restricted style. In November 2003 it proved the primary flight-control software of one airliner free of run-time errors with no false alarm, and in 2005 that of a larger one.

The analyzer was later sold for safety-critical code, and from 2018 the method was carried to checking machines that learn: a network is run on a blurred region of inputs, to prove that every input in the region gets the same answer.

The accepted names

The method is abstract interpretation; α is the abstraction map and γ the concretization; the pair is a Galois connection; f♯ = α ∘ f ∘ γ is the best abstract transformer. The signs form the sign domain, intervals the interval domain; ∇ is widening, and the second pass is narrowing. A check that never says safe wrongly is sound; a false alarm is a false positive. The analyzer of 2003 is Astrée; the flight-control software was that of the Airbus A340 and, in 2005, the A380.

Who said it first

Patrick Cousot and Radhia Cousot, “Abstract interpretation” (POPL 1977). The Astrée team at the École normale supérieure, led by Patrick Cousot, with Radhia Cousot, Jérôme Feret, Laurent Mauborgne, Antoine Miné, David Monniaux and Xavier Rival (2001-2005).
