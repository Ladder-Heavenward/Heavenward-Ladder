How Can Randy Tell the Message Was Not Changed?

How can Randy tell the message was not changed? Hiding a message is not the same as protecting it. Mike cannot read Evita’s scrambled order to her bank, but he may be able to change it, and the bank would unscramble his change without a murmur. Every secure connection today adds a short check, a tag, that only the key holders can make. This page shows a change slipping through a perfect scramble, builds a tag from a polynomial whose secret is where it is evaluated, counts the forger’s chance by counting roots, and shows why the tag must be checked before anything else, and why its one-time part must never be used twice.

Adding bits to a scrambled message adds the same bits to the message inside. So tag it: read the blocks as numbers mod a prime p and evaluate their polynomial at a secret r, plus a one-time secret s. A different message with the same tag makes r a root of a nonzero polynomial of degree at most n, which has at most n roots: the forger wins with chance at most n/p. Tag the scrambled message and check it first; never reuse r and s.

27crypt21Hidden Is Not Safe

Say Evita scrambles her order by adding, without carry as in 20·crypt2, a stream of key bits k that only she and the bank know: she sends c = m ⊕ k. Mike cannot read m. But he guesses what it says.

c = m \oplus k @@ perfectly hidden
\text{Mike sends } c \oplus d @@ d any bits he chooses
(c \oplus d) \oplus k = m \oplus d @@ the bank unscrambles
\htmlClass{new}{\text{“pay 100” becomes “pay 900”, if Mike knows where the digit sits}} @@ without ever reading it

A scramble can hide a message perfectly and still let it be changed unseen. The bank needs a second thing: a check that only a key holder could have made for exactly this message.

27crypt22A Tag From a Polynomial

From here on, on this page, the message is cut into blocks m₁, …, mₙ, each read as a number mod a prime p. Evita and the bank share two more secrets, numbers r and s mod p. The tag is the polynomial with the blocks as its coefficients, evaluated at r, plus s.

t = m_1 r + m_2 r^2 + \cdots + m_n r^n + s \pmod p @@ the tag
r = 7,\ s = 20,\ (m_1, m_2) = (3, 5) @@ toy secrets and message
3 \cdot 7 + 5 \cdot 49 + 20 = 286 @@ work it out
\htmlClass{new}{t = 286 - 2 \cdot 101 = 84} @@ sent with the message

The bank recomputes the tag from what arrives and compares. Changing m₂ to 6 changes the tag to 32: Mike would have to know r to fix it.

27crypt23The Forger’s Chance, by Counting Roots

Mike sees one message m and its tag t, and sends a different m′ with a tag t′ of his choice. He wins if t′ is the right tag for m′.

\textstyle\sum m_i r^i + s = t,\ \ \sum m\prime_i r^i + s = t\prime @@ both tags right
\textstyle\sum (m_i - m\prime_i)\, r^i - (t - t\prime) = 0 @@ subtract: s cancels
\text{a nonzero polynomial of degree} \le n \text{ in } r @@ since m′ ≠ m
\text{at most } n \text{ roots mod } p @@ factor out each root (25d); mod a prime, no zero products
\htmlClass{new}{\text{chance} \le n/p} @@ r was any of p values, each equally likely

Root-count technique: a forger must hit a root of a nonzero polynomial of degree at most n, so wins with chance at most n/p, however clever. With p near 2130 and a million blocks, that is below 2−110.

27crypt24Scramble, Then Tag, Then Check First

Evita has two jobs: scramble and tag. The order matters, and so does what the bank does first.

c = \text{scramble}(m),\ \ t = \text{tag}(c) @@ tag what is sent, not what is hidden
\text{bank: check } t \text{ against } c @@ before anything else
\text{wrong: throw it away, unread} @@ no unscrambling, no error message
\htmlClass{new}{\text{right: only now unscramble}} @@ a changed message never reaches the unscrambler

Tag the scrambled message, and check the tag before unscrambling, so that nothing a forger made is ever handled. Banks that unscrambled first, and answered differently when the result looked odd, have leaked whole messages a guess at a time through those answers.

27crypt25Never the Same Secrets Twice

The root count assumed Mike saw one tag. Say Evita reuses r and s for a second message, (3, 6), whose tag is 32, and Mike sees both.

84 - 32 = (5 - 6)\,r^2 \pmod{101} @@ subtract: s cancels
-r^2 \equiv 52,\ \ r^2 \equiv 49 @@ −52 ≡ 49 mod 101
r \equiv 7 \text{ or } 94 @@ the two square roots
\htmlClass{new}{\text{Mike can now tag anything}} @@ and s follows from either tag

One-time technique: the secret s, or the r and s together, must be fresh for every message; a reused pair hands the forger r. Real systems make them from the key and a number used once, a counter that never repeats.

Accepted names

A tag is a message authentication code (MAC). The polynomial tag is a polynomial MAC, a case of Carter-Wegman authentication with a universal hash. Changing a scramble unseen is malleability. Scrambling and tagging together is authenticated encryption; tagging the scramble is encrypt-then-MAC. The number used once is a nonce, and leaking a message through error answers is a padding oracle attack.

Who said it first

Larry Carter and Mark Wegman built tags from hash families of this kind in 1979 and 1981. Polynomial tags with a prime near 2130 were published by Daniel Bernstein in 2005, and are used in secure web connections today.
