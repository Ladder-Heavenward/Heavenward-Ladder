41e · proof

Undecidable Everywhere

One question no machine answers would be a curiosity. This step shows it is a seed. The tool is a way of turning one question into another: a recipe that sends each case of the first question to a case of the second, with the same answer. If the second could be decided, so could the first. Run backwards, the stopping question’s refusal spreads to every question it can be turned into. Does this machine stop on a blank tape? Does it stop on every input? Do these two programs do the same thing? Each is undecidable, and the reason is one argument: any question about what a program does, as opposed to how it is written, is undecidable unless its answer is always the same. Then the spread reaches mathematics. No machine decides which statements the axioms of arithmetic reach, so the hope of a recipe that settles every question by calculating is closed. And it reaches the oldest kind of question there is, whether an equation in whole numbers has a solution. Solutions can be searched for. In 1970 it was shown that no recipe can always say there are none.

If a recipe turns one question into another with the same answers, a decider for the second gives one for the first. From stopping, the refusal spreads: every question about what programs do is undecidable unless trivial, no machine decides what arithmetic reaches, and no machine decides whether a whole-number equation has a solution.

41e1Turning One Question Into Another

A set A reduces to a set B when some machine computes a function f with: x is in A exactly when f(x) is in B. f turns every case of A into a case of B with the same answer.

Reduction-carries technique: if A reduces to B and B is decided, then A is decided; so if A reduces to B and A is not decided, B is not decided.

f \text{ computed},\ \allowbreak \ x \in A \iff f(x) \in B,\ \allowbreak \ D \text{ decides } B @@ given
\text{on } x\text{, }\allowbreak \text{compute } f(x)\text{, }\allowbreak \text{then }\allowbreak \text{run } D \text{ on it} @@ two machines in a row (41b1, putting inside)
\text{the }\allowbreak \text{run }\allowbreak \text{stops, }\allowbreak \text{and }\allowbreak \text{says }\allowbreak \text{yes }\allowbreak \text{exactly }\allowbreak \text{when } f(x) \in B @@ f stops on every input; D decides
\htmlClass{new}{\text{it }}\allowbreak \htmlClass{new}{ \text{decides } A} \quad \blacksquare @@ x ∈ A exactly when f(x) ∈ B; the second half is the first turned round (1b)

One example first. Does M stop when started on a blank tape? From ⟨M⟩ # w build M_w: write w on the tape, walk back to the first cell, then act as M. M_w on a blank tape does what M does on w. So H reduces to the blank-tape question, and the blank-tape question is not decided.

41e2What Programs Do

Each machine computes a function, with no value where the machine never stops. A property P of such functions is about what machines do: two machines computing the same function both have it or neither does. It is trivial when every machine’s function has it, or none does.

Behaviour technique: for every property about what machines do that is not trivial, no machine decides which codes ⟨M⟩ have it.

\text{the }\allowbreak \text{function }\allowbreak \text{with }\allowbreak \text{no }\allowbreak \text{values }\allowbreak \text{lacks } P;\ \allowbreak \ M_1\text{’s }\allowbreak \text{function }\allowbreak \text{has } P @@ not trivial; if the empty function has P, run the proof on not-P
N_{M,w}\text{: }\allowbreak \text{on }\allowbreak \text{input } x\text{, }\allowbreak \text{first }\allowbreak \text{run } M \text{ on } w\text{, }\allowbreak \text{then }\allowbreak \text{run } M_1 \text{ on } x @@ built from ⟨M⟩ # w by a recipe
M \text{ stops }\allowbreak \text{on } w \Rightarrow N_{M,w} \text{ computes }\allowbreak \text{what } M_1 \text{ computes: }\allowbreak \text{it }\allowbreak \text{has } P @@ the first part ends, the second is M₁
M \text{ never }\allowbreak \text{stops }\allowbreak \text{on } w \Rightarrow N_{M,w} \text{ has }\allowbreak \text{no }\allowbreak \text{values: }\allowbreak \text{it }\allowbreak \text{lacks } P @@ the first part never ends
\htmlClass{new}{H \text{ reduces }}\allowbreak \htmlClass{new}{ \text{to } P\text{; } P \text{ is }}\allowbreak \htmlClass{new}{ \text{not }}\allowbreak \htmlClass{new}{ \text{decided}} \quad \blacksquare @@ the reduction-carries technique

So none of these is decided: whether a machine stops on every input; whether it ever outputs 0; whether its function is that of adding one; whether two machines compute the same function. Questions about how a program is written are another matter. Whether a table has five rows is decided by counting. The line runs between the text of a program, which can be read, and its behaviour, which can only be run.

41e3What Arithmetic Reaches Is Not Decided

Reach-undecided technique: no machine decides which statements PA reaches.

\sigma_{M,w}\text{: } \exists y\ \text{“the }\allowbreak \text{run }\allowbreak \text{of } M \text{ on } w \text{ has }\allowbreak \text{stopped }\allowbreak \text{by }\allowbreak \text{step } y\text{”} @@ a search statement, written by 41b3 from ⟨M⟩ # w, by a recipe
M \text{ stops }\allowbreak \text{on } w \Rightarrow \sigma_{M,w} \text{ true} \Rightarrow PA \vdash \sigma_{M,w} @@ the search-reached technique (38g4)
M \text{ never }\allowbreak \text{stops }\allowbreak \text{on } w \Rightarrow \sigma_{M,w} \text{ false }\allowbreak \text{in } N \Rightarrow PA \nvdash \sigma_{M,w} @@ PA reaches only statements true in N (38g2)
\htmlClass{new}{H \text{ reduces }}\allowbreak \htmlClass{new}{ \text{to }}\allowbreak \htmlClass{new}{ \text{what }}\allowbreak \htmlClass{new}{ \text{PA }}\allowbreak \htmlClass{new}{ \text{reaches}} \quad \blacksquare @@ the reduction-carries technique

38b listed what PA reaches; now it is clear the list cannot be made into a decider. Run the same reduction with a finite collection in place of PA, the six lines of 38g2 without induction, which still reach every true search statement (held in trust here; the proof of 38g4 uses no induction). A finite collection G reaches σ exactly when “the lines of G, joined, imply σ” is true in every world (38d). So no machine decides which statements are true in every world. The question was asked in 1928 as a challenge, and this is its answer.

41e4Equations in Whole Numbers

Take a polynomial equation p(x₁, …, xₖ) = 0 with integer coefficients, and ask whether it has a solution in whole numbers. x² − 2y² = 1 has x = 3, y = 2. x² + y² = 3 has none: a square leaves remainder 0 or 1 by 4, so a sum of two squares leaves 0, 1 or 2, and 3 leaves 3 (4j).

Equation-search technique: the equations with a whole-number solution are listed.

\text{list }\allowbreak \text{the }\allowbreak \text{lists } (x_1, \dots, x_k) \text{ of }\allowbreak \text{whole }\allowbreak \text{numbers} @@ by largest entry, then in order, as 35a listed pairs
\text{at }\allowbreak \text{each, }\allowbreak \text{compute } p(x_1, \dots, x_k) @@ adding and multiplying, built without search
\text{stop }\allowbreak \text{in }\allowbreak \text{yes }\allowbreak \text{at }\allowbreak \text{the }\allowbreak \text{first }\allowbreak \text{zero} @@ one search (41b1)
\htmlClass{new}{\text{yes }}\allowbreak \htmlClass{new}{ \text{exactly }}\allowbreak \htmlClass{new}{ \text{on }}\allowbreak \htmlClass{new}{ \text{the }}\allowbreak \htmlClass{new}{ \text{solvable }}\allowbreak \htmlClass{new}{ \text{equations}} \quad \blacksquare @@ if none, the search never ends

That is one half, and it is easy. The other half was proved in 1970, after twenty years of work by four people: every listed set A of numbers has a polynomial p with integer coefficients such that a is in A exactly when p(a, x₁, …, xₖ) = 0 has a whole-number solution. Take A to be the codes of stopping pairs, and the stopping question reduces to solvability. So no machine decides whether an equation in whole numbers has a solution. The ladder names this result and does not prove it: its proof turns the run of a machine into an equation, using the solutions of x² − dy² = 1 to make powers out of adding and multiplying.

The remainder argument for x² + y² = 3 is a certificate that no solution exists. Some equations have such certificates and some do not, and no machine finds the certificate whenever there is one.

The accepted names

The reduction of 41e1 is a mapping reduction, or many-one reduction, written A ≤ₘ B. The blank-tape question is the blank-tape halting problem. The behaviour technique is Rice’s theorem. The reach-undecided technique is Church’s theorem on the undecidability of arithmetic, and the question of truth in every world is the Entscheidungsproblem, posed by David Hilbert and Wilhelm Ackermann in 1928. The question of whole-number equations is Hilbert’s tenth problem (1900), and its negative answer is the Matiyasevich, or MRDP, theorem; x² − dy² = 1 is Pell’s equation.

Who said it first

Alonzo Church (1936) and Alan Turing (1936) answered the Entscheidungsproblem, each by his own calculus. Henry Gordon Rice proved his theorem in 1951, published 1953. Martin Davis, Hilary Putnam and Julia Robinson reduced Hilbert’s tenth problem to one fact about growth by 1961, and Yuri Matiyasevich supplied it in 1970, using the Fibonacci numbers. The old hope of settling disputes by calculating is Gottfried Leibniz’s “calculemus”.

A proof that is not allowed

“Whether M stops on every input is a property about what M does. So by the behaviour technique it is not listed.” Not allowed: the behaviour technique says not decided, and says nothing about listing. In fact neither this set nor its outside is listed, but that needs its own argument.
