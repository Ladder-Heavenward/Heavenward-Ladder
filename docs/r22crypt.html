Can Two Files Have the Same Fingerprint?

Can two files have the same fingerprint? A fingerprint of a file is a short code worked out from the whole file, the same way every time. Change one letter of the file and the code changes beyond recognition. Computers use fingerprints to check that a download arrived whole, to store passwords without storing the passwords themselves, and to name every version of a program. Each of these uses trusts that two different files never share a fingerprint. But there are far more files than codes, so some pairs of files must share one. What makes it hard is to tell how soon such a pair turns up, when nobody can predict the codes. This page shows, with counting, rung seventeen’s exp and rung twenty-two’s rare events, that among codes drawn at random a shared code turns up far sooner than the number of codes suggests, after about its square root, and why fingerprints are made twice as long as a count of codes alone would ask.

Draw codes at random, one after another. The chance that no code matches an earlier one is a product of shrinking fractions, one for each draw. Count the pairs of draws, and share them out over the codes. The chance of a match is fenced above by that share, and below by a fence built from rung seventeen’s exp of it. So a match is as likely as not once the pairs are about seven tenths of the codes, and that happens at about the square root of the number of codes. Twenty-three people share a birthday as often as not. A fingerprint holds out against a search for any matching pair only half as many bits as it has.

22crypt1Shared Fingerprints Must Exist

From here on, on this page, a fingerprint is a function F from files to codes of b bits, so there are N = 2ᵇ codes. A collision is two files f ≠ g with F(f) = F(g).

\text{files of 1 kB}:\ 2^{8192} @@ counted-functions (4k): 8192 bits, each 0 or 1
\text{codes of 256 bits}:\ 2^{256} @@ the same count
2^{8192} > 2^{256} @@ powers of 2 rise (4g)
\htmlClass{new}{\text{some two files of 1 kB share a code}} \quad \blacksquare @@ the pigeonhole technique (8·cb5)

Collision technique: a fingerprint of b bits on files longer than b bits always has collisions; what can be made hard is only to find one. So the question is how many files someone must fingerprint before two of them collide.

Nobody can predict a good fingerprint’s codes. So take as a working guess that the codes of n different files behave like n codes drawn at random: every list of n codes is equally likely. The guess is tested by the fingerprint’s makers, not proved.

22crypt2No Match, Counted

\text{lists of } n \text{ codes}:\ N^n @@ counted-functions (4k)
\text{lists with no two alike}:\ N(N - 1)\cdots(N - n + 1) @@ arrangements (4k)
q_n = \tfrac{N(N-1)\cdots(N-n+1)}{N^n} @@ chance by counting (4·stat), every list equally likely
\htmlClass{new}{q_n = (1 - \tfrac1N)(1 - \tfrac2N)\cdots(1 - \tfrac{n-1}{N})} \quad \blacksquare @@ one fraction for each draw after the first

No-match technique: among n codes drawn at random from N, the chance that no two match is the product of 1 − k/N for k from 1 to n − 1. The chance of a match is 1 − qₙ.

Birthdays are codes, too: take N = 365, every day equally likely, and leave out the leap day. For 23 people, q₂₃ ≈ 0.4927. So a shared birthday among 23 is a little more likely than not: about 0.507.

22crypt3Fenced by e

The product is hard to read. Fence it. Write λ = n(n − 1)/(2N): the number of pairs of draws, n(n − 1)/2, shared out over the N codes.

1 - x \le e^{-x} \text{ for } x \ge 0 @@ exp(−x) − (1 − x) is 0 at 0, and its slope 1 − exp(−x) ≥ 0 (14d, 17f)
q_n \le e^{-1/N} e^{-2/N} \cdots e^{-(n-1)/N} = e^{-\lambda} @@ multiply the fences; adding becomes multiplying (17e); 1 + ⋯ + (n − 1) = n(n − 1)/2 (15g)
q_n \ge 1 - (\tfrac1N + \tfrac2N + \cdots + \tfrac{n-1}{N}) = 1 - \lambda @@ (1 − x₁)⋯(1 − xⱼ) ≥ 1 − (x₁ + ⋯ + xⱼ) for each xᵢ in [0, 1], by induction (4c)
\htmlClass{new}{1 - e^{-\lambda} \le 1 - q_n \le \lambda} \quad \blacksquare @@ take each fence from 1

Pair technique: with λ the number of pairs per code, the chance of a match lies between 1 − e−λ and λ. For 23 birthdays λ ≈ 0.693, so the chance is fenced between 0.500 and 0.693; the count gave 0.507.

The lower fence is 22j’s rare-events technique at work. Each of the n(n − 1)/2 pairs is a rare event, matching with chance 1/N, and 22j gives the chance that none of them happens as about e−λ. When N is large and λ is not, the fence and the count agree to many places.

22crypt4About the Square Root

1 - e^{-\lambda} = \tfrac12 \iff \lambda = \ln 2 @@ exp undoes ln (17e)
n(n - 1) = 2N\ln 2 \Rightarrow n \approx \sqrt{2\ln 2}\,\sqrt{N} \approx 1.18\sqrt{N} @@ n − 1 is about n when n is large
N = 2^b \Rightarrow \sqrt{N} = 2^{b/2} @@ powers (17g)
\htmlClass{new}{\text{a } b\text{-bit fingerprint gives up a collision after about } 1.18 \cdot 2^{b/2} \text{ tries}} \quad \blacksquare @@ the lower fence

Matching-pair technique: a match among random codes is as likely as not after about 1.18 √N of them, so a b-bit fingerprint holds out only about b/2 bits against a search for any colliding pair. The pairs grow as n², and n² outgrows n (22k’s ranking technique), so they catch up with the codes long before the draws do.

b = 28:\ \ 1.9 \times 10^{4} \text{ tries} @@ 7 hex digits: at once
b = 128:\ \ 2.2 \times 10^{19} \text{ tries, about 8 months} @@ within reach of one large effort
b = 160:\ \ 1.4 \times 10^{24} \text{ tries, about } 45\,000 \text{ years} @@ by brute search alone
\htmlClass{new}{b = 256:\ \ 4.0 \times 10^{38} \text{ tries, about } 10^{19} \text{ years}} @@ out of reach

That is why fingerprints are made long. A password of 128 random bits holds out for 2¹²⁸ guesses (17·crypt). A fingerprint must have 256 bits to hold out as long against a search for a colliding pair.

The accepted names

A fingerprint is a cryptographic hash function, and its code a hash value or digest. The shared-birthday count is the birthday problem, often called the birthday paradox, and a search for any colliding pair is a birthday attack. A search for a second file matching one given file’s code, as in 22·crypt.5, is a second-preimage attack. Common fingerprints: MD5 (128 bits), SHA-1 (160 bits) and SHA-256 (256 bits). The version-control program git names every stored version by its SHA-1 code and shows a few hex digits of it as a short name.

Who said it first

The shared-birthday count is usually credited to Richard von Mises (1939). Gideon Yuval (1979) turned it into an attack on signed messages. Xiaoyun Wang and her colleagues found collisions in MD5 in 2004 and, in 2005, published a method for SHA-1 far faster than 2⁸⁰ tries; the dispute staged in 22·crypt.6.5 followed. In 2012 the Flame malware forged a software-signing certificate with an MD5 collision. In 2017 Marc Stevens and colleagues at CWI Amsterdam and Google showed the first SHA-1 collision, two different PDF files with one code, after about 2⁶³ computations.
