4l · technique

What a Recipe for Answers Is Made Of

4j ran the gcd algorithm. 4i wrote numbers in twos. 4f added by counting on. Each of these takes a starting point and makes the same kind of move again and again until a check says stop. This step takes such a recipe apart. It asks what its parts are, why it stops, and why its answer is right.

A recipe for answers needs two proofs, not one. One says every run stops. The other says the answer at the stop is right. A number that falls on every move gives the first. A statement that every move keeps gives the second.

4l1A Recipe, Part by Part

A recipe for answers has five parts.

  • A state: what the recipe holds between moves, such as a pair of numbers.
  • A start: the state made from the input.
  • A stop test: a settled statement about the state (4h7), so it can always be checked.
  • A move: a function from states to states (4d2). It is used only when the stop test fails.
  • An output: what is read off the state at the stop.

The accepted name for a recipe like this is an algorithm. From here on the ladder uses that word.

An algorithm is an operator built from repeating: a statement that names a start, a move and a stop test. Carry it out, and the move repeats until the test says stop, and the test is sure to say it. What is left is the output. A clock’s hand repeats too, but it never stops, so it is a cycle, not an algorithm.

From here on, the run of an algorithm is the function run on ℕ given by the recursion technique (4d8): run(0) is the start. run(n + 1) is the move applied to run(n) when run(n) fails the stop test, and is run(n) itself when it passes. The run stops when some run(n) passes the stop test.

Example: the gcd algorithm of 4j12, part by part.

\text{state: } (u, b) \text{, a pair of numbers} @@ the state
\text{start: } (a, b) @@ the two numbers given
\text{stop test: } b = 0 @@ settled, by settled-order
\text{move: } (u, b) \mapsto (b, r),\ \ u = b \cdot q + r,\ \ r \lt b @@ division-with-remainder (4j7); used only when b ≠ 0
\text{output: } u @@ read off at the stop
(84, 36) \mapsto (36, 12) \mapsto \htmlClass{new}{(12, 0)} @@ two moves; 12 is the output

Writing an algorithm down is naming its five parts; nothing else may happen between moves.

4l2Why It Stops

Each move of the gcd algorithm makes b smaller. A counting number cannot get smaller for ever. That is the whole reason it stops.

Falling-measure technique: if a counting number read off the state is smaller after every move, every run stops. The number is called the measure. You already know it: a countdown that drops every second must reach the end.

\varphi(m):\ \text{every run whose start has measure } m \text{ stops} @@ the condition
\text{suppose } \varphi(k) \text{ for every } k \lt m @@ the strong induction hypothesis
\text{case: the start passes the stop test} @@ then run(0) stops it
\text{case: it fails:\ \ run}(1) \text{ has measure } m' \lt m @@ the move lowers the measure
\qquad \text{the run from run}(1) \text{ stops at some } n @@ the hypothesis with k = m′; it is this run, one place on
\qquad \htmlClass{new}{\text{this run stops at } n + 1} @@ run(n + 1) is that run’s n-th state
\forall m\;\varphi(m) \quad \blacksquare @@ the strong induction technique

For the gcd algorithm the measure is b. The move puts r in its place, and r < b.

4l3Why the Answer Is Right

Stopping is not enough. An algorithm that outputs 0 at once always stops, and is nearly always wrong. Rightness needs a second proof.

Kept-statement technique: a statement true at the start, and kept by every move, is true at the stop. “Kept” means that whenever it holds of a state, it holds of the state the move makes. You know this too. If every swap in a game keeps the number of cards even, and it was even at the start, it is even at the end.

\psi(n):\ P(\mathrm{run}(n)) @@ the condition
\psi(0) @@ P holds at the start
\text{if run}(n) \text{ passes: run}(n + 1) = \mathrm{run}(n) @@ nothing moves, so P still holds
\text{if it fails: run}(n + 1) = \mathrm{move}(\mathrm{run}(n)) @@ P is kept by the move
\forall n\;\psi(n) @@ the induction technique
\htmlClass{new}{P \text{ and the stop test hold at the stop}} \quad \blacksquare @@ the stop is some run(n)

The accepted name for a kept statement is an invariant. From here on the ladder uses that word.

P(u, b):\ u, b \text{ have the same common divisors as } a, b @@ the invariant
P(a, b) @@ true at the start
P(u, b) \Rightarrow P(b, r) @@ split-keeps-divisors: u, b and b, r share their common divisors
\text{at the stop } (g, 0):\ \text{common divisors of } a, b = \text{divisors of } g @@ everything divides 0
\htmlClass{new}{g = \gcd(a, b)} \quad \blacksquare @@ divisor-not-past: each divisor of g is at most g, when g ≠ 0

So the algorithm has a measure, b, and an invariant, P. The measure says it stops. The invariant says what it gives.

Anexact, yet rigorous · loose, then locked

2f set out a principle of the second kind of care: things are made in two steps, a loose gathering and then a lock. An algorithm is made the same way. First comes the loose gathering. The same moves are run on input after input, by habit, and the answers come out right nearly every time. Adding in columns was a habit long before it was a recipe. Then the gathering locks. A measure and an invariant fix it: every run stops, and every answer is right.

Describe both steps: what runs were gathered, under what loose rule, and what proof locked them.

The lock has a price, and it can be read without watching a single run. Each move lowers the measure by at least one, so a run from a start with measure m takes at most m moves. The gcd algorithm on (a, b) takes at most b divisions, whatever a is.

Unlocking runs the steps backward. Change one move, and the proofs can fail while the runs still look right. In between sits a real state: a recipe that has worked on every input tried, with no lock found yet.

The recipe of 4l.6.5 has stopped on every start anyone has tried. Is it loose, or locked?

4l4Two More, Worked

Adding by counting on, as an algorithm. The state is (s, k), the start is (a, b), and the stop test is k = 0. The move is (s, S(j)) ↦ (S(s), j). The output is s.

\text{measure: } k @@ j < S(j): the next is past (4h)
\text{invariant: } s + k = a + b @@ true at the start
S(s) + j = s + S(j) @@ the techniques of plus (4f): the move keeps it
\htmlClass{new}{s = s + 0 = a + b} \text{ at the stop} \quad \blacksquare @@ the stop test, k = 0

Writing n in twos, as an algorithm. The state is (q, w, L): what is left to write, the value of the bits written, and how many there are. The start is (n, 0, 0), and the stop test is q = 0. The move splits q = 2 · q′ + d (4i6). It writes d to the left of the bits so far, and goes to (q′, d · 2L + w, L + 1).

\text{measure: } q @@ q′ < q whenever q ≠ 0
\text{invariant: } n = q \cdot 2^L + w @@ n · 2⁰ + 0 = n at the start
(2q' + d) \cdot 2^L + w = q' \cdot 2^{L+1} + (d \cdot 2^L + w) @@ spread and the power techniques (4g): the move keeps it
\htmlClass{new}{n = w} \text{ at the stop} \quad \blacksquare @@ q = 0

Finding an algorithm’s invariant is finding what its moves never change. The measure is usually the part of the state that shrinks.

The accepted names

An algorithm is an effective procedure. A run is also called an execution or a trace. The falling measure is called a variant or a termination measure, and an algorithm whose every run stops is said to terminate. The kept statement is a loop invariant. An algorithm that stops with the right answer is totally correct; one that is right whenever it stops is partially correct.

Who said it first

The word algorithm comes from the name of Muhammad ibn Musa al-Khwarizmi, whose ninth-century book taught reckoning with the Hindu numerals. Alan Turing checked a long routine by an invariant and a measure in a short paper of 1949. Robert Floyd (1967) and Tony Hoare (1969) made invariants a method for proving programs right. The algorithm of 4l.6.5 is Lothar Collatz’s (1937). Whether every run of it stops is still open: computers have checked every start below about 2.95 × 1020.
