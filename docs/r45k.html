Who Holds Which Key

Millions of keys sit on thousands of machines, and machines come and go. This step shows how a machine finds the one that holds a key, knowing only a few others.

Put keys and machines on one clock; each key lives with the next machine round. Jump half the remaining way each hop.

45k1Keys on a Ring

Scramble every key and every machine’s name into a number on a clock of 2ᵐ hours (43a). A key is held by the first machine at or after it, going round.

Ring-move technique: when a machine joins or leaves, only the keys between it and the machine before it change hands.

Every other key still has the same first machine after it. With n machines spread evenly, that is about 1/n of the keys. Holding keys at “key mod n” instead would move almost all of them whenever n changes.

45k2Fingers That Halve

Each machine knows the machines about 1/2, 1/4, 1/8, … of the way round from it. To find a key, jump to the farthest known machine not past the key, and repeat. Each hop at least halves the distance left, so a lookup takes at most m hops, and about log₂ n with n machines spread evenly (39l).

45k3Distance by Exactly-One

Another way to measure: write two names in twos and put 1 where they differ. That is exactly-one of 39a3, taken place by place, read as a number. It is a distance: 0 only from a name to itself, the same both ways, and d(a, c) ≤ d(a, b) + d(b, c).

The last holds because a ⊕ c = (a ⊕ b) ⊕ (b ⊕ c), and x ⊕ y ≤ x + y, since exactly-one never carries. Each hop fixes at least one more leading place, so again about log₂ n hops.

45k4Why Not One List

One list of every key is one machine to fail and one machine to ask. A ring asks each machine to know only about log₂ n others, and the work of answering is shared by all.
