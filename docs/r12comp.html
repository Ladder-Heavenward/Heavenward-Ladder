What Can a Machine With No Memory Check?

What can a machine with no memory check? A card reader checks that a number has the right count of digits. A spreadsheet checks that every bracket opened in a formula is closed. Each reads a string of symbols one at a time and answers yes or no at the end. Some checks need only a fixed handful of states, such as which digit you are on. Others seem to need a memory that grows with the string. Where exactly is the line? The question is hard because a clever machine might find a trick. “I can't think of one” proves nothing. This page writes rules that build strings, by 4d's recursion, and sorts them into four families. Then it builds the machine with no memory, and proves with 8·cb5's pigeonhole technique what it cannot check. Rung 12 turns up in the middle: a count of brackets, like a continuous curve, never skips.

A grammar is a start placeholder and rules that rewrite strings. Its sentences are the strings of plain letters the rules can reach. A machine with no memory has finitely many states and moves between them one letter at a time. Fed more strings than it has states, it must end two of them in one state, and then it cannot tell them apart. So no such machine checks a run of one letter followed by just as many of another, or brackets nested without bound. Brackets nested only so deep it checks, with two more states than the depth.

12comp1Strings

From here on, on this page, an alphabet is a finite set (4k) of symbols called letters, such as {a, b}, the two digits {0, 1}, or the two brackets. A string over an alphabet is 4i's list of its letters, written without commas: aab is the list of length 3 with entries a, a, b. The string of length 0, 4i's empty list, is the empty string, written ε. Two strings written side by side, uv, name u followed by v. A language is any set of strings over an alphabet.

Reuses, said out loud. ε named a small positive real on 10a; on this page it names only the empty string, as in the books, and the two never meet here. A high n on a letter, aⁿ, names a written n times, so a³ = aaa and a⁰ = ε; for numbers 4g's power stands. S names a grammar's start placeholder below, not 4b's next-one S, so this page writes q + 1 where 8·cb5 wrote S(q). The arrow in a rule u → v reads “may be rewritten as”, so a rule is a statement about two strings; for functions and limits its old meanings stand.

12comp2Rules That Build Strings

From here on, on this page, a grammar has an alphabet of letters, a few placeholders, written as capitals, a start placeholder S, and a finite list of rules u → v. In a rule, u and v are strings of letters and placeholders, and u holds a placeholder. To apply the rule to a string is to replace one place where u appears by v. Placeholders have the accepted name nonterminals, and letters terminals.

Which strings can the rules reach? 4d's recursion answers, on the set A of all sets of strings. Let R(0) = {S}. Let R(n + 1) be R(n) together with every string got from a member of R(n) by applying one rule. A string is reachable when it is in R(n) for some number n. A sentence is a string of plain letters that the rules can reach from S. The grammar's language is the set of its sentences.

S \to aSb,\ \ S \to ab @@ the rules
S,\ aSb,\ aaSbb,\ aaabbb @@ each string from the last by one rule: aaabbb is a sentence
S \to (S)S,\ \ S \to \varepsilon @@ brackets: the alphabet is the two brackets
\begin{aligned}&S,\ (S)S,\ (S),\ ((S)S),\ (()S),\\ &\quad \ (()(S)S),\ (()()S),\ (()())\end{aligned} @@ a sentence with brackets inside brackets

Sentences technique: the sentences of S → aSb, S → ab are exactly the strings aⁿbⁿ with n ≥ 1.

\begin{aligned}&\varphi(n):\ \text{every member of } R(n) \text{ is}\\ &\quad a^kSb^k \text{ with } k \le n,\\ &\quad \text{or } a^kb^k \text{ with } 1 \le k \le n\end{aligned} @@ the claim, for each number n
\varphi(0):\ R(0) = \{S\} = \{a^0Sb^0\} @@ a⁰ = ε
\varphi(n) \Rightarrow \varphi(n + 1) @@ only aᵏSbᵏ holds a placeholder; the rules give aᵏ⁺¹Sbᵏ⁺¹ and aᵏ⁺¹bᵏ⁺¹
\text{sentences} \subseteq \{a^nb^n : n \ge 1\} @@ induction (4c); a sentence has no placeholder
a^nb^n \in R(n) \text{ for } n \ge 1 \quad \blacksquare @@ apply S → aSb n − 1 times, then S → ab

12comp3A Grammar Runs the Transform Backwards

1a's transform took a sentence as it came and rewrote it into a shape the ladder could argue with. Almost everything since has run that way: English in, statements out. A grammar runs the other way. It starts from a few rules, each an operator on strings, and works forward to sentences.

A grammar is a technique for making sentences: the inverse of reading them. From a finite list of rules it reaches endlessly many strings. Some make sense and say something real. Some make sense and say nothing real. Some are built right and make no sense at all, like the colourless green ideas in the questions below. The rules cannot tell these apart. They tell only built right from built wrong.

A grammar used this way, to make every sentence of a language and nothing else, has the accepted name generative grammar. The linguist who named it added a second kind of rule: transformations, which take a built sentence and turn it into another shape meant to say the same thing, as “Gomez bit Randy” turns into “Randy was bitten by Gomez”. That is 1a's transform, written down as rules a machine could follow. The whole scheme is called transformational-generative grammar: generate, then transform.

So a grammar is a quiet witness for 0a's possibility axiom, on the side of sentences: a finite stock of rules writes endlessly many. Whether everything that happens fits into them is still the axiom's bet.

12comp4Four Families of Grammars

Grammars are sorted by what their rules may look like. Each family allows more than the one before.

familyrules allowedexample languageaccepted name
firstA → aB, A → a, A → ε: one placeholder on the left; on the right a letter and at most one placeholder after itan even count of a'sregular
secondone placeholder on the left, any string on the rightaⁿbⁿ; bracketscontext-free
thirdany rule whose right side is at least as long as its leftaⁿbⁿcⁿcontext-sensitive
fourthany ruleevery language some machine can listunrestricted
S \to aSBC,\ S \to aBC,\ CB \to BC,\ aB \to ab,\ bB \to bb,\ bC \to bc,\ cC \to cc @@ no rule shortens a string
\begin{aligned}&S,\ aSBC,\ aaBCBC,\ aaBBCC,\\ &\quad \ aabBCC,\ aabbCC,\\ &\quad \ aabbcC,\ aabbcc\end{aligned} @@ CB → BC sorts the placeholders; the rest turn them into letters in order

Each family's languages are languages of the next, and each next family has languages the one before has not. The first part is nearly plain from the table. A rule of the first family is a rule of the second. Between the second and the third, rules like A → ε shorten strings, and the books show how to rewrite them away, the empty string aside. The second part is three walls. This page proves the first: aⁿbⁿ belongs to the second family and not the first. The other two walls have longer proofs, and this page only names them: aⁿbⁿcⁿ is in the third family and not the second, and the fourth has languages the third has not. The ladder of families has the accepted name the Chomsky hierarchy.

Each family has its machine. The first family's languages are exactly those a machine with no memory checks. The second's need a machine with a stack, a pile of symbols it can add to and take from at the top only. The third's need a memory as long as the input. The fourth's need a memory without end. This page builds the first machine.

12comp5The Machine with No Memory

From here on, on this page, a machine with no memory has a finite set of states, one start state, some accepting states, and a table. For each state and each letter, the table gives the next state. Fed a string, the machine starts in the start state and reads the letters in order, moving by the table at each one. It answers yes when it ends in an accepting state. It remembers nothing but the state it is in. It checks a language when it answers yes exactly on that language's strings.

A ZIP code is five digits. Salinas's, 93901, and Monterey's, 93940, both begin 939. A machine checking “five digits beginning 939” needs a state for each digit read so far, 0 to 5, and one more, a dead state, for a string already wrong. That is seven states, and it never needs more, however many codes it checks.

Remainder-machine technique: a machine with three states finds the remainder by 3 of any number written in twos. Its states are 0, 1 and 2, its start is 0, and its accepting state is 0. Reading a digit d in state r, it moves to the remainder of 2r + d by 3. After reading a numeral w, it is in the state equal to the remainder of w's number by 3.

\begin{aligned}&\psi(w):\ \text{after reading } w, \text{ the}\\ &\quad\text{state is the remainder of } [w] \text{ by } 3\end{aligned} @@ [w] is the number w writes in twos (4i), with [ε] = 0; the claim for each numeral, by induction on its length
\psi(\varepsilon):\ \text{state } 0,\ [\varepsilon] = 0 @@ the start state
[wd] = 2[w] + d @@ 4i's writing in twos: a new last digit doubles the rest
[w] = 3m + r \Rightarrow 2[w] + d = 3(2m) + (2r + d) @@ ψ(w), with 4j's remainder r
\begin{aligned}&\htmlClass{new}{\text{remainder of } [wd] = \text{remainder of } 2r }\\ &\quad \htmlClass{new}{+ d} \quad \blacksquare\end{aligned} @@ 4j's remainders: a multiple of 3 added changes no remainder; that is the table's move
1001:\ 0 \to 1 \to 2 \to 1 \to 0 @@ nine: yes
1011:\ 0 \to 1 \to 2 \to 2 \to 2 @@ eleven: remainder 2, no

12comp6A Count That Never Skips

From here on, on this page, the depth walk of a string of brackets is the list h₀, h₁, …, hₙ with h₀ = 0, going up 1 at each opening bracket and down 1 at each closing one. The string is balanced when its walk never goes below 0 and ends at 0. The sentences of S → (S)S, S → ε are exactly the balanced strings. 12·comp.10.4 asks for half of the proof.

A checker must watch for the walk going below 0. Must it watch for −1, −2, −3 and the rest? Rung 12 says no, in counting numbers. A continuous function cannot skip a value, and neither can a walk that moves by one.

Step-walk technique (in-between-value for steps of one): a walk that moves by one at each step passes through every whole number between its start and its end. Precisely: let h₀, …, hₙ be integers, each differing from the next by 1 or −1. Then every integer y between h₀ and hₙ, ends included, is some hᵢ.

n = 0:\ \ y \text{ between } h_0 \text{ and } h_0 \Rightarrow y = h_0 @@ the start; the claim is for every such walk of n steps, by induction on n
y \text{ between } h_0 \text{ and } h_n \Rightarrow y = h_i \text{ for some } i \le n @@ the hypothesis, for the first n steps
\begin{aligned}&y \text{ between } h_0 \text{ and } h_{n+1},\\ &\quad \ \text{not between } h_0 \text{ and } h_n\end{aligned} @@ the only other case (rung 7's either-way, on settled integers)
y \text{ lies beyond } h_n \text{ and not beyond } h_{n+1} @@ 8g's order on the line
h_{n+1} = h_n \pm 1 \Rightarrow \htmlClass{new}{y = h_{n+1}} \quad \blacksquare @@ no integer lies strictly between two neighbours: 4h's next-is-not-past, said for integers

So a walk that goes below 0 hits −1 first: −1 lies between h₀ = 0 and the first value below 0. A checker of brackets need only count, and stop at −1. 12a's in-between-value promised a zero between a sign change; step-walk promises a −1. The proof is easier because there is nothing between neighbouring integers to fall through.

12comp7Bounded and Unbounded

Bounded-depth technique: for each number k, a machine with no memory with k + 2 states checks the balanced strings whose walk never rises above k. Its states are the depths 0, 1, …, k and one dead state. An opening bracket moves depth d to d + 1, or to dead from k. A closing bracket moves d to d − 1, or to dead from 0. The dead state stays dead. It accepts only depth 0. By step-walk, a walk that goes above k passes through k + 1 on the way, so the dead state catches it there.

No-memory-wall technique: no machine with no memory checks the strings aⁿbⁿ.

\begin{aligned}&\text{suppose a machine with } q \text{ states}\\ &\quad\text{checks } \{a^nb^n : n \ge 0\}\end{aligned} @@ supposing, to refute
\begin{aligned}&a^0,\ a^1,\ \cdots,\ a^q:\ q + 1 \text{ strings,}\\ &\quad\text{each ending in one of } q \text{ states}\end{aligned} @@ a function from q + 1 strings to q states
a^i,\ a^j \text{ end in one state},\ i \lt j @@ pigeonhole (8·cb5)
a^ib^i \text{ and } a^jb^i \text{ end in one state} @@ from one state, the table moves the same way on the same letters bⁱ
a^ib^i \in L,\ \ a^jb^i \notin L @@ the machine says yes to both or to neither
\htmlClass{new}{\bot};\ \text{no such machine} \quad \blacksquare @@ the supposition refuted

Put an opening bracket for a and a closing one for b, and the same lines show that no machine with no memory checks all balanced strings. For each k it can check depth up to k, and no single machine checks every depth. The line between what it can and cannot check is 12b's word: bounded. A machine with a counter crosses it. A counter that can grow without end is a memory, and the second family's stack is one.

12comp9Running It Backwards

Handed a machine's table, find its language: ask what each state knows about the letters read so far. Handed a language, look for that knowledge: if finitely many facts about what has been read decide every answer, a machine with no memory exists, one state per fact. If endlessly many strings must be told apart, as a⁰, a¹, a², … must be for aⁿbⁿ, pigeonhole says no machine with no memory checks it.

Who said it first

Machines with finitely many states were first studied as nets of nerve cells by Warren McCulloch and Walter Pitts (1943). Stephen Kleene showed in 1951, published 1956, which sets of strings such nets can check, his regular events. Michael Rabin and Dana Scott gave the machine its present form in 1959. Noam Chomsky set out the four families in 1956 and 1959. He is the linguist of 12·comp.10.5, in Syntactic Structures (1957). The machine with a memory without end is Alan Turing's, of 1936.

Chomsky argues that a sentence such as “colorless green ideas sleep furiously”, and the same words in reverse order, would be equally remote from anything a speaker had heard, yet a speaker hears only the first as grammatical.

Noam Chomsky, Syntactic Structures (1957), chapter 2; paraphrase

Accepted names

A machine with no memory is a deterministic finite automaton, and the languages it checks are the regular languages. The no-memory wall's argument, in its general form, is the pumping lemma for regular languages. Counting the strings a machine must tell apart, as in 12·comp.10.3, is the Myhill–Nerode technique. A machine with a stack is a pushdown automaton, one with memory as long as its input a linear bounded automaton, and one with a memory without end a Turing machine.
