40i · proof

Data Defined by Repeating

A program holds more than numbers. It holds lists, and lists of lists, and trees. This step defines them as rung 4 defined the whole numbers, by a start and a way to build. Then functions on them, and proofs about them, follow the same build.

A list is empty, or a number in front of a list. Write the function and the proof the same way: one line for empty, one for a number in front.

40i1A List Is Empty or a Number in Front of a List

The lists of numbers are the smallest set that holds the empty list and holds h in front of t whenever it holds t (4b). A tree is empty, or a node holding a number with two trees below it.

Smallest means every list is built in finitely many steps from the empty list. No list holds itself.

40i2Functions That Follow the Shape

length(empty) = 0, and length(h in front of t) = 1 + length(t). The function has one line for each way a list is built, and each call is on a part. The size falls, so by 40e2 every call stops.

40i3Induction Over the Shape

Shape-induction technique: if a claim holds of the empty list, and holds of h in front of t whenever it holds of t, then it holds of every list.

The set of lists with the claim holds the empty list and is closed under putting in front. The lists are the smallest such set, so all of them have the claim.

The accepted names

Types built this way are algebraic data types, and “a number in front” is often called cons. Functions that follow the shape use structural recursion, and the proofs use structural induction.
