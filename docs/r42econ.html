Can Everyone Be Paired so No Two Would Rather Swap?

Can everyone be paired so no two would rather swap? Every year, thousands of new doctors rank the hospitals where they would like to train, and the hospitals rank the doctors. A pairing is wanted, and not just any pairing: if a doctor and a hospital both prefer each other to what they were given, they will make their own deal on the side, and the pairing comes apart. Markets like this once did come apart, with offers made earlier and earlier and taken in a panic. This page asks whether a pairing with no such pair always exists. It finds one by a list of proposals and refusals, proves the list always ends and always gives a pairing that holds, and finds that it is the best such pairing for the side that proposes and the worst for the side that chooses. Then it finds where the idea stops: when everyone ranks everyone, as with roommates, there may be no pairing that holds at all.

A pairing holds when no doctor and hospital both prefer each other to their partners. Let each free doctor propose to the best hospital not yet refusing them, and each hospital hold its best offer so far. It ends within n² − n + 1 proposals, the pairing holds, and every doctor gets the best partner of any pairing that holds; every hospital gets its worst.

42·econ.1A Pairing That Holds

Take n doctors and n hospitals, each hospital with one place. Each doctor ranks every hospital and each hospital ranks every doctor. A pairing is a matching of the two-sided graph of 42e that uses every dot. A doctor and a hospital not paired with each other block the pairing if each prefers the other to the partner given. A pairing holds if nothing blocks it.

An example with doctors u, v, w and hospitals H, J, K, best first:

  • u: J, H, K.   v: H, K, J.   w: J, H, K.
  • H: w, v, u.   J: v, u, w.   K: u, v, w.
u\text{–}H,\ v\text{–}J,\ w\text{–}K @@ one of the 3! = 6 pairings
v \text{ prefers } H \text{ to } J,\ H \text{ prefers } v \text{ to } u @@ so v and H block it
u\text{–}J,\ v\text{–}K,\ w\text{–}H:\ \ u \text{ and } w \text{ have their first; } v \text{ wants only } H @@ H has its first, w
\htmlClass{new}{\text{nothing blocks } u\text{–}J,\ v\text{–}K,\ w\text{–}H: \text{ it holds}} @@ checking every pair not in it

Of the six pairings, exactly two hold: this one and u–K, v–J, w–H. Checking them all costs n! pairings and n² pairs each; the next footing finds one without the search.

42·econ.2Proposals and Refusals

The run: while some doctor is free, that doctor proposes to the best hospital that has not yet refused them. A hospital with no offer holds it. A hospital holding an offer keeps the better of the two doctors and refuses the other, who is free again. A hospital never refuses without holding someone better.

u \to J \text{ held};\ \ v \to H \text{ held} @@ first choices
w \to J \text{ refused} @@ J prefers u to w
w \to H \text{ held},\ v \text{ let go} @@ H prefers w to v
v \to K \text{ held} @@ v’s next choice
\htmlClass{new}{\text{no one free: } u\text{–}J,\ v\text{–}K,\ w\text{–}H \text{ after 5 proposals}} @@ the pairing that holds

Proposal-count technique: with n doctors and n hospitals, the run ends after at most n² − n + 1 proposals, with everyone paired.

\text{each doctor proposes to each hospital at most once} @@ proposals go down the list
\text{a hospital, once holding, holds someone for ever after} @@ it only trades up
\text{the run stops once every hospital holds} @@ n hospitals holding means n doctors held, none free
\text{before the last proposal, some hospital has had none} @@ else it would have stopped
\text{so each doctor has proposed to at most } n - 1 @@ that hospital is on no one’s list yet
\htmlClass{new}{\text{at most } n(n - 1) + 1 = n^2 - n + 1 \text{ proposals}} \quad \blacksquare @@ the last one reaches that hospital

A free doctor can always propose: if all n hospitals had refused them, all n would be holding someone, and n doctors other than this one would be held, but there are only n − 1. The bound cannot be lowered: for n = 4 there are lists that need all 13 proposals, a standing question below. Which doctor proposes first does not change the end, nor the set of proposals made; the standing questions check that on the example.

42·econ.3Why the Result Holds

No-swap technique: the pairing the run ends with holds.

\text{suppose doctor } d \text{ and hospital } h \text{ block the final pairing} @@ for contradiction (7b)
d \text{ prefers } h \text{ to its partner, so } d \text{ proposed to } h \text{ first} @@ d goes down its list
h \text{ refused } d, \text{ then or later, for a doctor it prefers} @@ refusals only trade up
h\text{’s final partner is at least as good to } h \text{ as that one} @@ holdings only improve
h \text{ prefers its partner to } d @@ so h does not want d
\htmlClass{new}{\text{no pair blocks}} \quad \blacksquare @@ the contradiction

So a pairing that holds always exists, for any lists at all. The proof is a proof by running: a method, a count that says it stops, and a check that what it stops at is right. Nothing in it needs the lists to agree, to be fair, or to be honest.

42·econ.4Which Side It Favours

Call a hospital possible for a doctor if some pairing that holds pairs them.

Best-for-proposers technique: in the run, no doctor is ever refused by a hospital possible for them; so each doctor ends with the best possible hospital, and every hospital with the worst possible doctor.

\text{suppose the first such refusal: } h \text{ refuses } d \text{ for } d^* @@ h is possible for d: d–h in a holding pairing M
d^* \text{ prefers } h \text{ to every hospital that has not refused it} @@ d* proposed to h, so the hospitals it likes better refused it
\text{those refusals came earlier, and none was by a possible hospital} @@ this one is the first
d^* \text{ prefers } h \text{ to its partner in } M @@ which is possible for d*, so has not refused it, so is lower than h
h \text{ prefers } d^* \text{ to } d @@ it refused d for d*
\htmlClass{new}{d^* \text{ and } h \text{ block } M,\ \text{which holds}} \quad \blacksquare @@ a contradiction
  
\text{let } M \text{ hold, and the run give } h \text{ the doctor } d @@ suppose h prefers d to its partner in M
d \text{ prefers } h \text{ to its partner in } M @@ h is d’s best possible, and M gives d another possible one
\htmlClass{new}{d \text{ and } h \text{ block } M} \quad \blacksquare @@ so h does at least as well in every M

In the example the doctors propose and get u–J, v–K, w–H, where the doctors have their 1st, 2nd and 2nd choices. Let the hospitals propose instead, and the run is three proposals: H to w, J to v, K to u, every hospital its first choice; the doctors get their 3rd, 3rd and 2nd. Both pairings hold. Which side proposes is a choice of who is favoured, and it is a choice a market designer makes.

42·econ.5Where It Is Used, and Where It Stops

The run, with doctors proposing and hospitals with several places, has paired new doctors with US hospitals every spring since the 1990s; an older run with hospitals proposing began in 1952. Cities use it to place children in schools, with children proposing, and some countries to place students in universities. Two more facts make it safe to use. A doctor never gets a better hospital by giving a false list when the doctors propose, so the honest list is the best list for them. A hospital sometimes can, as a standing question below finds, so the side that proposes is also the side that has no reason to lie. That fact is stated here, not proved.

The idea needs two sides. Four students share two rooms of two, and each ranks the other three:

  • 1: 2, 3, 4.   2: 3, 1, 4.   3: 1, 2, 4.   4: anyone.
\text{whoever rooms with 4 ranks 4 last} @@ 4 is last on every list
\{1, 2\}\{3, 4\}: \ 2 \text{ and } 3 \text{ prefer each other} @@ 3 is 2’s first; 2 beats 4 for 3
\{1, 3\}\{2, 4\}: \ 1 \text{ and } 2 \text{ prefer each other} @@ 2 is 1’s first; 1 beats 4 for 2
\{1, 4\}\{2, 3\}: \ 1 \text{ and } 3 \text{ prefer each other} @@ 1 is 3’s first; 3 beats 4 for 1
\htmlClass{new}{\text{every pairing is blocked}} \quad \blacksquare @@ all three pairings of four

With two sides, the proof of the no-swap technique used that a doctor only ever proposes and a hospital only ever chooses. Among roommates everyone does both, and 1, 2 and 3 chase each other round a ring of three, the odd cycle of 42a that a two-sided graph cannot have.

The cellar · there if you want it

The accepted names

A pairing that holds is a stable matching, and a blocking pair is a blocking pair. The run of proposals and refusals is the deferred acceptance algorithm, or the Gale–Shapley algorithm. The best-for-proposers technique is the optimality of proposer-proposing deferred acceptance, and its other half is the lattice fact that the same matching is worst for receivers. That proposers cannot gain by lying is strategy-proofness for the proposing side. The roommates question is the stable roommates problem, which has an algorithm to find a stable pairing when one exists.

Who said it first

David Gale and Lloyd Shapley published the run in 1962, under the title “College admissions and the stability of marriage”. The US hospitals had used a version since 1952. Lester Dubins and David Freedman (1981) and Alvin Roth (1982) proved that proposers cannot gain by lying. Roth and Elliott Peranson redesigned the medical match in 1998 so that doctors propose; Roth, Parag Pathak and Atila Abdulkadiroğlu designed the school placements of New York (2003) and Boston (2005). Roth and Shapley shared the economics prize of 2012. Robert Irving found the roommates algorithm in 1985.

A proof that is not allowed

“Pair each doctor with their first choice. If two want the same hospital, the hospital takes the one it likes better, and the other takes their second choice. Everyone gets as high a choice as possible, so nothing blocks.” Not allowed: the doctor sent to a second choice may push out someone who was settled there, who must move again, and the argument stops after one round. It never shows the moves end, nor that no earlier refusal comes back as a block. The run is that argument done in full, with a count that stops it and a check at the end.
