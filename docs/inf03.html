What Is an Effect?

What is an effect? Rung 40’s programs did more than compute a value: they changed what names held. Others may fail, or return many answers, or draw by chance. Each such program is an ordinary function into a wrapped type: a value that may be missing, a list of values, a value with a new state, a chance list of values. Wrapped programs run in a row when the wrapper has two maps, one to wrap a plain value and one to unwrap a wrapper of wrappers, obeying three conditions, and those conditions are exactly what makes wrapped programs a category. Every left-and-right pair of rung 47 gives such a wrapper. This way of describing programs dates from 1989. Since then effects have been built from operations and the handlers that interpret them, and in 2019 it was proved that many pairs of wrappers cannot be combined into one.

A wrapper T sends a type A to T(A), with wrap η : A → T(A) and a row ⋆: from f : A → T(B) and g : B → T(C), g ⋆ f : A → T(C). Three conditions: g ⋆ η = g, η ⋆ f = f, (h ⋆ g) ⋆ f = h ⋆ (g ⋆ f). Maybe, list, state S → B × S and chance lists are wrappers. The conditions make wrapped programs a category. A left-and-right pair F ⊣ U gives the wrapper U ∘ F; lists are freeing after forgetting.

inf3.1State Is a Wrapper

40c2’s assignment technique says a step reads the state of the program and leaves a new one. A step that takes a value of type A and gives a value of type B, while it reads and changes a state in S, is a function from A × S to B × S.

State-wrap technique: functions from A × S to B × S match functions from A to the wrapped type T(B) = the functions from S to B × S.

h : A \times S \to B \times S @@ a step that reads and changes the state
\tilde h(a) = (s \mapsto h(a, s)) @@ fix the first input
\tilde h : A \to (B \times S)^{S} @@ 47f2’s pair-to-function technique, with D = B × S
\htmlClass{new}{A \times S \to B \times S \ \text{ matches } \ A \to T(B),\ T(B) = (B \times S)^{S}} \quad \blacksquare @@ the matching of 47f2

So a step with state is an ordinary function, into a wrapped type. The state is no longer hidden in the machine; it is in the type of the answer, waiting for a starting state.

inf3.2Three Wrappers and a Row

Three more wrappers. Maybe: T(B) is B with one extra member, “failed”. List: T(B) is the finite lists of members of B. State: T(B) = (B × S)S. Each has a wrap η that makes a plain value into a wrapped one: the value itself; the list of one; s ↦ (b, s), leaving the state alone.

Two wrapped programs f : A → T(B) and g : B → T(C) do not run in a row as they stand: g wants a B and f gives a T(B). The row g ⋆ f opens the wrapper. For maybe, if f failed, fail; else run g. For list, run g on each member of f(a) and join the lists. For state, run f from s to get (b, s′), then run g on b from s′.

Maybe-row technique: for the maybe wrapper, g ⋆ f fails at a exactly when f fails at a, or f succeeds with b and g fails at b.

f(a) = \text{failed} \Rightarrow (g \star f)(a) = \text{failed} @@ the row stops at the first failure
f(a) = b \Rightarrow (g \star f)(a) = g(b) @@ otherwise it passes b along
\htmlClass{new}{(g \star f)(a) = \text{failed} \iff f(a) = \text{failed or } g(f(a)) = \text{failed}} \quad \blacksquare @@ the two cases

inf3.3The Three Conditions

A wrapper with η and ⋆ is well-made when g ⋆ η = g (wrapping then running g is running g), η ⋆ f = f (running f then wrapping again changes nothing), and (h ⋆ g) ⋆ f = h ⋆ (g ⋆ f) (brackets do not matter). These are 47a1’s demands on a category, with η as the do-nothing arrow and ⋆ as running in a row.

Wrapped-category technique: for a well-made wrapper, the types with the wrapped programs A → T(B) as arrows, η as do-nothing and ⋆ as running in a row, make a category. The list wrapper is well-made.

(g \star \eta)(a) = \text{join of } [\,g(a)\,] = g(a) @@ one list, joined, is itself
(\eta \star f)(a) = \text{join of } [\,[b_1], \dots, [b_n]\,] = [b_1, \dots, b_n] = f(a) @@ lists of one, joined
((h \star g) \star f)(a) = \text{join over } b \in f(a) \text{ of join over } c \in g(b) \text{ of } h(c) @@ unwind ⋆ twice
(h \star (g \star f))(a) = \text{join over } c \in \text{join}_{b \in f(a)} g(b) \text{ of } h(c) @@ unwind ⋆ the other way
\htmlClass{new}{\text{both list } h(c) \text{ for } c \text{ in } g(b),\ b \text{ in } f(a),\ \text{in that order}} \quad \blacksquare @@ joining lists does not care about brackets

inf3.4Lists Are Freeing After Forgetting

47b2 freed a group on a set of letters and forgot it back to a set. Do the same with joining alone, no undoing: the free joining on a set S is the finite lists of letters of S, joined end to end, with the empty list as do-nothing. Forget the joining and keep the set of lists: that is the list wrapper.

Free-wrapper technique: for a left-and-right pair F ⊣ U, the wrapper U ∘ F has η the arrow A → U(F(A)) matched with the do-nothing of F(A), and the row joins with the product of F; for free joining this is the list wrapper.

\eta(x) = [x] @@ by 47f1, the do-nothing of F(S) matches the function sending each letter to its own list
F(U(F S)) \to F S \text{ joins a list of lists} @@ the do-nothing of U(F S), matched back: evaluate a word of words
g \star f = \text{join} \circ \text{(list of } g) \circ f @@ apply g in each place, then join
\htmlClass{new}{U \circ F = \text{the list wrapper}} \quad \blacksquare @@ the same η and the same row

47f1’s left-and-right pairs are everywhere in rung 47, and each gives a wrapper this way. The arrows carry the plan; how a list is stored in a machine is let go.

inf3.5Chance Is a Wrapper

Let T(B) be the chance lists on a finite B: a chance for each member, at least 0, adding to 1. A program A → T(B) is a chance function: for each a, chances of each b. Wrap η gives chance 1 to the value itself.

Chance-row technique: for chance functions f : A → T(B) and g : B → T(C), (g ⋆ f)(a) gives c the chance Σb f(a)(b) · g(b)(c); as grids, ⋆ is 30p1’s product of chance grids.

(g \star f)(a)(c) = \textstyle\sum_b f(a)(b)\, g(b)(c) @@ every route through b, its chance times the next
\textstyle\sum_c (g \star f)(a)(c) = \sum_b f(a)(b) \sum_c g(b)(c) = \sum_b f(a)(b) = 1 @@ a chance list again
G_{cb} = g(b)(c),\ F_{ba} = f(a)(b) \Rightarrow (g \star f) = GF @@ the row is the grid product
\htmlClass{new}{(g \star f)(a)(c) = (GF)_{ca}} \quad \blacksquare @@ 30p1: chance grids run in a row

Open questions

These are open: the field is still asking them. There is no key; a good attempt is a reason, a guess, or a better question.

∞1.oq.1Is there a general way to combine effects? Swapping one wrapper past another works for some pairs, and a 2019 proof showed that for many pairs no well-made swap exists. Building effects from operations and handlers combines more of them, but not all. What a language’s system of effects should promise its programmers, and whether one system can promise it for every effect, is open.
A short history · told from more than one side

How we got here

In 1989 a computer scientist proposed that the effects of a program, state, failure, many answers, input and output, be described by wrappers with two maps and three conditions, a structure already known in category theory. The proposal was meant for describing languages, not for writing programs.

In the 1990s the idea was carried into programming: a language with no hidden state wrote its input and output as a wrapper, and programmers wrote wrapped programs in a row. Wrappers spread from there to other languages, often under other names.

From 2003 to 2009 effects were rebuilt from operations, such as read, write and fail, with the wrapper generated freely by them, and from handlers that say what each operation does. Several languages adopted handlers. Combining wrappers stayed hard: in 2019 a proof showed that many pairs admit no well-made swap.

The accepted names

A lawful wrapper is a monad; wrap is the unit or return, the row is Kleisli composition, opening the wrapper is bind, and the category of wrapped programs is the Kleisli category. Maybe is the option or Maybe monad; the chance wrapper is the distribution monad. A swap obeying laws is a distributive law. Effects from operations are algebraic effects, interpreted by effect handlers.

Who said it first

Eugenio Moggi, computational lambda-calculus and monads (1989; “Notions of computation and monads”, 1991). Philip Wadler brought monads into functional programming (1990s). Gordon Plotkin and John Power, algebraic operations and generic effects (2003); Gordon Plotkin and Matija Pretnar, handlers of algebraic effects (2009). Maaike Zwart and Dan Marsden, no-go theorems for distributive laws (2019).
