When Do Two Machines Behave the Same?

When do two machines behave the same? Rung 41’s reading machines and rung 40’s programs with state have the same shape: a set of states with one map out of it, giving an output and a next state. Two states behave alike when some relation ties them and survives every step; then no experiment tells them apart. There is one last machine that every machine maps into, and its states are the behaviours themselves. For outputs in a row that last machine is the streams, and two streams are proved equal by showing a relation, not by induction. The smallest machine for a pattern is a machine’s image in the last one. And the last machine for “a set of nexts” would need sets that hold themselves, which rung 3’s foundation forbids. One theory for all such machines was set out in 2000; in 2013 checking two machines by a relation up to what is already known made the check far faster. Sameness for machines with chance or with qubits is still being settled.

A machine is c : X → O × X (an output and a next state), or for reading machines X → 2 × XΣ. A relation R is a bisimulation when x R y gives equal outputs and next(x) R next(y). Streams Oℕ are the last machine: every machine maps into them in exactly one way. Streams related by a bisimulation are equal. The image of a reading machine in the last one is its smallest machine. The last machine is matched with one step of itself, Z ≅ F(Z); for “a set of nexts” that would be Z ≅ 𝒫(Z), against 35c1.

inf7.1A Machine Is a Map Out of a Set

40c2’s program state, and 41g1’s pattern machines, are both a set of states X with a rule saying what is seen now and what state comes next. Write it as one map out of X. A stream machine with outputs in O is c : X → O × X, x ↦ (out(x), next(x)). A reading machine on letters Σ is c : X → 2 × XΣ: whether x accepts, and for each letter the state it moves to.

A map of machines h : X → Y keeps the shape: out(h(x)) = out(x) and next(h(x)) = h(next(x)). Machines and their maps are a category.

Map-keeps-outputs technique: a map of stream machines sends each state to a state with the same row of outputs.

\mathrm{out}(h(x)) = \mathrm{out}(x) @@ the first output, by the definition
\mathrm{next}^{n}(h(x)) = h(\mathrm{next}^{n}(x)) @@ by induction on n, next commutes with h
\mathrm{out}(\mathrm{next}^{n}(h(x))) = \mathrm{out}(h(\mathrm{next}^{n}(x))) = \mathrm{out}(\mathrm{next}^{n}(x)) @@ the first line at next^n(x)
\htmlClass{new}{h(x) \text{ and } x \text{ give the same outputs at every step}} \quad \blacksquare @@ every n

inf7.2A Relation That Survives Every Step

Two machines need not map into each other to behave alike. A relation R between the states of X and of Y is a bisimulation when x R y gives out(x) = out(y) and next(x) R next(y): related states look alike now, and their next states are related again.

Bisimulation technique: states related by a bisimulation give the same output at every step.

x\,R\,y \Rightarrow \mathrm{out}(x) = \mathrm{out}(y) @@ step 0, by the definition
x\,R\,y \Rightarrow \mathrm{next}^{n}(x)\ R\ \mathrm{next}^{n}(y) @@ by induction on n: R survives each step
\mathrm{out}(\mathrm{next}^{n}(x)) = \mathrm{out}(\mathrm{next}^{n}(y)) @@ step 0 at the related pair
\htmlClass{new}{x \text{ and } y \text{ behave the same}} \quad \blacksquare @@ for every n

A bisimulation is a certificate. To show two states alike, write down a relation holding them, check one step, and the induction is done once for all inside the technique.

inf7.3The Last Machine

The streams Oℕ, endless rows s₀, s₁, s₂, … of outputs, form a stream machine: out(s) = s₀, the head, and next(s) = s₁, s₂, …, the tail.

Last-machine technique: every stream machine X has exactly one map into the streams, x ↦ (out(x), out(next(x)), out(next²(x)), …).

h(x)_n = \mathrm{out}(\mathrm{next}^{n}(x)) @@ forced by the map-keeps-outputs technique
\mathrm{out}(h(x)) = h(x)_0 = \mathrm{out}(x) @@ h keeps the output
\mathrm{next}(h(x))_n = h(x)_{n+1} = \mathrm{out}(\mathrm{next}^{n}(\mathrm{next}(x))) = h(\mathrm{next}(x))_n @@ h keeps the next state
\htmlClass{new}{\text{exactly one map } X \to O^{\mathbb N}} \quad \blacksquare @@ forced, and it works

So a state’s behaviour is its image in the last machine, and two states behave the same exactly when they have one image. Rung 47 pinned a set down by the maps into it; here a behaviour is pinned down by the one map of machines into the streams.

inf7.4Equal by a Relation

Two streams can be shown equal without induction on places. Let s be the stream with s = 0, 1, s: zero, one, then s again. Let a(b) be the stream b, then a(1 − b): it starts at b and flips. Is s = a(0)?

Relation-proof technique: streams related by a bisimulation on the streams are equal.

R = \{(s,\ a(0)),\ (\mathrm{tail}\,s,\ a(1))\} @@ the relation to check
\mathrm{head}\,s = 0 = \mathrm{head}\,a(0),\quad \mathrm{tail}\,s\ R\ a(1) @@ the first pair, one step
\mathrm{head}(\mathrm{tail}\,s) = 1 = \mathrm{head}\,a(1),\quad \mathrm{tail}^2 s = s\ R\ a(0) = \mathrm{tail}\,a(1) @@ the second pair, one step
\htmlClass{new}{s = a(0)} \quad \blacksquare @@ the bisimulation technique gives equal outputs at every place

The relation had two pairs and one step to check for each; the endless row of places was handled once, inside the bisimulation technique.

inf7.5The Smallest Machine for a Pattern

For reading machines the last machine has a state for each set of strings L, accepting when L holds the empty string, and moving on letter σ to {w : σw in L}. A state x of a machine maps to the set of strings it accepts. The image of a machine is the set of those languages it reaches.

Least-machine technique: the image of a reading machine in the last one accepts the same strings and has no more states than any machine that does, among those whose every state can be reached.

x \mapsto L(x) = \{w : \text{started at } x,\ w \text{ is accepted}\} @@ the one map into the last machine
\text{the image is } \{\,\{w : uw \in L\} : u \text{ a string}\,\} @@ every state reachable: the states are the leftovers of L
\text{every such machine maps onto that set} @@ the same leftovers, whichever machine reads L
\htmlClass{new}{|\text{states}| \ge |\text{image}|} \quad \blacksquare @@ a map onto a set has at least as many inputs as the set has members

A three-state machine for “an even number of a’s” whose states q₀, q₁, q₂ go q₀ → q₁ → q₂ → q₁ on a, accepting at q₀ and q₂, maps q₀ and q₂ to one language: the image has two states. Merging states with one image is the standard way to make a pattern machine small.

inf7.6Sets That Hold Themselves

A machine whose next is “a set of nexts” is c : X → 𝒫(X): from each state, any of several. Every last machine is matched with one step of itself.

Last-is-matched technique: if Z is a last machine for the shape F, its map c : Z → F(Z) is undoable.

F(c) : F(Z) \to F(F(Z)) \text{ makes } F(Z) \text{ a machine} @@ apply the shape to c
h : F(Z) \to Z \text{ the one map of machines} @@ Z is last
h \circ c : Z \to Z \text{ is a map of machines, so } h \circ c = \mathrm{id} @@ the do-nothing is the only map from Z to Z
\htmlClass{new}{c \circ h = F(h) \circ F(c) = F(h \circ c) = \mathrm{id}} \quad \blacksquare @@ h keeps the shape; then the first line

For streams, Oℕ ≅ O × Oℕ: a stream is its head and its tail. For a set of nexts it would give Z ≅ 𝒫(Z), which 35c1 forbids: among sets there is no last machine for “any set of nexts”. With only finitely many nexts at each state a last machine exists, but its one-state loop x → {x} maps to a state Ω whose nexts are {Ω}; read as sets, Ω = {Ω}, a set that holds itself, which 3a18’s foundation rules out. Theories of such machines either use states that are not sets of nexts, or drop foundation for an axiom that allows them.

Open questions

These are open: the field is still asking them. There is no key; a good attempt is a reason, a guess, or a better question.

∞7.oq.1What is the right sameness for machines with chance or with qubits? For chance there are several notions, from matching chances exactly to being close in a distance on behaviours, and the right one depends on what an observer can test. For machines with qubits, where reading a state changes it, which relation should count as “no experiment tells them apart”, and how to check it fast, is open.
A short history · told from more than one side

How we got here

Relations that survive every step were introduced in the 1970s and early 1980s for programs that run side by side and talk, as the right sameness for machines that are watched while they run. In 1988 a set theory without foundation was published in which sets may hold themselves, with such relations as its sameness.

In 2000 a paper set out one theory for all machines given as maps out of a set, of any shape: streams, reading machines, machines with choices, with chance. Behaviours became the states of the last machine, and proofs by relation became the matching partner of induction.

In 2013 a method checked two reading machines with choices by a relation “up to” what is already known: a pair need not be in the relation if it follows from pairs that are. On standard tests it was far faster than the methods before it.

The accepted names

A map out of a set of shape F is an F-coalgebra; the last machine is the final coalgebra; a relation that survives every step is a bisimulation, and proving equality with one is coinduction. The last-is-matched technique is Lambek’s lemma. Reading machines with choices are nondeterministic finite automata; the least machine is the minimal automaton, and the leftovers are Brzozowski derivatives. Sets that hold themselves are non-well-founded sets, allowed by the anti-foundation axiom.

Who said it first

Robin Milner and David Park, bisimulation (1970s-1981). Peter Aczel, Non-Well-Founded Sets (1988). Joachim Lambek, the lemma (1968). Jan Rutten, “Universal coalgebra: a theory of systems” (2000). Filippo Bonchi and Damien Pous, “Checking NFA equivalence with bisimulations up to congruence” (POPL 2013).
