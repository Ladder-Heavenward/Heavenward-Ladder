Why Is Fast Memory So Small?

Why is fast memory so small? A chip adds two numbers in a third of a billionth of a second, but fetching a number from main memory takes a hundred billionths. A machine that waited on memory for every number would idle most of its life. Memory built from 39h’s latches is fast and costly; memory built from tiny charged cells is slow and cheap. So machines stack small fast memories in front of big slow ones and bet that what is wanted next sits near what was wanted last. This page prices the stack, finds the average wait, shows why the bet usually wins, and adds two more tricks: a line of workers, and memory that pretends to be bigger than it is.

Keep copies of recently used data in a small fast memory. Average wait = hit time + miss rate × miss penalty. Programs reuse data and walk through it in order, so most looks hit. Split each instruction into stages so several run at once, and give each program its own made-up addresses, translated by a table.

39comp2The Average Wait

\text{hit: } 1 \text{ ns} @@ found in the cache
\text{miss: } 1 + 100 \text{ ns} @@ look, then go on
\text{average} = 1 + m \cdot 100 \text{ ns} @@ m the share of misses, averages (30g)
m = 0.05:\ 6 \text{ ns};\ \ m = 0.01:\ 2 \text{ ns} @@ a few misses cost most of the time
\htmlClass{new}{\text{average wait} = \text{hit time} + \text{miss rate} \times \text{miss penalty}} @@ the cache’s one law

Cache technique: the average wait is the hit time plus the share of misses times the cost of a miss. Cutting misses from 5 in 100 to 1 in 100 triples the speed, though the cache itself is no faster.

39comp3Why the Bet Wins

A cache helps only if a program asks again for what it asked for lately, or for its neighbours. Most do: a loop (40b) runs the same lines over and over, and walks an array in order.

\text{the same item again soon} @@ a loop’s counter, its lines
\text{the next item soon} @@ an array walked in order
\text{fetch a line of } 64 \text{ bytes, not one} @@ neighbours come along
\htmlClass{new}{\text{walk by rows: } 1 \text{ miss in } 8;\ \text{by columns: every look a miss}} @@ 8-byte numbers, a big grid stored by rows

The same sum over a big grid can run ten times slower walked by columns, because each look lands on a new line. A program is fast when it uses again what it used lately and walks memory in order.

39comp4A Line of Workers

Each instruction of 39j’s list passes through stages: fetch it, decode it, read the numbers, do the sum, write the result. Each stage is a separate circuit, so five instructions can be in five stages at once.

\text{one at a time: } 5 \text{ ticks each} @@ every stage waits
\text{in a line: one finishes every tick} @@ once the line is full
n \text{ instructions: } n + 4 \text{ ticks, not } 5n @@ nearly five times the work
\htmlClass{new}{\text{a jump (40b) whose way is not yet known stalls the line}} @@ so chips guess the way

Splitting each instruction into stages lets several run at once, as long as nothing waits on a result not yet made. Chips guess which way each jump goes and undo the work when they guess wrong.

39comp5Memory That Pretends

Each program sees memory starting at address 0, as if it had the machine to itself. A table, kept by the machine, sends each made-up address to a real one, in pages of 4096 bytes.

\text{made-up address} = \text{page} \cdot 4096 + \text{offset} @@ division with remainder
\text{page} \mapsto \text{real page, by the table} @@ a function (2h) the machine keeps
\text{page not in memory} \Rightarrow \text{fetch it from the drive} @@ a miss a million times dearer
\htmlClass{new}{\text{a small cache of the table itself}} @@ the table look-up is a look-up too

Made-up addresses give each program its own memory, walled off from the others, and let the drive stand in for memory the machine lacks. The same law of hits and misses rules each layer, from registers to drive.

Accepted names

The stack is the memory hierarchy; the two nearnesses are temporal and spatial locality; the law of 39comp2 is the average memory access time. Main memory is DRAM, cache is SRAM. The line of workers is a pipeline, guessing jumps is branch prediction, made-up addresses are virtual memory and the small cache of the table is the TLB.

Who said it first

Maurice Wilkes described a small fast “slave memory” in front of a big one in 1965, and IBM’s System/360 Model 85 shipped the first cache in 1968. Virtual memory first ran on the Atlas computer at Manchester in 1962.
