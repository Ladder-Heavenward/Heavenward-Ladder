Can You Compute on Secrets Without Seeing Them?

Can you compute on secrets without seeing them? Three friends want their average pay without anyone learning anyone else’s. A hospital wants a cloud server to run a test on records the server must not read. In 1982 Andrew Yao asked how two millionaires could learn who is richer while telling nothing else. The answers lean on 43·crypt’s sharing and on maps that keep plus and times, rung 44’s idea. Shares can be added without being opened; some locks let locked numbers be multiplied; and since 2009, a lock lets any computation run on what it hides. This page first fixes a choice in place without showing it, then adds shares, multiplies under a lock, and says what computing on locked data costs.

Commit by publishing a fingerprint of the choice and a random pad; open later by showing both. Split each secret into random shares that add to it; each friend adds the shares it holds, and only the total is opened. A lock that keeps times, E(a)·E(b) = E(ab), lets locked numbers be multiplied; one that keeps both plus and times lets any circuit of 39’s gates run on locked bits.

44crypt21Fixing a Choice Without Showing It

Zoe and Mike settle a bet by phone. Each must name heads or tails before seeing the other’s choice, and neither trusts the other to go first.

\text{publish } H(\text{choice} \,\|\, r),\ r \text{ a long random pad} @@ 22·crypt’s fingerprint
\text{hiding: the fingerprint says nothing of the choice} @@ r makes every choice look alike
\text{binding: no other choice gives the same fingerprint} @@ finding one is as hard as a clash
\htmlClass{new}{\text{open later by showing choice and } r} @@ anyone checks the fingerprint

From here on, on this page, to commit is to publish something that fixes a value now and reveals it only when its maker chooses to open it.

44crypt22Adding Secrets by Adding Shares

Zoe, Sarah and Mike earn 50, 70 and 60 thousand. They work on a clock of 1000 hours (43a). Each splits their pay into three shares that add to it, and hands one to each friend.

\text{Zoe: } 50 = 812 + 431 + 807 \pmod{1000} @@ two shares random, the third forced
\text{each share alone: any number, equally likely} @@ says nothing
\text{each friend adds the three shares they hold} @@ one from each friend
\htmlClass{new}{\text{the three sums add to } 180;\ \text{average } 60} @@ only the total is opened

Shared-sum technique: split each secret into random shares that add to it; sums of shares are shares of the sum, so a total can be computed and opened while no one sees any single secret. Adding is a map that keeps plus, so it passes through the sharing.

44crypt23Locks That Let You Multiply

Lock a number with 43o’s RSA: E(a) = ae mod n. Multiply two locked numbers.

E(a)\,E(b) = a^e b^e = (ab)^e = E(ab) \pmod n @@ powers of a product
\text{the server multiplies locked numbers, never seeing } a, b @@ only the key holder unlocks
E \text{ keeps times, but } E(a) + E(b) \ne E(a+b) @@ not plus
\htmlClass{new}{\text{a lock that keeps plus exists too (Paillier, 1999)}} @@ each keeps one operation

A lock that is a map keeping one operation lets that operation be done on locked numbers. But any computation needs both: 44l’s Boolean algebra builds every table from plus and times on bits, so a lock keeping both would run any program.

44crypt24Any Program on Locked Data

\text{AND} = a \cdot b,\ \ \text{XOR} = a + b \pmod 2 @@ 39f’s gates as times and plus
\text{a lock keeping both} \Rightarrow \text{any circuit runs locked} @@ every table from one gate
\text{each locked step adds a little noise} @@ the lock hides its number in noise
\htmlClass{new}{\text{too much noise: refresh by running the unlock itself, locked}} @@ Gentry, 2009

Craig Gentry’s 2009 scheme ran the unlocking circuit on locked data to scrub the noise, so steps can go on without end. Fully locked computing is possible, but each step still costs thousands to millions of times the plain step, so it is used for small jobs on very private data.

44crypt25Two Parties, One Circuit

Shares handle sums; for anything else, two parties can evaluate a whole circuit together. One scrambles each gate’s table with random labels; the other walks through it learning only labels, never the bits.

\text{each wire’s 0 and 1 get random labels} @@ the labels look alike
\text{each gate’s four rows locked under its input labels} @@ only the right row opens
\text{the walker gets its own input labels without saying which} @@ by a trade that hides its choice
\htmlClass{new}{\text{only the output wire’s labels are revealed}} @@ who is richer, and nothing else

Any computation two parties can write as a circuit can be done so that each learns the output and nothing more. Browsers use this kind of joint computing to check a password against lists of stolen ones without sending the password.

Accepted names

The commitment is a commitment scheme with hiding and binding; shares that add are additive secret sharing; computing jointly on secrets is secure multiparty computation (MPC). A lock keeping an operation is homomorphic encryption; keeping both, fully homomorphic (FHE); the refresh is bootstrapping. The scrambled circuit is a garbled circuit and the hiding trade oblivious transfer.

Who said it first

Rivest, Adleman and Dertouzos asked for computing on locked data in 1978. Andrew Yao posed the millionaires’ problem in 1982 and garbled circuits followed from his work; Pascal Paillier gave an additive lock in 1999, and Craig Gentry the first fully homomorphic scheme in 2009.
