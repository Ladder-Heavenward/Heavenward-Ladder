40·∎ · conclusion

Writing for the Machine

Name the numbers; write in three shapes; prove each shape by its technique, each loop by what it keeps and a number that falls; and translate so that every run is kept.

The conclusion · the rung's claim, in full, and its proof

This page opens once every question on 40j is ticked. The claim below is proved from the steps of this rung, so it waits for them.

What the rung set out to show

The survey of rung 40 promised a climb from the machine’s numbers to a language whose programs can be proved. 40a named the numbers, and 40b proved three shapes enough. 40c gave names their values, and 40d gave calls their pile. 40e proved recursion by induction, 40f wrote promises, and 40g proved loops. 40h checked types, 40i built data by repeating, and 40j carried a language down. This page puts the claim together.

The claim, in full

Labels and words are turned into instruction numbers by two passes, with every run kept. Every flow chart is sequence, choice and repetition with one extra cell. An assignment changes only its name, to the value its expression had before. Calls return in the reverse order they were made, each with its own names.

A function that calls itself is right if it is right on its start cases and right on each input whenever it is right on the smaller inputs it calls, and it stops if a whole-number measure falls at every call. {Q[e/x]} x ← e {Q}; promises chain through a middle condition, split by cases, strengthen before and weaken after; from {I ∧ B} c {I} follows {I} while B do c {I ∧ ¬B}. A program that passes the type check never hands an operation a value outside its types. A claim true of the empty list, and of h in front of t whenever true of t, is true of every list. A compiler that is right shape by shape is right on every program.

The Proof

Each part below is a technique already proved on a step of this rung.

\text{two passes: one number per line, one address per label} @@ the two-pass technique (40a3)
\text{any chart: a while around a chain of ifs} @@ three shapes are enough (40b3)
x \leftarrow e \text{ changes only } x @@ the assignment technique (40c2)
\text{returns reverse calls} @@ why a pile (40d2)

\text{recursion} = \text{induction; a falling whole number stops it} @@ 40e1, the falling-measure technique (40e2)
\{Q[e/x]\}\ x \leftarrow e\ \{Q\} @@ backwards-assignment (40f2), with sequence, choice and consequence
\{I\}\ \text{while } B \text{ do } c\ \{I \wedge \neg B\} @@ the while technique (40g1)
\text{well-typed runs keep every value in its type} @@ the type-check technique (40h2)
\text{shape-induction; compiling keeps runs} @@ 40i3, 40j2

So the rung’s claim holds: a program in names and shapes can be proved, piece by piece, and carried down to the machine with every run kept.
