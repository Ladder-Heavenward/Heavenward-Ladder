Some Questions No Machine Can Answer

Rung 39 built a processor out of switches that follows a list of orders, and counted its steps. Rung 4 had used the word recipe loosely for gcd, counting on and writing in twos, and 38b called checking a proof a recipe because it always stops. This rung makes the word exact. A tape machine reads one cell of a long tape, looks up one row of a finite table, writes, moves one place and changes state. It looks too weak to do much, and yet every other exact account of a recipe ever proposed, from feeding terms to one another to building functions by search, reaches exactly the same functions. The rung therefore locks the loose word to the tape machine and calls the lock a thesis, since no proof can show that it caught every recipe. Then it finds the limits. One machine runs every machine from its code, as a stored program does. No machine decides which machines stop, by 35b’s diagonal, and from that one gap the rung carries undecidability to every question about what programs do, to what arithmetic reaches, and to whole-number equations. Machines can print their own code. Machines with less memory check less, and the rung says exactly what they miss. Then it counts cost: some questions that a machine can answer take too long, and the gap between checking an answer and finding one is the most famous open question of the subject. Coins help, and a prover can convince a checker without telling it anything. The last steps run machines, reductions and such proofs by hand.

A tape machine is a finite table acting on a tape, and every exact account of a recipe reaches the same functions as it; locking “recipe” to it is a thesis, not a technique. One machine runs every machine. No machine decides which machines stop, so no machine decides any question about what programs do, nor what arithmetic reaches, nor which equations have whole-number solutions. Among questions that are decided, more time decides more, checking may be easier than finding, and coins and conversation change what can be shown fast.

What it means to say it

To say that some questions no machine can answer is to say this. Fix the tape machine as the exact meaning of “a machine computes f”. Then there are yes-or-no questions, stated about finite strings and with a true answer for every string, such that no tape machine answers every one of them correctly and stops. The stopping question is one; so is whether a program’s output has any property that some programs have and others lack; so is whether PA reaches a statement; so is whether an equation in whole numbers has a solution. And among the questions some machine does answer, some need more steps than any fixed power of the length of the question.

No tape machine decides which tape machines stop on which inputs, and none decides any property of what machines do that some machines have and others lack; among the questions that are decided, for every power of n some are decided in a larger power and in none smaller. The rung proves it. That “tape machine” means “recipe” is a thesis, held up by evidence and not by proof; the rung says where it is used.

Where it comes from

In 1900 and again in 1928 it was asked whether a mechanical method could settle every mathematical question. In 1936 three exact accounts of a method appeared within months: building functions by search, feeding terms to one another, and the tape machine, and they were soon proved to reach the same functions. The tape machine was offered with an argument that it caught what a person computing by rule could do, and with it the proof that no machine decides stopping. The stored program of the late 1940s is the universal machine in hardware. Machines with no memory and grammars were sorted into families in the 1950s. Time as a cost was made exact in 1965, NP-complete questions appeared in 1971 and 1972, and coin machines and conversations as proofs in the 1970s and 1985. The question of whole-number equations, asked in 1900, was settled in the negative in 1970. The names are in the cellars of the steps.

The principles, in plain words

The rung proves seven things.

First, a tape machine runs one step at a time, each step fixed by one row of its table, and a set is decided exactly when it and its outside are both listed. Many tapes do no more than one. Locking “recipe” to the tape machine is a thesis, in the green box of 41a: loose, then locked.

Second, three other exact accounts of a recipe, built functions with one search, feeding terms, and search formulas of arithmetic, reach exactly the functions tape machines compute. That is the main evidence for the thesis.

Third, every machine has a code, and one machine runs every machine from its code. There are more questions than machines, so some question is answered by none.

Fourth, the stopping set is listed and not decided, and its outside is not even listed. By carrying questions from one to another, no machine decides any property of what machines do that is not trivial, nor which statements PA reaches; and the equations with whole-number solutions are listed, with the step to undecided named and held in trust.

Fifth, a machine can print its own code, and any machine can be given its own code to read. Machines with no memory check only patterns, and patterns can be pumped; stack machines check more, and can be pumped twice; machines with bounded room have stopping decided.

Sixth, time and room are costs. Fast sets do not depend on the kind of machine, every set in NP fast-reduces to the satisfiable statements, more time decides more, and room can be saved by halving.

Seventh, coin machines answer with a chance of error fixed in advance, in the green box of 41i: laws with a known exception rate. Repetition lowers the chance, and a random point tests whether a polynomial is zero.

What follows

With those, the techniques work by hand. 41j runs machines line by line, proves small machines never stop, and runs the diagonal on a table. 41k turns any statement in clauses into a map that can be three-coloured exactly when the statement can be made true. 41l convinces a checker that a map can be three-coloured without showing a colouring. The annexes ask whether computing must cost energy, and find that only forgetting does, and whether faraway particles are secretly connected, with qubits, the inequality that hidden answers obey, its tests, and quantum factoring. The research fronts ask how long a machine with five states can run, whether checking is easier than finding, and whether a computer can tell if a knot is untied.

What you can do because you know it

You can write a tape machine for a task, run it, and say what set it decides or lists. You can show a question undecided by carrying the stopping question into it, and recognise when a question is not decided at all and when it is only slow. You can say what fast means, place a question in P or NP, carry one NP question into another, and say why a coin machine’s answer can be trusted to a stated chance.

And you can say exactly what the results do not show: not that people can do what machines cannot, and not that undecided questions have no answers, but that no single machine gets every answer right and stops.

What it costs

Nothing new is laid down. The rung spends rung 35’s diagonal and lists, rung 38’s calculus, codes, search formulas and provable mark, rung 4’s recipes and primes, rung 30’s spread of a sum, and rung 39’s switches and counted steps. One thing is a thesis, not a technique: that tape machines compute whatever can be computed. Held in trust: the step from listed to undecided for whole-number equations in 41e, and, on the research fronts, the bounds whose proofs run to hundreds of pages. At the end of the rung you will know what it means to say some questions no machine can answer, why it is true, and what you can do because you know it.
