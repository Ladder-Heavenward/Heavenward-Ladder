45l · proof

Merging Edits Made Apart

Copies on different machines are edited apart, and edits reach each copy in any order, some twice. This step finds the laws a merge must keep so that copies that have seen the same edits always agree, with no agreement step at all.

Let merging be grouping-free, order-free and repeat-free. Then a copy is the merge of the set of edits it has seen, and the same set gives the same copy.

45l1The Problem

Each copy applies edits as they reach it. Different copies get them in different orders, and a resent edit may come twice. The demand: two copies that have seen the same edits hold the same state.

45l2Three Conditions

Converge technique: if merge is associative, commutative and idempotent, then two copies that have merged the same set of updates, in any order and with any repeats, hold the same state.

Associative and commutative make the result of merging a list depend only on what is in it and how often (44a). Idempotent, x ⊔ x = x as x ∨ x = x in 44l, makes how often not matter. So the state depends only on the set.

45l3Counters and Sets

A count that only grows: each machine holds a list with one entry per machine, adds only to its own entry, and merges by taking the larger entry place by place. Larger-of is associative, commutative and idempotent. The value is the sum of the entries.

A set that only grows merges by union, which also keeps the three conditions. Taking things out needs care: a removed item is kept on a second set of removals, so a late copy of its adding cannot bring it back.

45l4Text Is Harder

In a shared text, “put x at place 5” means something else once another edit has put a letter at place 2. One answer shifts each edit’s places by the edits it meets, and its techniques must be right for every order, which is hard to get right. The other gives every letter a lasting name between its neighbours, so places never shift and the three conditions can hold again.
