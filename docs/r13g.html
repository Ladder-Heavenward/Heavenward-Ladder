13g · technique

The growing square

13a defined the slope and computed it for the square, the cube and one over the input. This step puts the definition in your hands until the gesture runs without asking. Take the square, change the input a little, and write the new product in 5i's grid of cells. There is the old product, two cells that each carry the change once, and one cell that carries it twice. Take away the old product, divide by the change, which is never 0, and you have the chord slope exactly. Then the limit decides which cells stay and which go to 0, and a single count settles it: how many times a cell carries the change. The cube runs the same way, and so does every polynomial, by two roads.

Change the input a little, and write the new value in the grid of cells. Take away the old value, and divide by the change. Every cell that carries the change once leaves a piece without it, which stays. Every cell that carries it twice or more leaves some behind, which goes to 0 in the limit.

13g1A proverb, and what the words mean here

A popular calculus book of 1914 opens with an old proverb, for the reader who is afraid of the subject: what one fool can do, another can. It means it as comfort, and it is the right mood for a technique step.

The title uses three words that have shapes in everyday speech, and none of the shapes is meant. “Square” is 5f's word: x² is x · x, a product, and nothing else. “Growing” says only that the input changes, from x to x + h. And the cells are 5i's grid of cells, which 13c said plainly: an arrangement of products in writing. There is a row for each term of one sum and a column for each term of the other. The grid is often drawn as a picture of something growing by strips, with a size read into each cell. The ladder has not built that, and rung 15 builds what they would read into it. So a cell holds a product, and this step calls it the cell's product.

One more word, for the next power. From here on, x³ is also read “x cubed”, and called the cube of x: x · x · x, a product, as 5f's square is x · x. 8f read ³√u as “the cube root of u”, and 9f's picture had a link called “cube”; both are this product, run backwards or forwards. The shape that shares the name waits for geometry, on rung 18.

13g2The square, in the grid of cells

Let y = x · x and change the input by h, a real other than 0 (13a's line). The new value is (x + h)(x + h), a product of two sums. So 5i's grid-of-cells technique writes it as four cells: a row for x and a row for h, a column for x and a column for h.

(x + h)(x + h) = \htmlClass{keep}{x \cdot x} + x \cdot h + h \cdot x + \htmlClass{new}{h \cdot h} @@ grid-of-cells with a = c = x and b = d = h: one cell for each row and column
= x^2 + \htmlClass{new}{2xh} + h^2 @@ turn-about for times on ℝ: x · h and h · x are like terms; collect them (5i)

The x · x cell is the old product: its cell's product is y itself. The two cells x · h and h · x each carry one factor h. The h · h cell carries two. Now run 13a's gesture through the grid, one move per line.

y + \Delta y = (x + h)(x + h) @@ 13a's Δ: the new value is the old value plus the change
y + \Delta y = x^2 + 2xh + h^2 @@ the grid of cells, collected
\Delta y = \htmlClass{new}{2xh + h^2} @@ take away y = x² from both sides (adding-keeps-answers): the change, all of it
\dfrac{\Delta y}{h} = \htmlClass{new}{2x + h} \quad (h \ne 0) @@ multiply by h⁻¹ (spread on ℝ, reciprocal on ℝ): licensed because h ≠ 0. This is the chord slope, exactly
y' = \lim_{h \to 0}\,(2x + h) = \htmlClass{keep}{2x} @@ agreeing-near and line-limit (10a): the linear function h ↦ 2x + h heads to its value at 0. slope-of-x² again

Read the fourth line cell by cell. The two one-h cells, divided by h, became 2x, which has no h left in it. The h · h cell, divided by h, became h. Nothing was set aside: for every h ≠ 0 the chord slope is 2x + h, not “about 2x”. Then the limit sends h to 0, and the piece that still carries an h goes with it. The slope is where the chord slopes head.

Check it with numbers. At x = 100 with h = 1, the new product is 101 · 101 = 10201, so Δy = 201. The one-h cells give 200 and the h · h cell gives 1. With h = 0.1, 100.1 · 100.1 = 10020.01, so Δy = 20.01 and the chord slope is 20.01/0.1 = 200.1. The one-h cells give 200 every time. The h · h cell gives exactly h after the division, and only the limit takes it away.

13g3The count of h decides

Why does the h · h cell go and the one-h cells stay? Not because it is small. For one fixed h every cell is just a real, and h · h can be larger than 2xh (take x = 0.01 and h = 1). The difference shows only after the division, and only in the limit.

From here on, in this step, the h-count of a cell is the number of factors h written in it. The cell x · x has h-count 0, x · h has h-count 1, h · h has h-count 2.

Count-of-h technique: let a cell be c · hᵏ, with c a real that does not depend on h and k a number. If k = 0, the cell is part of the old value and leaves in the subtraction. If k = 1, the cell divided by h is c, which stays in the limit. If k ≥ 2, the cell divided by h is c · hᵏ⁻¹, which heads to 0 as h → 0.

k = 0:\ \ c \text{ is also a cell of the old value} @@ put h = 0 in the grid: only the h-count-0 cells remain, and they make the old value (power-zero, anything-times-zero)
k = 1:\ \ \dfrac{c\,h}{h} = \htmlClass{new}{c} \quad (h \ne 0) @@ regroup for times on ℝ, reciprocal on ℝ, times-one on ℝ: licensed because h ≠ 0. A constant heads to itself (line-limit with step 0)
k \ge 2:\ \ \dfrac{c\,h^k}{h} = c\,\htmlClass{new}{h^{k-1}} @@ power-of-a-next and reciprocal on ℝ: one factor h cancels, at least one is left
\lim_{h \to 0} c\,h^{k-1} = c \cdot 0^{k-1} = \htmlClass{keep}{0} \quad \blacksquare @@ power-limit and constant-factor (10c): hᵏ⁻¹ heads to 0ᵏ⁻¹, which is 0 since k − 1 ≥ 1 (anything-times-zero)

A large number in front changes nothing: 500 · h · h divided by h is 500h, which still heads to 0. A small number in front saves nothing either: 0.001 · h divided by h is 0.001, which stays. It is the count of h's, never how small a cell looks for one h, that decides.

That popular book sorts small quantities into those of the first order of smallness and those of the second. It lets the second go as negligible beside the first.

Its sorting is the h-count, and its instinct is right about which pieces leave. The ladder's reason is different. No piece is negligible: for every h ≠ 0, every cell is in the chord slope. The pieces with h-count 2 or more leave because, after the division, they still carry an h. Count-of-h sends that h to 0 in the limit.

13g4The cube, likewise

Now y = x³ = x · x · x. The new value is (x + h)(x + h)(x + h), which is (x + h) times the square's four cells. So the grid has two rows, x and h, and four columns, the square's cells x · x, x · h, h · x, h · h: eight cells in all.

(x + h)^3 = (x + h)\,(x \cdot x + x \cdot h + h \cdot x + h \cdot h) @@ power-of-a-next for powers of a real; the square's grid above
= \htmlClass{keep}{x^3} + \htmlClass{new}{3x^2 h} + 3x h^2 + h^3 @@ grid-of-cells, two rows by four columns: one cell of h-count 0, three of h-count 1, three of h-count 2, one of h-count 3; collect
\Delta y = 3x^2 h + 3x h^2 + h^3 @@ take away y = x³ (adding-keeps-answers)
\dfrac{\Delta y}{h} = \htmlClass{new}{3x^2} + 3xh + h^2 \quad (h \ne 0) @@ divide by h: count-of-h, cell by cell
y' = \htmlClass{keep}{3x^2} @@ count-of-h: only the three one-h cells stay. slope-of-x³ again

Count the cells by their h-count: one, three, three, one. That is row 3 of 4k's table, and it is no accident. Picking, from each of the three brackets, either its x or its h is 4k's counting of choices. So the cells with k factors h number by choosing-counts-parts. These counts have the accepted name binomial coefficients: a binomial is a sum of two terms, like x + h. At x = 2 with h = 0.1: the old product is 8. The one-h cells give 3 · 4 · 0.1 = 1.2. The two-h cells give 3 · 2 · 0.01 = 0.06. The three-h cell gives 0.001. Together 1.261, and 2.1³ − 8 = 9.261 − 8 = 1.261. Divided by h: 12 + 0.6 + 0.01 = 12.61, which heads to 12.

Further, you cannot lay the cells out flat, but the counting does not care. For xⁿ, 4k's binomial technique, read in ℝ, writes (x + h)ⁿ as the sum of the cells . The cells with h-count 1 are = n of them, each x^{n−1}h. Count-of-h keeps exactly those, so the slope is n x^{n−1}: 13d's power for slopes, seen by counting instead of by induction. The second entry of every row of 4k's table is the power itself.

13g5Any polynomial, from first principles

A polynomial is a statement that names a sum of terms uₖxᵏ (9g). Change x to x + h in each term, and expand each power by the grid or by two-term-power. What comes out is a sum of cells, each a real times a power of h. Collect the cells by their h-count and you have a polynomial in h. Its h-count-0 cells make p(x) (put h = 0); its h-count-1 cells make the slope.

Polynomial-chord technique: for a polynomial p and a real w, there is a polynomial Q in h with (p(w + h) − p(w))/h = Q(h) for every h ≠ 0. Then p′(w) = Q(0), which is the coefficient of h in p(w + h).

p(w + h) = \textstyle\sum_{k \le n} u_k (w + h)^k @@ substitute for the expression (9g's line)
= b_0 + b_1 h + b_2 h^2 + \cdots + b_n h^n @@ two-term-power on each power, then collect by powers of h (termwise, factor-out): b's are reals that depend on w, not on h
b_0 = p(w) @@ put h = 0: every term with an h is 0 (anything-times-zero), and (w + 0)ᵏ = wᵏ
\dfrac{p(w + h) - p(w)}{h} = \htmlClass{new}{b_1 + b_2 h + \cdots + b_n h^{n-1}} \quad (h \ne 0) @@ take away b₀ = p(w); multiply by h⁻¹: call this Q(h), a polynomial in h
p'(w) = \lim_{h \to 0} Q(h) = Q(0) = \htmlClass{keep}{b_1} \quad \blacksquare @@ agreeing-near; substitution (10c): a polynomial in h heads to its value at 0

There is a second road, and it uses only 9g's techniques. Since p(w) − p(w) = 0, the real w is a zero of the polynomial x ↦ p(x) − p(w). So factor writes p(x) − p(w) = (x − w)q(x) for a polynomial q. Then for x ≠ w, by 13a's two-ways-to-write-a-limit, the chord slope is (p(x) − p(w))/(x − w) = q(x). Its limit as x → w is q(w), by substitution. So p′(w) = q(w), and polynomial-division's long division finds q. The displacement pattern x − w is the factor that the division takes away.

p(2) = 8 - 4 + 5 = 9 @@ substitute for the expression
p(2 + h) = 8 + 12h + 6h^2 + h^3 - 4 - 2h + 5 @@ the cube's cells at 2: 2³, 3 · 2² · h, 3 · 2 · h², h³
= 9 + \htmlClass{new}{10h} + 6h^2 + h^3 @@ collect by powers of h
p'(2) = \htmlClass{keep}{10} @@ polynomial-chord: the coefficient of h. polynomial-slope agrees: 3 · 2² − 2 = 10
p(x) - 9 = x^3 - 2x - 4 = (x - 2)(x^2 + 2x + 2) @@ the second road: factor, with q found by polynomial-division (multiply back by 5i's grid to check)
q(2) = 4 + 4 + 2 = \htmlClass{keep}{10} @@ the slope, again: p′(2) = q(2)

So every polynomial's slope can be found from the definition with no rule at all: expand, collect by h-count, read the h-count-1 coefficient. Polynomial-slope is the same answer collected once for all.

13g6Illegal moves, and why each breaks

y = x^2 + 3x:\ \ \Delta y = 2xh + h^2 + \htmlClass{keep}{3h} @@ the change: the square's cells and the cell 3 · h. Its h-count is 1
3h \text{ “is small, so drop it”}\,? @@ divided by h it is 3, which stays. Dropped, the answer is 2x, the slope of another function; the true slope is 2x + 3
h = 0 \text{ “to remove the } h \cdot h \text{ cell”}\,? @@ then Δy = 0 and the chord slope is 0/0 (nothing-times-0-is-1). The cell is not made 0; count-of-h sends it to 0 in the limit, after the division
(x + h)^2 = x^2 + h^2\,? @@ loses both one-h cells, the only cells that stay. At x = 3, h = 1: 16 against 9 + 1 = 10
\dfrac{\Delta y}{h} = 2x + h \text{, so } y' = 2x + h\,? @@ the chord slope is not the slope. The slope is a limit: no h survives it

13g7Running it backwards

The forward gesture turns a function into its change. Backwards, a change rebuilds the function, and it is exact. Suppose some y answers every x and every h with the change Δy = 6xh + 3h². Put x = 0 and call the change x: then y(x) − y(0) = 6 · 0 · x + 3x² = 3x², so y(x) = 3x² + y(0). The change fixes how y grows, and fixes y itself once one value is known. Check by running forward: 3(x + h)² − 3x² = 6xh + 3h².

Backwards from the slope alone is a different question. Which y has slope 3x²? x³ does, and so does x³ + 7, by 13d's lifting. Slope 2x + 3? x² + 3x, or that plus any constant. Whether those are all the answers is rung 14's question, as 13d said. And backwards from a chord slope: say the chord slopes of some polynomial at w are exactly 5 + 4h + h². Then by polynomial-chord its slope at w is 5. And p(w + h) = p(w) + 5h + 4h² + h³: the cells of a cube at some input, plus a lift.
