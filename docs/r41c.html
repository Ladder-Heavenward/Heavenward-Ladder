41c · proof

One Machine Runs Them All

A tape machine is a table, and a table is a short list of rows. Write the rows down as a string, and the machine has become something another machine can read. That is the whole idea of this step, and it changes what a machine is. Until now each job had its own machine: one to add one, one to compare counts, one to check a proof. Here one machine is built that takes two things on its tape, the written table of any machine and an input, and does exactly what that machine would do on that input, step for step, a little slower. The table is no longer wiring. It is data, the same stuff as the input. The processor of the rung before already worked this way, with its instructions stored as numbers in its memory beside the numbers it worked on, and this step says why that was enough to run any program at all. Then a count. Machines can be listed, because their tables are strings. Questions with yes or no answers about numbers cannot be listed, by the rung on sizes. So most such questions are answered by no machine at all, and the next step names one.

A machine’s table is a string, and one machine reads such a string and an input and does what the written machine would do. Program and data are the same stuff. Machines can be listed and the yes-or-no functions on numbers cannot, so most of them are computed by no machine.

41c1A Machine Written as a String

Number the states 1, 2, …, k with 1 the start and 2 the stop, the marks 1, 2, …, m with 1 the blank, and the steps L as 1 and R as 2. A row δ(q, s) = (s′, d, q′) is written as five blocks of 0s with a single 1 between neighbouring blocks: q 0s, then s, then s′, then d, then q′. The rows are written one after another with 11 between them. The string is the machine’s code, written ⟨M⟩.

Table-code technique: every tape machine has a code, a string of 0s and 1s; different tables have different codes; and whether a string is the code of some machine is decided.

41c2The Universal Machine

The universal machine U has three tapes. The first holds ⟨M⟩ and never changes. The second holds M’s tape, each of M’s marks written as its block of 0s, with a separator between cells. The third holds M’s state, as a block of 0s. U starts on ⟨M⟩ # w by copying w onto the second tape in that form and writing 0 on the third.

Universal technique: there is one tape machine U such that for every machine M and every input w, U on ⟨M⟩ # w stops exactly when M on w stops, in the same stop state and with the same output.

\text{read }\allowbreak \text{the }\allowbreak \text{state } q \text{ on }\allowbreak \text{tape }\allowbreak \text{3 }\allowbreak \text{and }\allowbreak \text{the }\allowbreak \text{mark } s \text{ under }\allowbreak \text{M’s }\allowbreak \text{head }\allowbreak \text{on }\allowbreak \text{tape }\allowbreak \text{2} @@ two blocks of 0s
\text{walk }\allowbreak \text{tape }\allowbreak \text{1 }\allowbreak \text{to }\allowbreak \text{the }\allowbreak \text{row }\allowbreak \text{whose }\allowbreak \text{first }\allowbreak \text{two }\allowbreak \text{blocks }\allowbreak \text{are } 0^q, 0^s @@ compare block lengths by crossing off, a few rows of U’s table

So U spends at most c steps on each step of M, with c fixed by M’s code, and by the tracks technique the three tapes become one. U’s own table is fixed and finite. It does not grow with the machines it runs.

That is the stored program. 39j’s processor keeps its instructions as numbers in the same memory as its data, and its fetch-and-run loop reads the next instruction, does it, and reads the next. That loop is U, and the memory is tape 1 and tape 2 at once. Loading a new program is writing a string, not rewiring: the program is data.

41c3Most Questions Have No Machine

A yes-or-no question about numbers is a function g from ℕ to {0, 1}, or, the same thing, the set of n with g(n) = 1. A machine answers it when it decides that set, reading n written in twos.

Few-machines technique: some yes-or-no question about numbers is answered by no tape machine.

The proof is 35c’s diagonal, run on machines: at place n, look at whether machine n says yes to n, and take the other answer. It names no machine and no question. It shows that the questions machines answer are a countable crowd among uncountably many. Which question is missed depends on running each machine on its own number, and the next step does exactly that, carefully.

The accepted names

The code ⟨M⟩ is a description or encoding of the Turing machine; the list M₀, M₁, … is an enumeration of Turing machines. U is the universal Turing machine. A processor that keeps its program in the memory it computes in is a stored-program computer, or von Neumann architecture. The few-machines technique is the counting argument that there are uncountably many undecidable languages.

Who said it first

Alan Turing built the universal machine in his paper of 1936; his coding of tables as “description numbers” is the table-code technique. John von Neumann’s draft report on the EDVAC (1945) described a computer storing its program in its memory, and the Manchester Baby ran the first stored program on 21 June 1948. Small universal machines have been studied since Claude Shannon showed in 1956 that two states, or two marks, are enough if the other is allowed to grow; Marvin Minsky gave one with 7 states and 4 marks in 1962.

A proof that is not allowed

“U can run every machine. So U can run every machine to its end and report what happened.” Not allowed: U runs a machine for as long as that machine runs. If the machine never stops, neither does U, and there is no end to report. Whether some other machine could report without waiting is 41d’s question.
