22·now · research front

Can one digit of π be found alone?

Can one digit of π be found alone? To learn the millionth decimal digit of π, people work out all the digits before it. There are ways to aim at one decimal digit alone, but they are slower than working out the whole run. In 1995 a computer search turned up a sum for π that does something new. In base sixteen, it gives a digit far out without the digits before it, using almost no memory. What makes it surprising is that π is one fixed number, and each of its digits seems to depend on all of it at once. This page shows, with 15i’s endless ratio sums and 22e’s geometric yardstick, how such a sum is proved, how it peels off a far digit, why every digit it gives is read from a fence that must be checked, and what is still unknown. Nobody knows whether a sum like it exists for base ten. Nobody knows whether the digits of π are spread evenly, in any base.

The sum has terms that shrink by a factor of sixteen, and each term is four small fractions. Multiply π by sixteen again and again, and its digits slide left past the point. In the sum, that multiplying touches only small whole numbers, and only their remainders on division matter. The terms left over shrink so fast that the geometric yardstick caps them. The result is a fence around the fraction part, and a digit is read off it wherever the whole fence agrees. The sum was found by a computer’s search and only then proved by hand, term by term, through an area.

22now1A digit far out

In base sixteen each place is a sixteenth of the place before. The digits run 0 to 9, then A, B, C, D, E, F for ten to fifteen. In base sixteen, π = 3.243F6A8885A308D3… . Write frac x for x − ⌊x⌋, the part of x after the point, and δₙ for the digit in place n after the point.

\pi = 3 + \tfrac{\delta_1}{16} + \tfrac{\delta_2}{16^2} + \tfrac{\delta_3}{16^3} + \cdots @@ the digits as an endless sum (8·cb5, in base sixteen)
16^d\pi = \text{a whole number} + \tfrac{\delta_{d+1}}{16} + \tfrac{\delta_{d+2}}{16^2} + \cdots @@ multiply by 16ᵈ: the first d digits pass the point
\operatorname{frac}(16^d\pi) = \tfrac{\delta_{d+1}}{16} + \tfrac{\delta_{d+2}}{16^2} + \cdots @@ the rest lies in [0, 1)
\htmlClass{new}{\delta_{d+1} = \lfloor 16\,\operatorname{frac}(16^d\pi) \rfloor} \quad \blacksquare @@ times 16: δ_{d+1} plus a part in [0, 1)

Shift technique: the digit in place d + 1 is the whole part of sixteen times the fraction part of 16ᵈπ. So a far digit needs only frac(16ᵈπ), and only roughly. It does not need the digits before it, if frac(16ᵈπ) can be reached some other way.

22now2A sum, taken through an area

First a smaller sum, with the same moves. The area under 1/(1 − x) from 0 to ½ is ln 2. Split 1/(1 − x) into a ratio sum and a leftover, and take the area of each piece.

\tfrac{1}{1 - x} = 1 + x + \cdots + x^{n-1} + \tfrac{x^n}{1 - x} @@ finite-ratio-sum (15i), for x ≠ 1
\int_0^{1/2}\tfrac{dx}{1 - x} = \textstyle\sum_{k=1}^{n}\tfrac{1}{k\,2^k} + \int_0^{1/2}\tfrac{x^n}{1 - x}\,dx @@ the area of xᵏ⁻¹ from 0 to ½ is (½)ᵏ/k (16c)
\ln 2 = \big[-\ln(1 - x)\big]_0^{1/2} @@ ∫g′/g = ln|g| (17i)
0 \le \int_0^{1/2}\tfrac{x^n}{1 - x}\,dx \le \tfrac12 \cdot 2 \cdot \big(\tfrac12\big)^n @@ on [0, ½], xⁿ ≤ (½)ⁿ and 1/(1 − x) ≤ 2: width times greatest height
\htmlClass{new}{\ln 2 = \textstyle\sum_{k=1}^{\infty}\tfrac{1}{k\,2^k}} \quad \blacksquare @@ the leftover heads to 0 (15i): the partial sums settle on ln 2 (22d)

Term-by-term technique: split the function into a ratio sum and a leftover, take the area of each piece, and show that the leftover’s area heads to 0. The leftover is capped by a geometric sum, 22e’s yardstick, so it vanishes fast. Twenty terms give ln 2 to within a millionth.

22now3The sum for π

The same moves, with 1/(1 − x⁸) on [0, 1/√2]. For j = 1, 2, …, 8, the area of x^(8k + j − 1) from 0 to 1/√2 is (1/√2)^(8k + j)/(8k + j), and (1/√2)⁸ = 1/16. The leftover is at most 16⁻ⁿ times a fixed number, since x⁸ ≤ 1/16 there.

\int_0^{1/\sqrt2}\tfrac{x^{j-1}}{1 - x^8}\,dx = \tfrac{1}{(\sqrt2)^j}\textstyle\sum_{k=0}^{\infty}\tfrac{1}{16^k\,(8k + j)} @@ term by term, as for ln 2
\textstyle\sum_{k=0}^{\infty}\tfrac{1}{16^k}\Big(\tfrac{4}{8k+1} - \tfrac{2}{8k+4} - \tfrac{1}{8k+5} - \tfrac{1}{8k+6}\Big) = \int_0^{1/\sqrt2}\tfrac{4\sqrt2 - 8x^3 - 4\sqrt2\,x^4 - 8x^5}{1 - x^8}\,dx @@ j = 1, 4, 5, 6, each times (√2)ʲ; sums-are-linear
= \int_0^1 \tfrac{16(y - 1)}{(y^2 - 2)(y^2 - 2y + 2)}\,dy @@ y = √2 x (16d); top and bottom share (y² + 2)(y² + 2y + 2)
= \int_0^1 \Big(\tfrac{4y}{y^2 - 2} - \tfrac{4(y - 1)}{(y - 1)^2 + 1} + \tfrac{4}{(y - 1)^2 + 1}\Big)\,dy @@ partial fractions (17k); y² − 2y + 2 = (y − 1)² + 1
= \Big[\,2\ln|y^2 - 2| - 2\ln\big((y - 1)^2 + 1\big) + 4\arctan(y - 1)\Big]_0^1 @@ ∫g′/g = ln|g| (17i); arctan′ u = 1/(1 + u²) (21m)
\htmlClass{new}{= 0 - \big(2\ln 2 - 2\ln 2 - \pi\big) = \pi} \quad \blacksquare @@ arctan 0 = 0, arctan(−1) = −π/4

Digit-sum technique (the BBP formula): π is an endless sum whose terms shrink by a factor of sixteen, each made of four small fractions. These lines are not how it was found. A computer was set to hunt for whole numbers u₁, …, u₈ that make Σ 16⁻ᵏ Σⱼ uⱼ/(8k + j) agree with π to many places. It found 4, 0, 0, −2, −1, −1, 0, 0. A match to many places is a guess. The column above is what made it a technique.

22now4Peeling off a far digit

Write Sⱼ = Σ 1/(16ᵏ(8k + j)), so π = 4S₁ − 2S₄ − S₅ − S₆. The shift technique needs frac(16ᵈπ). Split each 16ᵈSⱼ at k = d.

16^d S_j = \textstyle\sum_{k=0}^{d}\tfrac{16^{d-k}}{8k + j} + \sum_{k=d+1}^{\infty}\tfrac{16^{d-k}}{8k + j} @@ split at k = d
16^{d-k} = q\,(8k + j) + \rho_k,\ \ 0 \le \rho_k \lt 8k + j @@ division with remainder (4j)
\operatorname{frac}\tfrac{16^{d-k}}{8k + j} = \operatorname{frac}\tfrac{\rho_k}{8k + j} @@ the whole number q drops out
0 \lt \textstyle\sum_{k=d+1}^{\infty}\tfrac{16^{d-k}}{8k + j} \lt \tfrac{1}{8d + j}\big(\tfrac{1}{16} + \tfrac{1}{16^2} + \cdots\big) = \tfrac{1}{15\,(8d + j)} @@ the geometric yardstick (22e)
\htmlClass{new}{\operatorname{frac}(16^d\pi) = \operatorname{frac}\big(4F_1 - 2F_4 - F_5 - F_6\big),\ \ F_j = \operatorname{frac}(16^d S_j)} \quad \blacksquare @@ whole multiples of whole parts drop out

The remainders ρₖ need no huge number. To get the remainder of 16²ᵉ, square the remainder of 16ᵉ and take its remainder again. So 16 to the power of a million takes about twenty squarings, and no number along the way passes (8k + j)². The tail is added term by term until what is left falls below the width wanted.

Peeling technique: the digits of π past place d need only remainders of powers of sixteen and a short tail, never the digits before. The work grows a little faster than d, and the memory hardly grows at all.

22now5A digit is read from a fence

A computer adds in its own arithmetic, keeping about sixteen decimal figures. Each of the 4d remainder fractions rounds a little. So frac(16ᵈπ) comes out as x, with a width w on each side.

\operatorname{frac}(16^d\pi) \in [x - w,\ x + w] @@ the computed value, and its width
\tfrac{i}{16} \le x - w \ \text{ and } \ x + w \lt \tfrac{i + 1}{16} @@ the whole fence inside one sixteenth
\htmlClass{new}{\delta_{d+1} = i} \quad \blacksquare @@ the shift technique, at every point of the fence
Anexact, yet rigorous · the cloud

21a said that every value of π is a fence. The peeling technique keeps that promise in a new way. It never gives π, only frac(16ᵈπ) with a width. At place one million, a run in ordinary arithmetic gives 26C65E52CB31…, and the true digits there are 26C65E52CB45… . Ten digits are right; the rest are rounding.

Report only the digits on which the whole fence agrees.

A fence that straddles a boundary gives no digit at all, however narrow it is. Near a run like …FFFF… or …0000…, a far narrower fence is needed. So record runs of π, now past a hundred trillion decimal digits, are checked by peeling hex digits near their end with sums of this kind, and comparing.

Two runs at the same place, with widths 10⁻¹⁰ and 10⁻¹², agree on eight hex digits and then part. Which digits would you publish?

22now6What is proved, and what is open

The research front here is close to the ground. Some of it is proved, some of it is ruled out, and some of it is plainly open. The sum and its base-sixteen digits are proved; a base-ten sum and the even spread of π’s digits are not.

  • Proved. The digit sum (1995, in print 1997), and with it the peeling technique for base sixteen, and so for base two, since each hex digit is four binary digits. Sums of the same kind are known for ln 2, for π², and for many other numbers.
  • Ruled out. A 2004 paper showed that no sum from one natural family of this kind, the family the known base-sixteen sums belong to, gives π in base ten. Whether some sum of another kind does is open.
  • Open. Whether π is normal: whether each digit, and each string of digits, turns up equally often in the long run. Trillions of digits look evenly spread, in base ten and in base sixteen. A count of cases proves no rule (1a), and no proof is known in any base.
  • A bridge, 2001. Run the peeling one place at a time: x₀ = 0, and xₙ = frac(16xₙ₋₁ + (120n² − 89n + 16)/(512n⁴ − 1024n³ + 712n² − 206n + 21)). Then ⌊16xₙ⌋ gives the hex digits of π, as far as anyone has checked. It was shown that if the xₙ spread evenly over [0, 1), then π is normal in base sixteen. That plain-looking hypothesis is open too.

The basement · there if you want it

The accepted names

Base sixteen is hexadecimal, and its digits hex digits. The digit sum is the BBP formula; sums of its kind are BBP-type formulas. The peeling technique is digit extraction, and a method that gives digits one at a time with little memory is a spigot algorithm. Squaring and taking remainders is fast exponentiation, or square-and-multiply. The computer’s hunt for whole numbers is an integer relation search, by an algorithm called PSLQ. A number whose digit strings all turn up equally often is normal. The field that finds by computer and then proves is experimental mathematics.

Who said it first

Simon Plouffe found the sum in 1995 with a search program by Helaman Ferguson and David Bailey, working with Peter Borwein; Bailey, Borwein and Plouffe published it in 1997. The sum ln 2 = Σ 1/(k 2ᵏ) is centuries old. Fabrice Bellard (1997) found a faster sum of the same kind; Colin Percival’s project PiHex (2000) used it to find the quadrillionth binary digit of π. David Bailey and Richard Crandall (2001) built the bridge from π’s normality to the sequence xₙ. Jonathan Borwein, Will Galway and David Borwein (2004) ruled out the natural family of base-ten sums. In 22·now.8.5, Arthur Jaffe and Frank Quinn (1993) asked for clear labels on unproved mathematics, and Doron Zeilberger (1993) argued that a proof checked to near certainty by computer may be worth more than its cost.
