Can a Chip Leak Its Key Through Its Power Cord?

Can a chip leak its key through its power cord? A cipher can be beyond any known attack on paper and still give its key away in practice, because the machine running it takes time and draws power, and both depend on the secret. In 1996 Paul Kocher timed how long a chip took to sign and read its key off the clock; in 1999 he read keys off a chip’s power draw. This page counts how much a check that stops early gives away, finds from 39·eng’s energy per switch why power follows the bits, shows how averaging many readings pulls a faint signal out of noise, and says how code is written to leak nothing.

A check that stops at the first wrong byte tells by its time how many bytes were right, so the key falls a byte at a time: 16 × 256 tries, not 256¹⁶. Each switch that flips spends energy C V², so power tracks how many bits flip. Averaging N readings shrinks the noise by √N. Code that takes the same time and draws the same power whatever the secret leaks nothing.

39crypt1A Check That Stops Early

Randy’s door lock compares a typed 16-byte code with the stored one, byte by byte, and stops at the first that differs. Mike can time each try.

\text{first byte wrong: stop after } 1 \text{ comparison} @@ quickest
\text{first byte right: stop after } 2 @@ a few billionths longer
\text{time} \propto 1 + \text{number of right bytes in front} @@ the time counts the right bytes
\htmlClass{new}{\text{the slowest of 256 guesses for byte 1 is right}} @@ then the same for byte 2

From here on, on this page, a side channel is anything the machine gives off besides its answer that depends on the secret: time, power, sound, heat.

39crypt2Counting the Tries

\text{whole code: } 256^{16} = 2^{128} \text{ guesses} @@ the counting principle (4·stat)
\text{byte by byte: } 16 \times 256 = 4096 @@ each byte found alone
2^{128} \approx 3.4 \times 10^{38} @@ beyond every computer
\htmlClass{new}{\text{a leak turns a product of choices into a sum}} @@ 4096 tries, a minute at the door

Side-channel technique: when a machine’s time or power reveals one piece of the secret at a time, the secret falls piece by piece, and the count of tries drops from a product to a sum.

39crypt3Power Follows the Flips

39·eng found that each switch that flips charges or drains a tiny capacitance, spending energy C V² each cycle it does so. A switch that stays still spends almost nothing.

E_{\text{flip}} \approx C V^2 @@ 39·eng, per switch per flip
E \approx k \cdot C V^2 @@ k the number of bits that flip
\text{loading } 0000\,0000 \to 1111\,0000:\ k = 4 @@ four flips
\htmlClass{new}{\text{power} \approx a + b \cdot (\text{bits that flip})} @@ a straight line in the flip count

When a chip mixes a key byte into a message byte it knows, the bits that flip depend on the key byte. Mike guesses the key byte and predicts the flip count for many messages. The guess whose predictions rise and fall with the measured power is the key.

39crypt4Averaging Pulls Out the Key

One reading is mostly noise: the flip of one byte is buried under thousands of other switches. Mike records many runs and lines them up.

\text{one reading: signal } s,\ \text{noise spread } \sigma @@ σ ≫ s
\text{mean of } N:\ \text{noise spread } \sigma / \sqrt{N} @@ the spread of a mean (30q)
\sigma = 50 s:\ \ N = 2500 \Rightarrow \sigma/\sqrt{N} = s @@ the signal stands as tall as the noise
\htmlClass{new}{\text{a few thousand runs read a key no single run shows}} @@ and computers record millions

Noise shrinks as one over the square root of the number of readings, so a leak too faint to see once is plain after thousands. That is why a small leak is a broken lock, not a small weakness.

39crypt5Code That Leaks Nothing

\text{compare every byte, always} @@ the time no longer counts right bytes
\text{no jump (40b) or table look-up that depends on the secret} @@ jumps and caches (39comp) take secret-dependent time
\text{mask: work on } x \oplus r,\ r \text{ fresh and random} @@ the flips no longer follow the key
\htmlClass{new}{\text{same time, same power, whatever the secret}} @@ the side channel carries nothing

Even the cache leaks: a program that reads a table at a secret place leaves that place in the cache, and another program on the same chip can time its own reads to find it. In 2018 the Spectre attacks used the chip’s own guessing at jumps to read memory across walls. A cipher is only as secret as the machine that runs it.

Accepted names

These are side-channel attacks: timing attacks, simple and differential power analysis (DPA), correlation power analysis and cache-timing attacks; the flip count is the Hamming distance, the count of 1s the Hamming weight. Code that leaks nothing by time is constant-time; working on x ⊕ r is masking. Spectre and Meltdown (2018) abuse speculative execution.

Who said it first

Paul Kocher published timing attacks on RSA and similar systems in 1996, and with Joshua Jaffe and Benjamin Jun differential power analysis in 1999. Spectre was found in 2017 and announced in January 2018 by several teams, among them Jann Horn of Google and a group including Kocher.
