How Can a Scramble Be Undone With the Key?

How can a scramble be undone with the key? Every card payment and every locked phone runs its messages through a cipher that cuts them into blocks and scrambles each block, many times over. Each scramble must be undone by whoever holds the key, and look like noise to everyone else. Seen with rung 19’s eyes, a key picks a shuffle of all the blocks. This page builds a round that can be undone even when the scrambling inside it cannot, stacks rounds and undoes them in reverse, and shows why sending the same block twice the same way gives the game away.

A block of n bits is one of 2ⁿ blocks, and a cipher with a key is a shuffle of them. Split the block in halves; a round swaps the halves and adds a scramble of one half into the other. Adding the same thing twice gives back what you had, so the round undoes itself in reverse for any scramble. Compose rounds for spread, undo them in reverse order, and chain each block to the last so equal blocks look different.

20crypt21A Key Picks a Shuffle

Evita and Randy share a key. A message is cut into blocks of n bits each, and each block is sent scrambled. Scrambling must be undoable, so two blocks never scramble to the same one: for each key, the scramble is a shuffle of the 2n blocks, in 19a’s sense.

n = 4:\ 2^4 = 16 \text{ blocks} @@ a toy block
16! \approx 2.1 \times 10^{13} \text{ shuffles} @@ every order of the 16 (4k)
n = 128:\ (2^{128})! \text{ shuffles} @@ a real block
\htmlClass{new}{\text{a } 128\text{-bit key picks only } 2^{128} \text{ of them}} @@ a tiny share, which must look like any

A key cannot list its shuffle: the list for 128-bit blocks would be longer than the world could store. The cipher must build the shuffle from small steps that the key steers.

20crypt22Adding Bits, and a Round That Undoes Itself

From here on, on this page, to add two strings of bits is to add each place on its own, with 1 + 1 = 0 and no carry, written ⊕. So 01 ⊕ 11 = 10. Adding the same string twice gives back the first: u ⊕ s ⊕ s = u.

Split a block into a left half L and a right half R. A round with a scramble f does this: (L, R) ↦ (R, L ⊕ f(R)). The scramble f need not be undoable at all.

(L\prime, R\prime) = (R,\ L \oplus f(R)) @@ the round
R = L\prime @@ the right half is carried across
R\prime \oplus f(L\prime) = L \oplus f(R) \oplus f(R) = L @@ adding twice gives back
\htmlClass{new}{(L, R) = (R\prime \oplus f(L\prime),\ L\prime)} @@ the round, undone, for any f

Half-swap technique: a round that swaps the halves and adds a scramble of one into the other can be undone for any scramble, by running f forward again. The scramble can lose information freely; the round never does.

20crypt23Rounds Stacked, and Undone in Reverse

One round leaves the right half in plain view on the left. So the cipher runs many rounds, each with a scramble steered by its own piece of the key, k1, k2, …, kr.

E = \rho_r \cdots \rho_2 \rho_1 @@ a shuffle after a shuffle is a shuffle (19a)
E^{-1} = \rho_1^{-1} \rho_2^{-1} \cdots \rho_r^{-1} @@ the undress-in-reverse technique (19c)
\rho_i^{-1} \text{ uses the same } f_{k_i} @@ by the half-swap technique
\htmlClass{new}{\text{undo: the same rounds, keys in reverse order}} @@ one machine does both jobs

Stack technique: the rounds compose to a shuffle, and it is undone by the same kind of rounds with the key pieces taken in reverse order. The cipher of 1977 that guarded banks for twenty years ran 16 such rounds on 64-bit blocks.

20crypt24Every Bit Must Reach Every Bit

After one round the left half of the output is the old right half, untouched. Follow which input halves each output half depends on.

\text{round 1: } (R,\ L \oplus f(R)) @@ the left output knows only R
\text{round 2: } (L \oplus f(R),\ R \oplus f(\ldots)) @@ each half now knows both
\text{change one bit of } L @@ it reaches every bit only through f
\htmlClass{new}{\text{a good } f \text{ turns one bit into about half the bits}} @@ and more rounds give f more turns

Rounds are stacked until changing any one bit of the input or the key changes about half the output bits, by no pattern a stranger could follow. Short cuts in a cipher are found by tracking a change through too few rounds; designers add rounds well past the best such track known.

20crypt25The Same Block Twice

A shuffle sends a block to the same block every time. A picture whose plain blocks repeat, a white sky, comes out with the same scrambled block wherever the sky was, and the outline shows through. Chaining fixes it.

c_1 = E(p_1 \oplus v) @@ v a fresh random block, sent openly
c_i = E(p_i \oplus c_{i-1}) @@ add the last scrambled block first
p_i = E^{-1}(c_i) \oplus c_{i-1} @@ adding twice gives back
\htmlClass{new}{p_i = p_j \not\Rightarrow c_i = c_j} @@ equal blocks no longer look equal

A good shuffle is not yet a good cipher: how the blocks are fed to it decides what leaks. With a fresh v each time, even the same message sent twice looks different.

Accepted names

A cipher on blocks is a block cipher, and its shuffle for one key a keyed permutation. The half-swap round is a Feistel round, adding without carry is XOR, and the key pieces are round keys from a key schedule. One bit changing about half the output is the avalanche effect; tracking changes through rounds is differential cryptanalysis. Scrambling each block alone is ECB mode, and chaining is CBC mode, with v the initialisation vector.

Who said it first

Horst Feistel’s team at IBM built the half-swap rounds in the early 1970s; their design became the Data Encryption Standard in 1977, 16 rounds on 64-bit blocks. Its successor, chosen in 2000 and standardised in 2001, works on 128-bit blocks by a different kind of round.
