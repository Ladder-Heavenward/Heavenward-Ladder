A Machine That Follows a List

Rows of catches hold numbers, gates add them, and a clock tells everything when to move. Put many rows side by side, each with a number of its own to pick it out, and that is a memory. Add one more row that holds a place in the memory and goes up by one at each turn, a counter. Now let the numbers in the memory do two jobs. Some are data, numbers to add. Others are instructions: a number whose first digit says what to do, load, add, store, take away, jump, stop, and whose other digits say where. The machine’s whole life is one loop. Read the cell the counter points at. Move the counter on. Do what the number read says. Go round again. That is all a processor does, billions of times a second, and this step builds one with seven kinds of instruction, writes a program that multiplies by adding, and follows it turn by turn. Because the program is numbers in the same memory as the data, a program can be handed to the machine as data, and can even rewrite itself. The rung on what machines can compute makes this machine exact, as a tape and a head, and asks what no such machine can do.

A memory is many registers, each picked out by its number. An instruction is a number: what to do, and where. The machine fetches the number the counter points at, moves the counter on, and runs it, again and again. Its whole state is a number, and each turn is a function of it. A program is data too.

39j1An Instruction Is a Number

A memory is a list of registers, cell 0, cell 1, cell 2 and so on, each holding a number. Its address is its place in the list. Which cell to read is a table from the address bits to a choice of row, and 39f2 builds any table, so reading a cell by its number is a circuit. On this page cells hold numbers below 1000, written in tens for reading; inside they are in twos.

Instruction-number technique: a number of three digits, first digit d and last two digits n, is read as an instruction: d says what to do and n says which cell. The seven kinds on this machine, with A a register named the accumulator:

  • 0: stop.
  • 1n: load: A takes the number in cell n.
  • 2n: add: A takes A plus cell n.
  • 3n: store: cell n takes A.
  • 4n: take away: A takes A less cell n.
  • 5n: jump if zero: if A is 0, the counter takes n.
  • 6n: jump: the counter takes n.
290 = 2 \cdot 100 + 90 @@ the one split by 100 (4i7): d = 2, n = 90
d = 2:\ \text{add} @@ the list above
\htmlClass{new}{290:\ A \text{ takes } A + \text{cell } 90} \quad \blacksquare @@ one number, one instruction

Nothing in the cell marks 290 as an instruction. It is a number. Whether it is read as one depends on whether the counter points at it.

39j2Fetch, Move on, Run

Besides the memory, the machine has two registers: the counter C and the accumulator A. At each turn: fetch the number in cell C; set C to C + 1; then run the number fetched. Every register is a row of edge-catches (39h3), so each turn happens between two rises of the clock.

Fetch-run technique: the machine’s whole state, its counter, accumulator and memory, is one list of numbers, and each turn is a function from states to states; so a run is fixed by its first state.

s = (C, A, \text{cell } 0, \text{cell } 1, \ldots) @@ every catch of the machine, in a list
s' = F(s):\ \text{each new value a table of the old bits} @@ gates compute only tables of their inputs (39f2), and every catch takes its input at the rise
F \text{ gives one } s' \text{ for each } s @@ a function (9a)
s_0, \ F(s_0),\ F(F(s_0)), \ldots @@ the recursion technique (4d): a start and a step define one run
\htmlClass{new}{\text{same start, same run}} \quad \blacksquare @@ the run is a function of s₀

So a processor is 4d’s recursion built in silicon: a start and a step. It looks clever because F is big, a table of billions of inputs. It is never more than a table, applied again and again.

39j3A Program That Multiplies

Multiplying is repeated adding (4g). The program sits in cells 0 to 9; cell 90 holds x = 3, cell 91 holds the count k = 4, cell 92 the product, starting at 0, and cell 93 holds 1.

  • 0: 191, load the count.
  • 1: 509, if it is 0, jump to 9.
  • 2: 192, load the product.
  • 3: 290, add x.
  • 4: 392, store the product.
  • 5: 191, load the count.
  • 6: 493, take away 1.
  • 7: 391, store the count.
  • 8: 600, jump to 0.
  • 9: 000, stop.
\text{round } 1:\ \text{cells } 0 \text{ to } 8:\ \text{product } 3,\ \text{count } 3 @@ nine turns
\text{rounds } 2, 3, 4:\ \text{product } 6, 9, 12;\ \text{count } 2, 1, 0 @@ nine turns each
\text{then cells } 0, 1, 9:\ \text{count } 0,\ \text{jump},\ \text{stop} @@ three turns
\htmlClass{new}{\text{cell } 92 = 12 = 3 \cdot 4,\ \text{after } 9 \cdot 4 + 3 = 39 \text{ turns}} \quad \blacksquare @@ checked by running it

For a count k the program takes 9k + 3 turns: the price of each multiplication grows in proportion to the count. 39k makes that kind of count its subject. A better program halves the count and doubles x, as rung 4’s columns do in twos, and takes turns in proportion to the number of digits of k.

39j4A Program Is Data

Instructions and data sit in one memory and are both numbers. So a store can write a number where an instruction will be fetched.

Stored-list technique: since instructions are numbers in the cells data is stored in, one machine runs any program placed in its memory, and a program can change the instructions it will run next.

\text{cell } 3 \text{ holds } 290:\ \text{add cell } 90 @@ the program above
\text{a store } 3n \text{ with } A = 291 \text{ and } n = 3 @@ write 291 into cell 3
\text{the next fetch of cell } 3 \text{ adds cell } 91 @@ the instruction-number technique on the new number
\htmlClass{new}{\text{the program has rewritten itself}} \quad \blacksquare @@ the same machine, a different list

Every program a machine like this can follow is a list of numbers, so the programs can be listed, as 35a listed the lists. One machine with the right program can read another program as data and follow it step by step. 39’s tape machine makes this exact, with one head on one tape and no loose ends, and asks the question this step only points at: is there a program that reads any other program and says whether it will ever stop?

The accepted names

A machine that keeps its program and data in one memory is a stored-program computer, or von Neumann architecture. The counter is the program counter, the accumulator is A, and the loop is the fetch–decode–execute cycle. An instruction’s first digit is its opcode and the rest its operand. The machine on this page is close to the teaching machine called the Little Man Computer. A program that rewrites itself is self-modifying code.

Who said it first

Charles Babbage designed a machine that followed a list on punched cards in the 1830s, and Ada Lovelace wrote a program for it in 1843; her note that it “has no pretensions whatever to originate anything” is the first camp of 39j.6.4. Alan Turing’s machine of 1936 is 39’s tape machine, and his paper of 1950 answered her objection. John von Neumann’s report on the EDVAC (1945) set out the stored program; the Manchester Baby ran the first one on 21 June 1948. Stuart Madnick designed the Little Man Computer at MIT in 1965.

A proof that is not allowed

“The machine follows its program exactly, so whatever it does was in the program, so a human could have predicted it by reading the program.” Not allowed: the run is fixed by the start (fetch-run), but fixed is not foreseen. 39k counts how many turns a reader would need, and 39 shows there are questions about runs no reading of the program answers.
