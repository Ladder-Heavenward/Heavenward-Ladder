45f · proof

Commit Together or Not at All

One change touches several databases on several machines. Either every one of them makes it, or none does. This step builds the standard method, proves it safe, and shows where it gets stuck.

Ask everyone to promise; commit only if all promise. A machine that has promised must wait to be told.

45f1Ask, Then Tell

A coordinator asks every machine to prepare. Each votes yes, after writing the change where a crash cannot erase it, and promising to commit if told. Or it votes no. If every vote is yes, the coordinator decides commit, and otherwise it decides abort. Then it tells everyone.

Two-phase technique: no two machines finish differently, and the change is committed only if every machine voted yes.

Only the coordinator decides, and every machine does what it is told. The coordinator decides commit only after every yes has arrived.

45f2Waiting on a Dead Coordinator

A machine that voted yes and then hears nothing cannot decide alone. If it aborts, the coordinator may have decided commit. If it commits, another machine may have voted no. Its view is the same in both runs (45b2), so any choice is wrong in one of them. It must wait, and while it waits it holds the change locked.

45f3A Third Phase, and Its Price

A third phase tells everyone “all voted yes” before anyone commits, so no machine is ever one step from both outcomes. A machine left alone can then decide by timeout. But a timeout is safe only if delays are bounded (45b4). In the model without bounds, 45g shows that no method is safe and always finishes.

The accepted names

This is two-phase commit, and the third phase makes three-phase commit. A method that may wait for ever on one machine is blocking. “Never wrong” and “always finishes” are safety and liveness.
