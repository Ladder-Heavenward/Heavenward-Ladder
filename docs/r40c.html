40c · proof

A Name That Holds a Value

In a program a name holds a number, and the number changes. That is a new job for a name. It must be kept apart from 0a’s names, which name one thing all through an argument.

x ← x + 1 is a step, not a sameness. A program’s state is what its names hold now, and each step changes it.

40c1A Step, Not a Sameness

Write x ← e for the step “work out e with the values held now, then put the result in x”. As a statement, x = x + 1 is totally false for every whole number: no number is its own next (rung 4). As a step it is fine: x held 4, and now it holds 5.

Many languages write = for the step. That is the old trouble of 0b9’s jobs of “is”, one mark for two jobs, and the ladder keeps ← for the step.

40c2The State

The state of a program is the list of what each name holds, just as 39j2’s state was the list of every cell.

Assignment technique: the step x ← e changes x and nothing else, and the new value of x is the value e had before the step.

So a run is a row of states, each made from the one before by one step, and a trace table writes them out, one row per step.

40c3A Swap Needs a Third Box

To swap x and y, the steps x ← y; y ← x fail. After the first, both hold the old y, and the old x is gone. A third name t keeps it:

x = 3,\ y = 8 @@ the start
t \leftarrow x:\ t = 3 @@ t keeps the old x
x \leftarrow y:\ x = 8 @@ x takes the old y
y \leftarrow t:\ y = 3 @@ y takes the old x, from t
\htmlClass{new}{x = 8,\ y = 3} \quad \blacksquare @@ swapped

40c4Order Matters

x ← x + 1; y ← 2x and y ← 2x; x ← x + 1 leave different states: from x = 1, the first gives y = 4 and the second y = 2. Steps in a row do not turn about the way an and does (1c3). A step reads the state the step before it left.

The accepted names

A name that holds a changing value is a variable, the step is assignment, the list of values is the program’s state, and a row of steps is sequential composition.
