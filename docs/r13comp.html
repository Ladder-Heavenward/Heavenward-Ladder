13·comp · computing

How does a calculator find a root?

How does a calculator find a root? Press the square root key and ten digits appear at once. Ask a financial calculator what interest a loan charges, and it finds the root of an equation that no formula solves. Yet the machine knows nothing a person does not. It adds, multiplies, compares, and does it again. 12e's halving and 13m's tangent steps are recipes of exactly that kind. The trouble is that each has a flaw. Halving never fails, but it is slow. Tangent steps are fast, but they can fly off, or cycle for ever. And the machine cannot look at a picture to see which is happening. This page writes both as programs, counts what each step buys, and builds the program real calculators use: both at once.

Halving keeps a trap and buys one bit of the answer per step: each step halves the width of the trap. A tangent step walks down the tangent line from the guess to where the line is 0; near a zero where the slope is not 0, it doubles the correct places. Far from one it can fly off. A safe program keeps the trap, takes the tangent step when it lands inside, and halves whenever the trap has not halved. The trap still halves each round, and the end game is the tangent step's.

Programs

From here on, on this page, a program is a numbered list of instructions that a machine carries out in order. The machine has a few named boxes, each holding one number. An instruction may work out a value from the boxes, put it in a box, compare two values, or send the machine to another numbered instruction. The mark x ← v means: put the value v in the box named x, so that x names v from then on. The mark is an operator: a statement that, carried out, makes x name v. Going back to an earlier instruction is a loop. 12·comp's machine had no boxes at all, only states. A program with boxes can count.

A calculator's boxes hold numbers with a fixed count of digits. A pocket calculator keeps about ten significant digits. A computer's standard numbers keep 53 binary digits, about 16 decimal ones. So between 1 and 2 a machine holds only finitely many numbers, and the line it works on has holes. 12d showed what holes do: in-between-value can fail. A program must notice when its trap has closed on a hole.

The halving program

\text{1. } c \leftarrow p,\ \ d \leftarrow q @@ given: f(p) and f(q) of opposite signs, so [p, q] is a trap
\text{2. } m \leftarrow (c + d)/2 @@ the middle (8h)
\text{3. if } m = c \text{ or } m = d,\ \text{stop: report } [c, d] @@ no machine number between: the trap has closed on neighbours
\text{4. if } f(m) = 0,\ \text{stop: report } m @@ middle-of-a-trap: the middle is a zero
\text{5. if } f(m) \text{ has the sign of } f(c),\ c \leftarrow m;\ \text{otherwise } d \leftarrow m @@ middle-of-a-trap: keep the half that is still a trap
\text{6. go to 2} @@ the loop

By 12e's halvings-width, n passes leave a trap of width (q − p)/2ⁿ. Each pass decides one binary digit of where the zero is, as trap-from-its-bits says. Halving buys one bit of the answer per step, whatever the function, as long as it has a trap. Ten bits are about three decimal places, since 2¹⁰ = 1024 ≈ 10³.

2^{33} = 8\,589\,934\,592 \lt 10^{10} \le 2^{34} @@ 10 places of √2 from [1, 2] take 34 halvings (halvings-width)
\begin{aligned}&2^{52}:\ \text{the standard numbers}\\ &\quad\text{between } 1 \text{ and } 2 \text{ are spaced } 2^{-52}\end{aligned} @@ so halving [1, 2] stops at instruction 3 after 52 passes

The tangent program

\text{1. } x \leftarrow x_0 @@ a first guess
\text{2. if } f'(x) = 0,\ \text{stop: no step} @@ a level tangent line is never 0 (13m)
\text{3. } x \leftarrow x - f(x)/f'(x) @@ the tangent step N(x)
\begin{aligned}&\text{4. if } x \text{ stopped changing,}\\ &\quad\text{stop: report } x;\ \text{otherwise go to 2}\end{aligned} @@ the machine's numbers are finite: “stopped changing” is a test it can make

13m proved, for a polynomial, that once a guess is close enough each step about doubles the correct places. The same is held in trust here for every function this page uses, until 14c proves it in general. From 3/2, the tangent step finds 12 places of √2 in three steps, where halving takes 40. Halving adds places at a fixed pace; the tangent step multiplies them.

Many computer chips divide this way. To find 1/k, hunt the zero of f(x) = 1/x − k. Its tangent step needs no division at all, only multiplying and taking away.

Reciprocal-step technique: for f(x) = 1/x − k, the tangent step is x(2 − kx), and its new error is −k times the old error squared. Precisely: for k ≠ 0 and x = 1/k + e, with x ≠ 0, N(x) = x(2 − kx) = 1/k − ke².

f(x) = \tfrac1x - k,\ \ f'(x) = -\tfrac{1}{x^2} @@ slope-of-one-over-x (13a); a constant has slope 0
N(x) = x - \dfrac{1/x - k}{-1/x^2} = x + x^2\big(\tfrac1x - k\big) @@ the tangent step; dividing by −1/x² is multiplying by −x²
= \htmlClass{new}{x(2 - ax)} @@ spread and collect (5i): no division left
x = \tfrac1k + e:\ \ x(2 - ax) = \big(\tfrac1k + e\big)(1 - ae) @@ 2 − k(1/k + e) = 1 − ae
= \tfrac1k - e + e - ae^2 = \htmlClass{new}{\tfrac1k - ae^2} \quad \blacksquare @@ spread (5i)
  
x_0 = 0.1 @@ error about 0.043
x_1 = 0.1(2 - 0.7) = 0.13 @@ error 0.0129 = 7 · 0.043² (reciprocal-step)
x_2 = 0.1417,\ \ x_3 = 0.14284777,\ \ x_4 = 0.1428571422\cdots @@ errors about 0.0012, 0.0000094, 0.0000000006: the places double

Where each one fails

Halving needs a trap to start, and a function continuous on it. Handed x² on [−1, 1], it cannot start: both ends are positive, though 0 is a zero. Handed a function with a jump, it closes on the jump and reports a zero that is not there. But given a true trap, it never fails.

The tangent step needs nothing to start but a guess, and 13m showed three ways it can mislead. On x³ − 2x + 2 from 0 it goes 0, 1, 0, 1 for ever. On the cube root it doubles its distance at every step. Near a level tangent it lands far away. A machine running the tangent program alone cannot see any of this. It only sees numbers that keep changing.

The safe program: both at once

13m ended with the engineers' working rule: trap first, then sharpen. A program can do both at every round, and let the trap judge the tangent step. Start from a trap [p, q].

\text{1. } c \leftarrow p,\ \ d \leftarrow q @@ a trap
\text{2. } w \leftarrow d - c;\ \ x \leftarrow \text{the end of } [c, d] \text{ where } |f| \text{ is smaller} @@ the width now, and the best guess so far
\text{3. if } f'(x) \ne 0,\ t \leftarrow x - f(x)/f'(x);\ \text{if } c \lt t \lt d,\ \text{split the trap at } t @@ the tangent step, kept only if it lands strictly inside
\begin{aligned}&\text{4. otherwise split}\\ &\quad\text{the trap at its middle}\end{aligned} @@ the step flew off: halve instead
\text{5. if } d - c \gt w/2,\ \text{split the trap at its middle} @@ the round did not halve the trap: halve it once more
\begin{aligned}&\text{6. stop if the trap has closed on }\\ &\quad \text{neighbours, or } f \text{ is } 0 \text{ at a split; }\\ &\quad \text{otherwise go to 2}\end{aligned} @@ to split at s: if f(s) has the sign of f(c), c ← s; otherwise d ← s

Safe-step technique: the safe program's trap always holds a zero, and it at least halves every round. Precisely: if [p, q] is a trap and no split lands on a zero, then after n rounds [c, d] is a trap of width at most (q − p)/2ⁿ.

c \lt s \lt d,\ f(s) \ne 0 \Rightarrow [c, s] \text{ or } [s, d] \text{ is a trap} @@ middle-of-a-trap's argument, at any point strictly inside (12e: any split point inside a trap is licensed)
\text{each split keeps a trap} @@ the tangent split is made only when c < t < d; a middle is always strictly inside
\text{after a round, } d - c \le w/2 @@ either the round already halved it, or instruction 5 halves it (halvings-width, one step)
\text{after } n \text{ rounds},\ d - c \le \htmlClass{new}{(q - p)/2^n} \quad \blacksquare @@ induction on n (4c)

So the safe program is never slower than halving by more than a factor of two in tests of f. And once the best guess is close, the tangent steps take over, and the places double. The trap's far end may lag behind. The answer to report is the best guess x, with the trap as its guarantee.

x = 1:\ t = 1 - \tfrac{1}{1} = 0,\ f(0) = 2 \Rightarrow [-2, 0];\ \text{halve at } -1 \Rightarrow [-2, -1] @@ round 1: the step that cycled lands inside, but the trap did not halve
x = -2:\ t = -2 - \tfrac{-2}{10} = -1.8,\ f = -0.232 \Rightarrow [-1.8, -1];\ \text{halve} \Rightarrow [-1.8, -1.4] @@ round 2
x = -1.8:\ t \approx -1.7699482,\ f \approx -0.0049 @@ round 3: the trap becomes [−1.76995, −1.58497] after one more halving
t \approx -1.769292663,\ \ \text{then } \htmlClass{new}{-1.7692923542} @@ rounds 4 and 5: f about −0.0000023, then −0.0000000000005. The cycle never starts

The interest on a loan

A car loan of $20 000 is repaid in 60 monthly payments of $386.66. What does it charge each month? If the monthly rate is i, the lender's formula for the payment gives (1 + i)⁶⁰(20 000i − 386.66) + 386.66 = 0. That is a polynomial of degree 61, and no formula solves it. It also has the useless zero i = 0. Financial calculators have had a key for this since the 1970s.

f(0.001) \approx -2.66,\ \ f(0.02) \approx 430 @@ a trap that leaves out the zero at 0
x = 0.001:\ t \approx -0.00027 \notin [0.001, 0.02] @@ the tangent step heads for the useless zero; the trap refuses it: halve
\begin{aligned}&\text{rounds 3 to 6}:\ 0.0051039,\ 0.0050028,\\ &\quad \ 0.00500036,\ \htmlClass{new}{0.0050003557}\end{aligned} @@ tangent steps inside the trap, each kept
12 \times 0.50\% \approx 6.0\% \text{ a year} @@ the rate the lender quoted

Illegal moves

\begin{aligned}&\text{the tangent step is}\\ &\quad\text{faster, so use it alone}\,?\end{aligned} @@ on x³ − 2x + 2 from 0 it never arrives; the trap is what makes it safe
\begin{aligned}&\text{halving found a trap of width } 10^{-12},\\ &\quad \text{ so there is a zero in it}\,?\end{aligned} @@ only if f is continuous there; on a jump the traps close on no zero
\text{keep halving until the width is } 0\,? @@ the machine's numbers have holes; stop when the middle is an end
\begin{aligned}&\text{the guesses stopped changing, so } f(x)\\ &\quad = 0\,?\end{aligned} @@ the machine's f(x) is rounded too; report the trap
f(m) \text{ has the sign of } f(d) \Rightarrow d \leftarrow m,\ \text{then } c \leftarrow m\,? @@ one box changes per split: the half kept must still be a trap

Running it backwards

Handed a final trap and the first one, read off how many halvings were run, and each choice, by trap-from-its-bits. Handed a step x ← x(2 − kx), find what it hunts: its fixed points are 0 and 1/k. Handed the number of places wanted, count the halvings by halvings-width, then count the tangent steps by doubling.

Who said it first

Programs that keep a trap and take a faster step inside it are T. J. Dekker's (1969) and Richard Brent's (1973). William Kahan built one into the SOLVE key of a pocket calculator, the HP-34C, in 1979; it took steps along chords, a cousin of the tangent step that needs no slope. The standard binary numbers of computers, with 53 binary digits, were fixed in 1985 by a standard Kahan led. The mathematician of 13·comp.4.4 is Thomas Nicely, who met the error while summing reciprocals of primes; the chip was Intel's Pentium, whose division used a table with five missing entries, not tangent steps.

Kahan explains that a root-finder on a calculator must never give up silently: when it cannot find a zero it should say so, and say what it found instead.

William Kahan, “Personal calculator has key to solve any equation f(x) = 0”, Hewlett-Packard Journal (December 1979); paraphrase

Accepted names

The halving program is the bisection method; the tangent program is Newton's method, or the Newton–Raphson method. A program that keeps a trap and steps inside it is a safeguarded or hybrid method; the best known is Brent's method. The machine's numbers are floating-point numbers, and the gap after 1 is the machine epsilon. A box is a variable, and x ← v is an assignment.

Wrong moves, worked

\text{each tangent step lands inside the trap} @@ not allowed: on x³ − 2x + 2 from 0 the step goes to 1, outside [−2, −1]
\text{so the safe program never needs to halve} @@ false: instruction 4 is what catches the fly-off
\text{so it is always as fast as the tangent step} @@ false: far from the zero it can be as slow as halving
