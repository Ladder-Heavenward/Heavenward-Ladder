What Does It Mean for a Cipher to Be Secure?

What does it mean for a cipher to be secure? For two thousand years ciphers were called strong until someone broke them. In 1982 Shafi Goldwasser and Silvio Micali said exactly what secure should mean: no quick attacker can learn even one bit about the message, beyond what it could guess. They put the definition as a game, and proved schemes secure by reduction, rung 41’s tool: any attacker that wins the game could be turned into a solver of a problem believed hard. This page sets the game, measures how well an attacker plays, finds the one cipher that wins perfectly and its price, shows why a cipher that always gives the same box for the same message loses, and builds the reduction.

The attacker picks two messages; the referee locks one, chosen by a coin; the attacker guesses which. Its advantage is how far its chance of winning sits above ½. Secure means every quick attacker has a tiny advantage. The one-time pad has advantage 0 but needs a key as long as the message. Locking the same message twice the same way loses the game, so locking must use fresh chance. To prove a scheme secure, turn any winner into a solver of a hard problem.

41crypt1A Game for Secrecy

Mike plays against a referee who holds a key Mike never sees. Mike may ask the referee to lock any messages he likes.

\text{Mike picks two messages } m_0, m_1 \text{ of the same length} @@ any two he likes
\text{the referee flips a coin } b \text{ and locks } m_b @@ Mike sees only the locked box
\text{Mike guesses } b @@ wins if right
\htmlClass{new}{\text{secure: no quick Mike wins much more than half the time}} @@ he learns nothing he could use

From here on, on this page, a quick attacker is one whose running time grows no faster than a polynomial in the key’s length, as 41h counted time.

41crypt2Measuring an Attacker

\text{advantage} = \big|P(\text{Mike wins}) - \tfrac12\big| @@ above a coin toss
\text{guessing blindly: } 0 @@ a coin wins half
\text{if the box shows the first bit: pick } m_0, m_1 \text{ differing there; advantage } \tfrac12 @@ one bit is enough to lose
\htmlClass{new}{\text{secure: advantage below } 2^{-80} \text{ for every quick Mike}} @@ tiny, say, for a key of 128 bits

Security-game technique: a scheme is secure when every quick attacker’s chance of telling which of two chosen messages was locked sits only a tiny amount above one half. Because Mike chooses the messages, a scheme that leaks any one bit of every message loses.

41crypt3The Pad Wins Perfectly

c = m \oplus k,\ k \text{ uniform, as long as } m @@ each key bit a fair coin
P(c \mid m_0) = P(c \mid m_1) = 2^{-n} @@ every box equally likely, whatever the message
\text{advantage} = 0 \text{ for every Mike, however slow} @@ perfect secrecy
\htmlClass{new}{\text{perfect secrecy needs at least as many keys as messages}} @@ Shannon, 1949

Shannon showed perfect secrecy costs a fresh key as long as all the messages ever sent. Practical ciphers settle for secrecy against quick attackers, with short keys, and that needs problems believed hard.

41crypt4Same Message, Same Box

Suppose locking is a fixed function: the same message under the same key always gives the same box. Mike may ask the referee to lock messages before he picks.

\text{ask the referee to lock } m_0;\ \text{get } c_0 @@ allowed in the game
\text{pick } m_0, m_1;\ \text{get box } c @@ the challenge
c = c_0 \Rightarrow \text{guess } 0;\ \text{else guess } 1 @@ always right
\htmlClass{new}{\text{advantage } \tfrac12:\ \text{fixed locking is never secure}} @@ it shows when a message repeats

A secure cipher must lock the same message differently each time, by mixing in fresh chance. That is why 20·crypt2’s chained mode starts each message with a random block.

41crypt5Proof by Reduction

A scheme S is built on a problem H believed hard. To prove S secure, Evita shows how any Mike who wins S’s game could be used to solve H, as 41k turned one problem into another.

\text{given Mike with advantage } \varepsilon \text{ against } S @@ suppose a winner
\text{build } R:\ \text{play the referee for Mike, using a copy of } H @@ Mike cannot tell
R \text{ solves } H \text{ with advantage } \approx \varepsilon,\ \text{in about Mike’s time} @@ his win becomes R’s solve
\htmlClass{new}{H \text{ hard} \Rightarrow \text{no quick Mike has more than tiny } \varepsilon} @@ by contraposition

A proof of security says: any quick attacker on the scheme would give a quick solver of a hard problem. It does not say H is hard; that stays a belief, the same as 41·now2’s question of whether checking is easier than finding.

41crypt6Moves to Watch Out For

Each line below is a move that looks right and is not. The tag says what kind of mistake it is; the words say which footing catches it.

\text{secure means the key cannot be found}\,? @@ <span class="vd vd-c">outside the collect</span> a scheme can hide its key and leak a bit of every message (41crypt2)
\text{advantage} = P(\text{Mike wins})\,? @@ <span class="vd vd-l">legal, with a cost</span> a coin wins half; advantage is the excess over ½ (41crypt2)
\text{lock each message the same way, for speed}\,? @@ <span class="vd vd-p">outside the plan</span> Mike locks m₀ first and wins every time (41crypt4)
\text{a winner against } H \text{ gives a winner against } S\,? @@ <span class="vd vd-a">out of arrangement</span> the reduction runs the other way: a winner against S solves H (41crypt5)
\text{the reduction proves } H \text{ hard}\,? @@ <span class="vd vd-s">out of sequence</span> it assumes H hard and concludes S secure (41crypt5)

Accepted names

The game is indistinguishability: with locking on request, IND-CPA (chosen-plaintext attack). Its goal is semantic security; locking with fresh chance is probabilistic encryption. A tiny advantage is negligible; the proof is a security reduction and the believed-hard problem a hardness assumption.

Who said it first

Claude Shannon proved perfect secrecy needs keys as long as messages in 1949. Shafi Goldwasser and Silvio Micali defined semantic security and probabilistic encryption in 1982, published 1984, and won the Turing Award for 2012.
