39q · technique

Counting Steps by Hand

A program on a page is a set of loops and calls, and its count can be read off before it is ever run. This step does that by hand, four ways. Loops inside loops whose inner count depends on the outer one are a sum, and the sums of the counting rung finish them. A loop that halves its counter, or doubles it, runs about as many times as the log of its bound, and the floor of that log can be pinned exactly. A program that calls itself gives a rule for its own count, one term for each call, and the last steps of this rung solve the rule. And at the end the family is read off by keeping the term that grows fastest, which is honest only past the size where that term takes over, so the step finds that size too.

Loops in loops are sums over the outer counter. A halving or doubling loop runs about the log of its bound. A program that calls itself writes its own rule. Keep the fastest-growing term for the family, and say from which size on it rules.

39q1Loops Inside Loops

A loop over i from 1 to n, with a loop over j from 1 to i inside, runs its inner body once for each pair j ≤ i. Count the inner rounds as a sum over the outer counter.

Nested-loop technique: the inner body of loops nested as i from 1 to n, j from 1 to i, runs n(n + 1)/2 times; with a third loop, l from 1 to j, it runs n(n + 1)(n + 2)/6 times.

\textstyle\sum_{i=1}^{n} i = \tfrac{n(n + 1)}{2} @@ 4k’s sum
\textstyle\sum_{i=1}^{n}\sum_{j=1}^{i} j = \sum_{i=1}^{n} \tfrac{i(i + 1)}{2} @@ the inner two loops, for each i
= \tbinom{n + 2}{3} = \tfrac{n(n + 1)(n + 2)}{6} @@ the triangle of choices (4k): each run is a choice of l ≤ j ≤ i from n values, repeats allowed
\htmlClass{new}{n = 10:\ \ 55 \text{ and } 220} \quad \blacksquare @@ checked by running the loops

39q2Loops That Halve or Double

A loop that sets k to the whole part of k/2 each round, while k > 1, or one that doubles i from 1 while i ≤ n, does not run n times. It runs about as many times as n can be halved.

Halving-loop technique: halving k to its whole part while k > 1 runs ⌊log₂ k⌋ rounds; doubling i from 1 while i ≤ n runs ⌊log₂ n⌋ + 1 rounds.

2^j \le n < 2^{j+1},\ \ j = \lfloor \log_2 n \rfloor @@ name the place of n among the powers of 2
i = 1, 2, 4, \ldots, 2^j \le n,\ \ 2^{j+1} > n @@ the doubling loop’s values
\text{rounds} = j + 1 @@ count 2⁰ to 2ʲ
n = 1000:\ \ 2^9 = 512 \le 1000 < 1024 @@ j = 9
\htmlClass{new}{10 \text{ doubling rounds},\ 9 \text{ halving rounds}} \quad \blacksquare @@ 1000 → 500 → 250 → 125 → 62 → 31 → 15 → 7 → 3 → 1

A halving loop inside a loop over n items costs n(⌊log₂ n⌋ + 1), the family n log n. A loop that goes up by adding 1 to i and stops at i² > n runs about √n times: what changes the counter decides the family.

39q3Programs That Call Themselves

A program that calls itself writes the rule for its own count: one term for each call it makes, at the size it calls with, plus the turns of its own loops.

Call-tree technique: if a program on size n calls itself on sizes n₁, …, n_a and spends f(n) turns of its own, its count obeys T(n) = T(n₁) + ⋯ + T(n_a) + f(n), and 39m and 22l2 solve the common shapes.

\text{halves, two calls, a loop over } n:\ T(n) = 2T(n/2) + n @@ merge sort’s shape: n log₂ n (22l1)
\text{one call on } n - 1, \text{ a loop over } n:\ T(n) = T(n - 1) + n @@ the shrink-by-one technique: about n²/2
\text{three calls on halves, a loop over } n:\ T(n) = 3T(n/2) + n @@ the master technique, r = 3/2: the bottom wins
\htmlClass{new}{n\log_2 n,\ \ \tfrac12 n^2,\ \ n^{\log_2 3} \approx n^{1.585}} \quad \blacksquare @@ 22l2’s third case

The calls draw a tree: the first call at the top, its calls below it, theirs below them. The count is the sum of the work at every place of the tree, which is why 22l2 adds the levels and 39m3 guesses and checks.

39q4Keep the Largest Term

A count read by hand is often a sum of terms of different families. The family is that of the fastest-growing term, ranked by 22k2. What that hides is where the fast term takes over.

Largest-term technique: a sum of finitely many terms is in the family of the term of highest rank; and the hand count should say the size past which that term is the largest.

T(n) = 3n^2 + 100\,n\log_2 n + 10^6 @@ a count read off a program
\tfrac{100\,n\log_2 n}{3n^2} \to 0,\ \ \tfrac{10^6}{3n^2} \to 0 @@ the ranking technique (22k2)
T(n) = O(n^2) @@ each lower term is at most 3n² past some size
3n^2 > 100\,n\log_2 n \text{ from } n = 270;\ \ 3n^2 > 10^6 \text{ from } n = 578 @@ found by machine
\htmlClass{new}{\text{below about } 600 \text{ items, the } 10^6 \text{ start-up rules}} \quad \blacksquare @@ the family speaks only for large n

The accepted names

Reading counts off loops is the analysis of algorithms by summation; halving and doubling loops are logarithmic loops. A program that calls itself is recursive, its count a recurrence, and its calls a recursion tree. Keeping the largest term is asymptotic analysis, and the size past which it rules is where the asymptotic regime begins; below it, constant factors and lower-order terms decide. The crosswalk items here are AP Computer Science A 2.11 and 2.12 (nested iteration, informal run-time analysis) and AP Computer Science Principles 3.17.

Who said it first

Donald Knuth made the counting of a program’s steps by sums and recurrences a discipline in The Art of Computer Programming (from 1968) and Concrete Mathematics (1989, with Ronald Graham and Oren Patashnik).

A proof that is not allowed

“The program has two loops, one inside the other, each up to n, so its count is n², and it is in the same family as a program with one loop up to n².” Not allowed as a reading of programs, though right in its last part: the inner loop may stop early, halve, or double, and only the sum of its rounds counts. Two nested loops are a sum to work out, not a family to guess.
