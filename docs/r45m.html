45m · proof

Splitting a Big Job

A job too big for one machine is cut into pieces for many. This step says when the pieces may be cut any way at all, what limits the gain, and how to use machines you do not trust.

Work on each piece apart, then combine. If combining ignores grouping, any split gives the same answer; the part that must run in a row sets the limit.

45m1Map, Then Combine

Apply f to each piece on its own machine, then combine the results with ⊕.

Split-combine technique: if ⊕ is associative, every way of grouping the pieces among machines gives the same answer; if it is also commutative, every order does too.

This is 44a’s laws once more: with grouping free, a long ⊕ needs no brackets, so a tree of machines may combine pairs in any shape. Subtracting is not associative, so it cannot be split freely.

45m2The Part That Will Not Split

If a fraction s of the work must be done in a row, n machines take at least s + (1 − s)/n of the time one machine takes. So the speedup is at most 1/(s + (1 − s)/n), which stays below 1/s however many machines are added (17·comp).

45m3Machines That Talk While Working

Some jobs cannot be cut clean: each piece of a weather map needs its neighbours’ edges each step. Machines then trade edges every round. The work grows with a piece’s area and the talk with its edge, so larger pieces waste less time talking, until there are too few pieces to share.

45m4Volunteers You Cannot Trust

Machines lent by strangers may return wrong answers, by fault or on purpose. Send each piece to two or more of them, and accept an answer only when they agree. A cheat is caught unless paired with another cheat giving the same wrong answer.

The accepted names

Map then combine is MapReduce, whose free tool is Hadoop. The limit of 45m2 is Amdahl’s law. Machines trading messages as they work use message passing, MPI. Lending home computers to science is volunteer computing, as BOINC organises it.
