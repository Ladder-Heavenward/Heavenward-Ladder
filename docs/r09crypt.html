9·crypt · cryptography

Can a code be truly unbreakable?

Can a code be truly unbreakable? People have hidden messages for as long as they have written them. For as long, other people have read what was hidden. Many ciphers were called unbreakable, and nearly all of them were broken, usually by a patient reader with tallies and a good guess. So the question sounds like a boast. It is hard because "unbreakable" has to mean something exact. It cannot mean "nobody has broken it yet". It has to mean that the secret text, on its own, tells a reader nothing about the message. This page builds a cipher that meets that demand, from 4·comp's exclusive or. It proves that a key used once hides everything but the length. Then it shows how a key used twice gives both messages away, as it did to real spies in the 1940s.

Write the message in bits, and a key of bits as long as it, chosen by coin tosses. The secret text is the message and the key joined by exclusive or, place by place, and the same joining with the same key runs it back. Used once, every message of that length fits the secret text with exactly one key. Used twice, the key cancels, and the two secret texts joined give the two messages joined.

What this stands on, and where it goes

Stands on 4h (numerals in twos, bits), 4·comp (⊕, the marks technique, checking a sameness row by row), 4j (the counted-functions technique: 2ⁿ lists of n bits), 4·crypt (a key, and trying every key), 9b (composing, the identity), 9c (one-to-one, onto, bijection), 9d (there-and-back, running-backwards). Ciphers, keys and secret text

A cipher is a pair of rules. One turns a message into secret text with the help of a key; the other turns the secret text back into the message, with the same key. The message is called the plain text, and the secret text the cipher text. Turning plain text into cipher text is encrypting; turning it back is decrypting. 4·crypt's shift was a cipher: its key was how far to count on, and there were only 25 keys worth trying. An attacker tried them all.

From here on, on this page, m names a message, k a key and c a cipher text, each a list of bits. A letter is written as its place in the alphabet, counting from A = 0 to Z = 25, in five bits (4h's numerals in twos): A is 00000, B is 00001, L is 01011, Z is 11001.

A list of n bits is a function from n to 2 = {0, 1}: it gives each place 0, 1, …, n − 1 a bit. By 4j's counted-functions technique there are 2ⁿ of them. A word of four letters is 20 bits, and there are 2²⁰ = 1 048 576 lists of 20 bits.

Exclusive or, place by place

From here on, on this page, for lists m and k of n bits, m ⊕ k names the list of n bits whose bit at each place i is m(i) ⊕ k(i). 4·comp's ⊕ joined two single marks, 1 when exactly one of them is 1. Here it joins two lists of the same length, one place at a time. On lists of one bit it is the old ⊕.

Four facts about single bits, each checked on its rows, as 4·comp checked its samenesses. Write 0 here for a list of zeros.

A \oplus 0 = A @@ rows A = 0, 1: 0 ⊕ 0 = 0, 1 ⊕ 0 = 1
A \oplus A = \htmlClass{new}{0} @@ rows: 0 ⊕ 0 = 0, 1 ⊕ 1 = 0. Exactly one of A and A is never 1
A \oplus B = B \oplus A @@ four rows; "exactly one of" does not care about order
(A \oplus B) \oplus C = A \oplus (B \oplus C) @@ eight rows: each side is 1 exactly when an odd number of A, B, C are 1

Each fact is true at every place, so it is true for lists of bits, place by place. That is all the algebra the pad needs.

The pad

From here on, on this page, for a key k of n bits, E_k names the function from lists of n bits to lists of n bits given by E_k(m) = m ⊕ k. Encrypting is E_k. The cipher that uses it, with a key as long as the message and used for one message only, is the pad.

Own-way-back technique: E_k ∘ E_k = id: the same key, used the same way, undoes itself.

(E_k \circ E_k)(m) = (m \oplus k) \oplus k @@ 9b's composing, inside first
= m \oplus \htmlClass{new}{(k \oplus k)} @@ regroup (the eight-row fact)
= m \oplus 0 = \htmlClass{keep}{m} \quad \blacksquare @@ A ⊕ A = 0 at every place, then A ⊕ 0 = A

So E_k undoes E_k on both sides. By 9d's running-backwards technique it is a bijection, and its inverse is itself: E_k⁻¹ = E_k. It joins 9f's undo list beside −x and 1/x, the functions that undo themselves. Decrypting is the same machine as encrypting. The teleprinter cipher of 1917 used one and the same circuit for both.

m = \text{LODI} = 01011\ 01110\ 00011\ 01000 @@ L = 11, O = 14, D = 3, I = 8, in fives
k = 10110\ 00111\ 11001\ 01101 @@ twenty coin tosses, heads 1
c = m \oplus k = \htmlClass{new}{11101\ 01001\ 11010\ 00101} @@ place by place. 11101 is 29 and 11010 is 26: no letter. The cipher text is bits, not letters
c \oplus k = 01011\ 01110\ 00011\ 01000 = \htmlClass{keep}{\text{LODI}} @@ own-way-back

Why the pad hides everything

An attacker has c and not k. She can do what 4·crypt's attacker did: try every key. Here is what she gets.

One-key-each technique: for each message m and each cipher text c of the same length, exactly one key sends m to c, namely k = m ⊕ c.

E_{m \oplus c}(m) = m \oplus (m \oplus c) = (m \oplus m) \oplus c = 0 \oplus c = c @@ some key works: regroup, A ⊕ A = 0, A ⊕ 0 = A (and turn the order)
m \oplus k = c \Rightarrow m \oplus (m \oplus k) = m \oplus c @@ only one key: ⊕ m on both sides (substitute for the expression)
\Rightarrow \htmlClass{new}{k = m \oplus c} \quad \blacksquare @@ the left side is k, by the first line's techs

Read it as a function. Fix the cipher text c. The rule k ↦ k ⊕ c sends each key to the message it decrypts c into. It is E_c, so it undoes itself, so it is a bijection from the keys onto the messages of length n. Trying every key lists every message of that length, each exactly once. For LODI's cipher text, the key 10011 01001 10000 10111 gives OAKS, and 10001 01001 10110 00101 gives MAMA. Nothing in the list points at LODI.

That is the exact sense of "hides everything". It needs the key to have been picked with no pattern an attacker could guess: coin tosses, not a phrase from a book. Then the attacker has no reason to prefer one key, and so none to prefer one message. The cipher text says how long the message is, and nothing else.

Why the key must be as long as the message

Short-key technique: if the keys are fewer than the messages, some cipher text rules some message out. Suppose the keys have r bits, with r < n, and each is stretched to n bits by a fixed rule, say by repeating it. Fix a cipher text c. The messages that fit c are the outputs of k ↦ (k stretched) ⊕ c, one for each key. So there are at most 2ʳ of them (each fitting message is counted by at least one key). There are 2ⁿ messages, and 2ʳ < 2ⁿ. So some message of length n fits no key at all. ∎ The attacker learns something: that message was not sent. With a short repeated key she learns far more than that, as later cryptography pages show.

So the price of the pad is its key. Every bit ever sent costs a bit of key, made in advance, carried to the other side, and burned after one use.

Anexact, yet rigorous · connections, not families

"A random key" is a family name. It says how the key was made, and every key of the family looks alike to that name. The one-key-each technique says nothing about families. It is about what the key does: k ↦ k ⊕ c matches the keys with the messages, one each. A key from coin tosses and a key copied from the digits of a phone book can be the same list of bits. Then E_k is the same function, and it hides the same message the same way.

Judge a key by what it does to the messages it meets, and by what else it is connected to.

The phone book key is connected to a phone book an attacker can also open. The pad used twice is connected to a second message. The family name of the key hides both connections. The function hides neither.

Two keys are the same list of bits. One came from coin tosses and one from the phone book. Is one of them safer?

The pad used twice

Key-cancels technique: if one key encrypts two messages, the two cipher texts together give m₁ ⊕ m₂, and the key is gone.

c_1 \oplus c_2 = (m_1 \oplus k) \oplus (m_2 \oplus k) @@ the same k twice
= m_1 \oplus m_2 \oplus \htmlClass{new}{(k \oplus k)} @@ turn the order and regroup
= \htmlClass{keep}{m_1 \oplus m_2} \quad \blacksquare @@ A ⊕ A = 0, A ⊕ 0 = A

Now the attacker does not need the key. She guesses a word that is likely somewhere in one message: an opening like MEET, a place name, a date. Put it at a place in m₁ and ⊕ it with m₁ ⊕ m₂ there. Out comes m₂ at that place, by own-way-back. If the guess and its place are right, m₂ reads as words. If not, it reads as nonsense, or gives groups of five bits that are no letter. A guessed word is called a crib.

m_1 \oplus m_2 = 01011\ 01010\ 01111\ 10000\ \cdots @@ from the two cipher texts; the key never appears
\text{crib MEET at place } 0:\ \ 01011 \oplus 01100 = 00111 = \text{H},\ \ldots @@ M = 12; then E, E, T in turn
\Rightarrow m_2 \text{ begins } \htmlClass{new}{\text{HOLD}} @@ a word: the guess is kept
\text{crib MEET at place } 1:\ \text{G, L, U, A} @@ GLUA: nonsense, so that place is dropped

Each correct guess in one message gives letters of the other, which suggest new guesses. The whole of both messages can come out this way, and then the key too: k = m₁ ⊕ c₁, by one-key-each. In 1942, under the pressure of war, a Soviet office printed some pages of its pads twice. American codebreakers found the repeats, and over the following decades read parts of thousands of messages. They named spies who had never been suspected.

Two pads in a row are one pad: E_j ∘ E_k = E_{k ⊕ j}, by regroup. So encrypting twice with two keys is no stronger than once, and a key used twice is not rescued by a second key used twice.

Illegal moves

c \text{ looks like noise, so any key is safe}\,? @@ a key from a guessable source fails, however the output looks: the attacker tries the guessable keys first
\text{a key of } 8 \text{ bits, repeated, is a pad}\,? @@ short-key: 2⁸ keys cannot fit 2ⁿ messages; most messages are ruled out
E_k(E_j(m)) \text{ is safer than } E_k(m)\,? @@ E_k ∘ E_j = E_{j ⊕ k}: one pad with key j ⊕ k
c_1 \oplus c_2 \text{ is noise, since each } c \text{ is}\,? @@ key-cancels: it is m₁ ⊕ m₂, and words in one give words in the other
m \text{ AND } k \text{ as a cipher}\,? @@ AND is not one-to-one in m: where k(i) = 0 every message gives 0, and nothing can run it back

Running it backwards

Handed m and c, the key is m ⊕ c (one-key-each). Handed c and k, the message is c ⊕ k (own-way-back). Handed two cipher texts under one key, ⊕ them and drag a crib along (key-cancels). Handed a wish, a cipher that hides everything, pay its price: a key from coin tosses, as long as the message, used once.

Who said it first

Gilbert Vernam, an engineer at AT&T, built the teleprinter cipher of 1917 that adds a key tape to the message tape bit by bit, in the five-hole teleprinter code. Joseph Mauborgne of the United States Army saw that the key tape must be random and never reused. A banker, Frank Miller, had printed the same idea for telegraph codes in 1882; Steven Bellovin found his book in 2011. Claude Shannon proved during the war, and published in 1949, that the pad hides everything and that no cipher can do so with fewer keys than messages. The pages printed twice were Soviet; the American project that read them, begun at Arlington Hall in 1943, was later called Venona, and Meredith Gardner was its first great reader.

Shannon showed that perfect secrecy is possible, and that it requires a key at least as long as the message, if the key is not to be used again.

Claude Shannon, “Communication Theory of Secrecy Systems”, Bell System Technical Journal 28 (1949); paraphrase

Accepted names: the pad is the one-time pad, or the Vernam cipher. Plain text and cipher text are written plaintext and ciphertext. ⊕ on bits is XOR. Hiding everything, in the sense of one-key-each with keys chosen without pattern, is perfect secrecy. A key used twice gives a two-time pad, and dragging a guessed word along m₁ ⊕ m₂ is crib dragging.
