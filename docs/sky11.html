How Much Memory Does a Question Need?

Step 40h counted the steps a machine takes and found that more time answers more questions. It also counted room, the cells of tape a machine writes on, and found that room can be reused where time cannot. This page counts room alone, and counts it small. A machine that only reads its input and writes on a tape as short as the number of digits in the input’s length can still do a great deal: it can count, compare, and walk a map one dot at a time. Such machines are always fast. Whether every fast question can be answered by one is open. Between the two sits a class that was expected to behave like the certificate class of 40h, and in 1987 it did not: two people, working apart, showed that a guessing machine in this little room can prove that there is no path from one dot to another as easily as that there is one. The proof counts. Then in 2025 a result about room and time moved a bound that had stood since the 1970s, and the field is still arguing about how far it goes.

A machine in room c log₂ n has a power of n configurations, so it is fast. More room decides more, by the diagonal, with a counter to catch loops. Reaching one dot from another needs room about (log₂ N)² without guessing and log₂ N with it. Counting the dots reached, layer by layer, lets a guessing machine in log room certify that a dot is not reached. Evaluating a list of not-and gates is fast and holds every fast question, so log room equals fast exactly when that list can be evaluated in log room.

sky11.1Room Smaller Than the Input

Room as 40h5 counted it includes the input, so no machine uses less than n cells. To count smaller, give the machine two tapes: the input, which it may read and never write, and a work tape. Its room is now the work cells it uses. A machine is in log room when its room is at most c · log₂ n for a fixed c. A count from 0 to n written in twos fits: for an input of a billion letters, 30 cells. So deciding whether a string of brackets balances, by 40h1’s walk with a counter, is in log room.

Few-configurations technique: a machine in log room, on an input of length n, stops within a power of n steps or never; so every set decided in log room is fast.

\text{a configuration: the state, where the input head is, where the work head is, and the work cells} @@ the input never changes, so it is not part of it
q \cdot (n + 2) \cdot s \cdot m^s \text{ configurations, with } s = c \log_2 n @@ q states, m marks, the ends of the input marked
m^s = 2^{c \log_2 n \cdot \log_2 m} = n^{c \log_2 m} @@ a power of n
\text{a run longer than the count repeats a configuration and never stops} @@ the bounded-room technique (40g4), with the input head as one more counter
\htmlClass{new}{\text{log room} \subseteq P} \quad \blacksquare @@ a power of n times n times log n is within a power of n

With q = 10, m = 2, c = 2 and n = 1000 the count is 10 · 1002 · 20 · 2²⁰, about 2 × 10¹¹: large, and a power of n. The sets decided in log room have the accepted name L. Fast, by this footing. Whether every fast set is in L is the question this page ends on.

sky11.2More Room Decides More

The more-time technique of 40h4 ran the universal machine with a counter and said the opposite. For room the same diagonal works, with one difference. A machine can loop forever inside its room, so the simulation needs a second counter that stops a run once it is longer than the count of configurations.

More-room technique: if s(n) ≥ log₂ n can be marked off in room s(n), and r(n)/s(n) shrinks to 0, then some set is decided in room about s(n) and by no machine in room r(n).

D\text{: on } \langle M\rangle \# 0^m \text{ of length } n\text{, mark off } s(n) \text{ cells, and a counter of } 2s(n) \text{ cells} @@ D’s room is about 3 s(n)
\text{run U on } \langle M\rangle \# \langle M\rangle \# 0^m \text{ inside the cells, counting steps} @@ stop if U leaves them or the counter runs out
\text{if U shows that } M \text{ said yes, say no; otherwise say yes} @@ the opposite, as in 40d2
M \text{ decides } D\text{’s set in room } r(n) @@ suppose it
U \text{ needs } c_M r(n) \lt s(n) \text{ cells, and } M \text{ has fewer than } 2^{2s(n)} \text{ configurations, once } n \text{ is large} @@ the padding makes n large; the count is q(n + 2) r m^r
\text{on that input } D \text{ sees } M\text{’s answer and says the opposite} @@ M and D disagree
\htmlClass{new}{\bot} \quad \blacksquare @@ refute

With s = (log₂ n)² and r = log₂ n: some set is decided in room (log₂ n)² and not in L. With s = n: some set is in PSPACE and not in L. Room, unlike time, loses nothing to the simulation but the fixed factor c_M, and the two counters are all the diagonal needs.

sky11.3A Path in Squared Room

Take a graph of N dots with one-way links (41f), given as the input, and two dots u and v. Is there a path from u to v? The layer-by-layer technique of 41k1 answers fast, and it keeps a mark for every dot reached: N cells. The halving-room technique of 40h5 answers in less room. The difference here is only the reading: a state of 40h5 is now a dot, written in log₂ N cells.

Squared-room-path technique: whether there is a path from u to v in a graph of N dots is decided in room about 3(log₂ N)², and by a guessing machine in room about 2 log₂ N. A guessing machine may have several next configurations at a step, and says yes when some run says yes; every run must stay in its room. The sets decided by guessing machines in log room have the accepted name NL.

\text{layer by layer: one mark per dot} @@ 2²⁰ = 1 048 576 cells
\text{halving: } 20 \text{ levels, each keeping } u, v, w \text{ of } 20 \text{ cells} @@ 3 × 20 × 20 = 1200 cells, and about 2⁴²⁰ steps
\text{guessing: keep the dot reached and a count of steps, guess the next link, check it on the input} @@ 20 + 20 = 40 cells
\text{yes when the dot reached is } v\text{; give up when the count passes } N @@ a path need not be longer than N − 1 links
\htmlClass{new}{\text{room } 1200 \text{ without guessing, } 40 \text{ with it}} \quad \blacksquare @@ the squared-room-path technique

The guessing machine finds a path when there is one. When there is none, every run gives up, and no run says so with a yes. To say “no path” with a yes, a guessing machine would have to be sure it had looked everywhere, in 40 cells, among a million dots. The next two footings do it.

sky11.4A Count Certifies a No

Suppose the guessing machine were told one number: c, the count of dots reachable from u. Then it could certify that v is not reachable. It walks through the dots w = 1, 2, …, N in order. For each it guesses whether w is reachable; if it guesses yes, it guesses a path from u to w and checks every link; if that w is v, it gives up. It counts the dots it has checked.

Count-certifies-no technique: a run that ends with its count equal to c has found every reachable dot, so if v was not among them, v is not reachable; and when v is not reachable, some run ends that way; the room is a few dot names, about 4 log₂ N cells. No run can check a path to a dot that is not reachable, so a run that counts c has missed none.

c = 4 @@ the reachable dots are 1, 2, 3, 4
\text{guess yes for } 1, 2, 3, 4\text{: paths } 1;\ 1 \to 2;\ 1 \to 2 \to 3;\ 1 \to 2 \to 4 @@ each link checked on the input
\text{guess no for } 5, 6\text{; count } 4 = c @@ this run says: 5 is not reachable
\text{a run that guesses no for } 4 \text{ counts } 3 \ne 4 @@ it gives up; and no run checks a path to 5 or 6
\htmlClass{new}{\text{no path from 1 to 5, certified in a few names}} \quad \blacksquare @@ the count-certifies-no technique

The room holds w, the count so far, the dot on the guessed path and the length of that path: four names. The machine never keeps the list of dots it found, only how many. Everything now rests on getting c.

sky11.5Counting the Count

Let cₖ be the count of dots reachable from u in at most k links. Then c₀ = 1, the dot u, and the count wanted is c_(N−1). The same trick, one layer at a time, gets each count from the one before.

Count-the-count technique: a guessing machine in room about 8 log₂ N, told cₖ, computes cₖ₊₁: every run either gives up or ends with the right count, and some run ends. For each dot v it walks through every w, guessing and checking paths of at most k links to the w within reach, as the last footing did. If the count of checked w is not cₖ, it gives up. Otherwise v is within k + 1 exactly when some checked w is v or has a link to v.

\text{within 1 link of 1: } \{1, 2\},\ c_1 = 2 @@ given
v = 3:\ \ w = 2 \text{ checked, and } 2 \to 3 @@ 3 is within 2
v = 5:\ \ \text{checked } w \text{: } 1, 2;\ \text{count } 2 = c_1;\ \text{neither is } 5 \text{ nor links to } 5 @@ 5 is not within 2, certified
v = 1, 2, 4 \text{ yes};\ \ v = 6 \text{ no} @@ the same walk for each
\htmlClass{new}{c_2 = 4} \quad \blacksquare @@ the count-the-count technique; c₃ = c₄ = c₅ = 4

Run it for k = 0, 1, …, N − 2, keeping only the last count, then use the count-certifies-no technique. So “no path” is decided by a guessing machine in log room, and by the same argument, for any room s(n) ≥ log₂ n, when a guessing machine decides a set in room s, another decides the strings outside it in room about s. The certificate class of 40h is not known to behave like this.

sky11.6Log Room Against Fast

A guessing machine in log room has a power of n configurations (sky11.1), and they make a graph of one-way links. It says yes when the yes configuration is reachable, which 41k1 decides fast. So the order is: log room, inside guessing log room, inside fast, inside PSPACE. The more-room technique puts PSPACE beyond log room, so at least one of the three steps is strict. Nobody knows which.

Gate-evaluation technique: evaluating a list of not-and gates, each fed by fixed 0s and 1s or by gates earlier in the list, is fast, and every fast set reduces to it by a function computed in log room; so L = P exactly when such lists can be evaluated in log room.

\text{evaluate the gates in order, each from two values already found} @@ one pass: fast
M \text{ decides } A \text{ within } t = n^k \text{ steps: its run is a table of } t \times t \text{ cells} @@ the tableau of 40h3
\text{each cell is fixed by the three above it, by a fixed table} @@ the one-next technique, as 40h3 used it
\text{that table, in not-and gates, written for each cell } (i, j) @@ 39f: every table from one gate
\text{row 0 is } x\text{: no free cells, so no certificate} @@ the difference from 40h3
\htmlClass{new}{\text{the list is written with counters } i, j \text{ only: log room}} \quad \blacksquare @@ x is in A exactly when the last row’s gate for the yes state gives 1

For t = n², the list has about n⁴ cells times a fixed number of gates. The last step, that a log-room evaluator joined to a log-room writer is a log-room machine, recomputes each gate of the list whenever it is needed instead of storing it; it is held in trust here. Evaluating a list of gates is the hardest fast question for log room, as satisfiability is for the certificate class.

Open questions · nobody has the answer yet

Open questions

These are open: the field is still asking them. There is no key; a good attempt is a reason, a guess, or a better question.

∞11.oq.1Is every fast question answered in log room? By the gate-evaluation technique this asks whether a list of not-and gates can be evaluated with a work tape of about log₂ n cells. The evaluator in one pass keeps every value. Nobody has found a way that keeps fewer than a power of n of them, in general, and nobody has proved there is none.
∞11.oq.2Does guessing help in log room? Finding a path along one-way links is the hardest question for guessing log room. Without guessing, the best known room has been about (log₂ N)² since 1970. For links that go both ways, a method in log room alone was found in 2005. Can the one-way case be done in log room, or even in room (log₂ N)^1.5?
∞11.oq.3Which step is strict? L ⊆ NL ⊆ P ⊆ PSPACE, and the more-room technique shows L ≠ PSPACE, so at least one of the three steps is strict. Most expect all three are. Not one of them has been proved.
∞11.oq.4How little room does time need? Since the 1970s a machine running t steps could be redone in room about t / log₂ t. In 2025 this came down to about √(t log₂ t). Can it come down to t^0.1, for every t? If it came down to a power of log₂ t, then every fast set would be decided in room a power of log₂ n, and the more-room technique would put PSPACE beyond it: P ≠ PSPACE. How far it can go is open.
∞11.oq.5Is evaluating a tree of tables in log room? Fill the leaves of a full tree of height h with numbers from 1 to k, and let each inner point apply a given table to its two children. Computing the root was proposed around 2010 as a way to separate L from P, on the expectation that it needs room about h log₂ k. In 2023 it was done in room about (h + log₂ k) · log₂ log₂ k, far below that expectation. Whether it is in log room is open.
A short history · told from more than one side

How we got here

Room was counted as soon as time was. In 1965 a group at General Electric’s research laboratory in New York State proved that more room decides more, by the diagonal of this page. A year before, a question had been asked about machines confined to the cells of their own input, guessing ones among them: do the sets they decide stay decided under not? It stayed open for 23 years.

In 1970 the halving-room technique showed that guessing costs at most a square in room. Many had expected far more, as guessing seemed to cost a doubling in time. Whether the square is needed has never been settled. In 1975 the path question was shown to hold all of guessing log room, and by analogy with the certificate class most expected that “no path” could not be decided by guessing in log room.

In 1987 the analogy broke. A student in Bratislava, then in Czechoslovakia, and a researcher in the United States, working apart, found the counting argument of this page; it also settled the 1964 question, yes. The two shared a prize in 1995. Some read it as a warning that time and room do not mirror each other. Others read it as a sign that a short idea can still settle a question that nearly everyone had guessed wrong.

The both-ways path question came next. In 1979 a random walk with coins was shown to find paths in log room. In 2005 a researcher at the Weizmann Institute removed the coins. Many now expect that coins never help in log room; that is still unproved.

Around 2010 a problem of evaluating trees of tables was proposed as a road to proving L ≠ P, with evidence that the natural methods for it need much more than log room. In 2023 two researchers went around those methods, reusing cells that already held data, an idea from 2014 called catalytic computing. In 2025 a researcher at MIT used their method to show that t steps can be redone in room about √(t log₂ t), the first large move since the 1970s on that question.

What is argued now: whether the 2025 result is a step toward separating P from PSPACE, or shows that the walls between time and room are lower than believed and that the separations will be harder than hoped. The fact that it came from a method many had thought was blocked is cited on both sides.

The accepted names

The machine with a read-only input tape and a work tape is the offline Turing machine of space complexity. The log-room sets are L (LOGSPACE), and those of guessing machines are NL. The more-room technique is the space hierarchy theorem. The path question along one-way links is STCON (directed reachability), NL-complete under log-space reductions; the squared-room-path technique is Savitch’s theorem for it. The count-certifies-no and count-the-count techniques are inductive counting, and the result NL = coNL, with NSPACE(s) = coNSPACE(s) for s ≥ log n, is the Immerman–Szelepcsényi theorem. Evaluating a list of gates is the circuit value problem, P-complete under log-space reductions. The both-ways case is USTCON, in L by Reingold’s theorem. The 1964 question is the second LBA problem. The tree problem is tree evaluation, and the 2025 result is TIME[t] ⊆ SPACE[√(t log t)].

Who said it first

Richard Stearns, Juris Hartmanis and Philip Lewis proved the space hierarchy in 1965. S.-Y. Kuroda posed the LBA problems in 1964. Walter Savitch proved the halving result in 1970. Neil Jones (1975) showed directed reachability NL-complete, and Richard Ladner (1975) showed circuit value P-complete. Neil Immerman and Róbert Szelepcsényi proved NL = coNL independently in 1987 and shared the Gödel Prize in 1995. Romas Aleliunas, Richard Karp, Richard Lipton, László Lovász and Charles Rackoff gave the random walk in 1979; Omer Reingold derandomized it in 2005. John Hopcroft, Wolfgang Paul and Leslie Valiant gave the t / log t bound in 1975. Stephen Cook, Pierre McKenzie, Dustin Wehr, Mark Braverman and Rahul Santhanam proposed tree evaluation; Harry Buhrman, Richard Cleve, Michal Koucký, Bruno Loff and Florian Speelman introduced catalytic computing in 2014; James Cook and Ian Mertz put tree evaluation in space O(log n · log log n) in 2023; Ryan Williams proved the square-root simulation in 2025.

A proof that is not allowed

“A guessing machine that says no path guesses where a path might go and finds none, so it decides no path.” Not allowed: a run that finds none says nothing, since another run might have found one. A yes must come from a run that is sure, and the only sureness here is the count: a run that has checked c dots, when c dots are reachable, has seen them all.
