How Does a Machine Search for a Plan?

How does a machine search for a plan? A robot finding a way across a warehouse, a phone finding a route home, and a program solving a sliding-tile puzzle all search a graph: each state is a dot, each move a link, and a plan is a path. The graph is usually too big to draw. Blind search grows like the number of moves to the power of the plan’s length; a good guess of the distance left cuts it down, and a guess that never overstates still finds the shortest plan. Against an opponent, search alternates best and worst. This page builds search on 42m’s shortest paths and 42h’s games.

Search grows like bᵈ. A* expands the dot with the least g + h, the cost so far plus a guess of the cost left; if h never overstates, the first time the goal is taken out, its path is shortest. Against an opponent, take the best of the opponent’s worst replies, and skip any branch already shown no better than one in hand.

42comp1Plans as Paths

Jean’s puzzle has eight numbered tiles in a 3 × 3 frame and one empty square. A move slides a tile into the empty square. The goal is the tiles in order.

\text{dot} = \text{an arrangement of the tiles} @@ a state
\text{link} = \text{one slide} @@ a move, cost 1
\tfrac{9!}{2} = 181\,440 \text{ reachable arrangements} @@ half of all, by 19’s parity of shuffles
\htmlClass{new}{\text{a plan} = \text{a path from start to goal}} @@ the best plan, the shortest path (42m)

From here on, on this page, to expand a dot is to list the dots one move away.

42comp2Blind Search Grows Fast

b \text{ moves from each dot, plan of length } d @@ b the branching
\text{dots within } d \text{ moves} \approx b^d @@ the counting principle (4·stat)
\text{puzzle: } b \approx 2.7,\ d \approx 22:\ 2.7^{22} \approx 3 \times 10^{9} @@ the frame caps it at 181 440
\htmlClass{new}{\text{the 15-tile puzzle: } 10^{13} \text{ arrangements}} @@ blind search cannot keep up

Searching outward in rings from the start, as 42m does, finds the shortest plan, but the rings swell like bᵈ. Search needs a sense of direction.

42comp3A Guess of the Distance Left

g(n) = \text{moves so far to } n @@ known
h(n) = \text{a guess of moves left} @@ cheap to work out
\text{expand the dot with the least } g + h @@ the most promising plan
\htmlClass{new}{h = \text{the sum of each tile’s rows and columns from home}} @@ for the puzzle

Each slide moves one tile one square, so it lowers that sum by at most 1. Expanding the dot with the least cost so far plus guessed cost left heads the search toward the goal. With h = 0 this is 42m’s shortest-path search again.

42comp4A Guess That Never Overstates

Say h never overstates the true cost left: h(n) ≤ the shortest distance from n to the goal. Then A* finds a shortest plan.

\text{suppose the goal is taken out by a path of cost } C > C^* @@ C* the shortest cost; for contradiction
\text{some dot } n \text{ on a shortest path still waits:}\ g(n) + h(n) \le C^* @@ h never overstates
g(n) + h(n) \le C^* < C @@ so n was more promising
\htmlClass{new}{\text{A* would have taken out } n \text{ first: contradiction}} @@ so C = C*

A* technique: if the guess of the cost left never overstates it, the first plan A* finishes is a shortest one. The closer the guess to the truth, the fewer dots it expands: for the puzzle, the sum of distances expands thousands of times fewer than blind search.

42comp5Searching Against an Opponent

In a game the other side moves too. 42h’s games are solved backward: Jean takes the best move, assuming the opponent then takes the move worst for her.

\text{value}(n) = \max_{\text{my moves}} \min_{\text{replies}} \text{value} @@ minimax
\text{a branch already worse than one in hand: skip its other replies} @@ it will not be chosen
\text{well ordered: about } b^{d/2} \text{ dots, not } b^d @@ twice the depth in the same time
\htmlClass{new}{\text{too deep: stop and score the board by a guess}} @@ as A* guessed the distance

Against an opponent, search takes the best of the opponent’s worst replies, and a branch shown no better than one in hand need not be finished. Chess programs searched this way until 2017, when programs that learn their guesses from self-play overtook them.

42comp6Moves to Watch Out For

Each line below is a move that looks right and is not. The tag says what kind of mistake it is; the words say which footing catches it.

\text{use the straight count of misplaced tiles times two}\,? @@ <span class="vd vd-l">legal, with a cost</span> it can overstate, and then A* may miss the shortest plan (42comp4)
\text{expand the dot with the least } h \text{ alone}\,? @@ <span class="vd vd-c">outside the collect</span> without g the search may follow a long path; least g + h (42comp3)
\text{the guess must equal the true cost left}\,? @@ <span class="vd vd-p">outside the plan</span> it need only never overstate (42comp4)
\text{take my best move, then the opponent’s best reply for me}\,? @@ <span class="vd vd-a">out of arrangement</span> the opponent picks the reply worst for me: max of min (42comp5)
\text{search all } b^d \text{ dots against an opponent}\,? @@ <span class="vd vd-s">out of sequence</span> skip branches already worse; about b^{d/2} (42comp5)

Accepted names

Search outward in rings is breadth-first search; the method of 42comp3 is A* search, a never-overstating guess an admissible heuristic, the sum of distances the Manhattan distance. Best of worst is minimax; skipping branches is alpha-beta pruning; the board guess an evaluation function. The puzzle is the 8-puzzle.

Who said it first

Peter Hart, Nils Nilsson and Bertram Raphael published A* in 1968, for the robot Shakey at the Stanford Research Institute. Knuth and Moore analysed alpha-beta in 1975. AlphaZero, which learned chess by self-play, beat the program Stockfish in 2017.
