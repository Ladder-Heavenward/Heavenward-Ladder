What Do Switches, Hubs and Routers Do?

The links of 46b are made of boxes that pass messages along. This annex says what three kinds of box do, and why each was needed, from rung 42’s graphs and 46d’s handshake.

A hub repeats to everyone, a switch learns where each address lives, and a router chooses a path between networks.

46eng1A Hub Repeats

A hub copies every signal it gets to every other port. All the machines on it share one wire, and two that send at once garble each other. Each must notice the clash and try again after a random wait, as 46d resends.

46eng2A Switch Learns

Learning-switch technique: a switch that writes down the port each sender’s address arrived on sends every later message for that address only out of that port.

Until it has seen an address, it sends that message to every port, as a hub would. Once it has, the message goes one way, and other ports are free for other talk at the same time.

Switches joined in a loop would pass a message to everyone round and round for ever. So they agree on a tree (42b) through the links and switch off the rest, since a tree has exactly one path between any two points.

46eng3A Router Finds Paths

A router joins networks, and picks for each message the next router on a shortest path, by the methods of 42m. Routers trade what they know of the map, so each learns the paths without a central list.

The layers then stack: the link moves bits between neighbours, the internet layer carries numbered messages from network to network with no promise of arrival, and the transport layer adds 46d’s handshakes and resends on top.

46eng5Data in Flight, and a Busy Switch

Networks pass messages hop by hop. Two numbers set how fast a long link can really go: how much data must be on its way, sent but not yet confirmed, to keep it full; and how long a message waits at each switch, which grows sharply as the switch gets busy.

10^9 \times 0.08 = 8 \times 10^7 \text{ bits} = 10 \text{ MB in flight} @@ send less before waiting for word back, and the link idles
\text{busy share } \rho:\ \text{average wait} = \dfrac{t_0}{1 - \rho} @@ arrivals at random (30o)
\rho = 0.5:\ 2t_0;\ \ \rho = 0.9:\ 10t_0;\ \ \rho = 0.99:\ 100t_0 @@ 
\htmlClass{new}{\text{a switch kept 90\% busy makes each message wait ten times its own time}} @@ why links are run well below full

Flight-and-queue technique: keep the link’s speed times its round-trip time in flight to fill it, and keep switches well below full, since waiting grows as one over one less the busy share. Shown on a network: pings timed to each router along a path add up hop by hop to the full round trip, and at a busy hour the extra delay piles up at the one crowded link.

The accepted names

The link layer is usually Ethernet. The loop-breaking tree is built by the spanning tree protocol. The internet layer is IP, and the transport layer is TCP, together TCP/IP. Routers trade maps by link-state or distance-vector routing.
