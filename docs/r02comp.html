What Does a Computer Check When It Reads "if"?

What does a computer check when it reads "if"? Every program that makes a choice makes it with an if. A sprinkler opens when the soil is dry. A gate lifts when the toll is paid. The words after the if are a condition. The machine has to find out whether the condition is true before it acts. That sounds like the work of this rung, and it is. What makes it hard is that a machine reads one piece at a time. Some pieces cost something to read. Reading one can take time, or ask a driver for money, or look for a boat that is not there. So the order of the pieces matters to the machine, even where it does not matter to the statement. This page shows that a condition is a statement the machine settles by reading. It shows that an and with a false left side, and an or with a true left side, are fixed whatever their right side is. It shows what a machine that reads the left side first, and stops as soon as the answer is fixed, can do that the turned-about condition cannot. And it ends with the part after the then, which is not a statement at all.

A computer reading an if checks only the condition. It reads the left side first. When the left side of an and is false, or the left side of an or is true, it stops there, since the right side cannot change the answer. So the left side can guard the right side: put on the left the check that makes the right side safe to read. Then the machine does the then part, which is a thing to do, not a thing to check.

2comp1A Condition Is a Statement

A program is a list of instructions that a machine carries out in order. An instruction that begins with if tells the machine to check something first. The words between the if and the then are the condition.

2comp2Left First, and Stopping Early

A machine does not see a whole statement at once. It reads one piece, then the next. Most programming languages fix the order: the left side of an and, or of an or, is read first. Sometimes the left side settles the whole.

Look at 1e2’s and machine. In the rows FT and FF the and is F. The left side is F in both rows, and the right side differs. So once the left side is F, the right side cannot change the answer. The or machine is the same the other way about. In the rows TT and TF the or is T, whatever the right side is.

The techs of 1b and 1c say the same in one line, with no table. A line holds ¬P beside P ∧ Q. Keep left, and the line holds ¬P and P: a clash, so the line equals ⊥. Whatever Q is, an and with a false left side cannot stand in a line beside that falsehood. The or part is shorter. From P, add an option gives P ∨ Q, for any Q at all.

Stop-early technique: an and whose left side is false is false, and an or whose left side is true is true, whatever the right side is. A line that holds ¬P and P ∧ Q equals ⊥. From P, you may write P ∨ Q. From ¬P, add an option to get ¬P ∨ ¬Q, and 1f3’s not-through for and, read leftward, writes it as ¬(P ∧ Q). The machine never needs that line, since it needs only the row.

A machine that reads left first can use the technique every time, and most do. It saves work. In the orchard, when the soil is wet, the controller never reads the forecast.

2comp3A Right Side That Names Nothing

On the car ferry from Seattle to Bainbridge Island, a ramp joins the dock to the boat’s car deck. A program at the dock tells the cars to roll. Let F be “a ferry is in the slip”. Let L be “the ferry in the slip has its car deck level with the ramp”. The program reads: if F ∧ L, wave the cars on.

When no ferry is in the slip, “the ferry in the slip” names nothing. Then L is not a statement about anything, and it has no row. A machine told to read L looks for a sensor on a boat that is not there. Real machines then stop with an error.

Read left first, F ∧ L is safe. When F is F, the stop-early technique fixes the answer at F, and the machine never reads L. The left side guards the right side.

Now turn it about. 1c3’s technique gives L ∧ F from F ∧ L, and the two have the same column wherever both are statements. But a machine reading L ∧ F reads L first. With the slip empty, it reads a line that names nothing, and fails. When the right side can name nothing, put on its left the check that makes it name something.

The turn-about technique is about statements, and it stays true. It never said which side a machine reads first. The order of reading belongs to the program, not to the statement.

2comp4A Right Side That Does Something

Eastbound over the Tacoma Narrows Bridge, every car pays a toll. A car with a Good To Go pass pays by the pass. Other drivers pay at a booth. Picture a gate whose program reads: if G ∨ B, lift the gate. Let G be “the car carries a Good To Go pass”. Let B be “the driver pays at the booth”.

Reading B is not just looking. To read B, the machine asks the driver to pay, and waits. Read left first, G ∨ B asks only drivers with no pass. When G is T, the stop-early technique fixes the or at T, and B is never read.

Turned about, B ∨ G reads B first. It asks every driver to pay, pass or no pass. 1c10’s technique gives B ∨ G from G ∨ B, with the same column. Yet on the bridge they make different days: one of them charges a pass holder at the booth as well. When reading a part does something, the order of reading decides who it is done to.

2comp5The Then Part Is Not Checked

So far the page has looked at the condition. Now the rest of the instruction: if D ∧ ¬R, open the valve. “Open the valve” is not a statement. It is not true or false. It is a command, a thing to do.

Compare 1d’s if. Let V be “the valve is open”. Then (D ∧ ¬R) ⇒ V is a statement. It is true in every row where D ∧ ¬R is false, as 1e’s if machine shows. The program does nothing in those rows. It skips the command and leaves the valve as it was.

The machine reads the condition. When the condition is T, the machine does the command. When it is F, the machine skips the command. A program’s if checks only its condition; the then part is done or skipped, never checked.

There is a link all the same. Once the instruction has run, (D ∧ ¬R) ⇒ V is true in every row. In a row where the condition is F, the if machine makes it true. In a row where the condition is T, the machine has just opened the valve, so V is T. Running the instruction makes 1d’s if true. It never checks it.

Accepted names

A condition is a Boolean expression, after George Boole. Stopping early is short-circuit evaluation, and an and or an or that does it is a short-circuit operator, written && and || in C and the languages that copied it. A left side that makes the right side safe to read is a guard. Reading a part that does something on the way is a side effect. An instruction “if C, do A” is a conditional statement; with an otherwise part it is an if-then-else. A name that names nothing, read by a machine, is a null reference.

Who said it first

George Boole (1854) wrote logic as an algebra of marks, and Claude Shannon (1937) showed that circuits of switches work it out. John McCarthy (1960) defined and and or for the language Lisp by conditional expressions, which stop early. The ALGOL 60 report and Pascal (1970) left the order of reading to each machine. C (1972) fixed it: left first, and stop early. Ada (1983) keeps both words: its and may read both sides, and its and then stops early. Those languages are the two sides of 2·comp.7.5. Tony Hoare brought in the null reference in 1965, and in 2009 he called it his billion-dollar mistake.
