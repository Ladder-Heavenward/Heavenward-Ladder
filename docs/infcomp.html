What Do a Program’s Arrows Hide?

What do a program’s arrows hide? Five computing annexes, from rung 2 to rung 17, each reached a result by looking inside a machine: at the order in which it reads, at its loops, its gates, its states, its comparisons. This page reads the five again with rung forty-seven’s arrows. Each time, the result turns out to rest on a plan that arrows carry, and the insides can hide. An if that stops early is a row of arrows that can fail. The checker that cannot exist is one fixed-point argument. An adder is boxes in a row and side by side. The fewest states a pattern needs is the size of an image. And every way of sorting is one and the same map, read through different brackets.

A check is an arrow that passes or fails, and reading “P and Q” left first is the row q ⋆ p; the row exists one way round only when q can be read only where p passed. No checker of stopping: the fixed-point technique with B = {stops, runs on}. Circuits are arrows between numbers of wires; the adder for n bits is (FA ⊕ 1) ∘ (1 ⊕ Rₙ₋₁). A machine with no memory has at least as many states as its language has leftovers. Sorting is the one map s with s([a]) = [a] and s(x ++ y) = merge(s(x), s(y)); the bracketing changes only the cost.

infcomp.1An If Is a Row That Can Stop

At the ferry dock of 2·comp3 a program read “if F ∧ L, wave the cars on”, with F “a ferry is in the slip” and L “the ferry in the slip has its car deck level with the ramp”. Read left first it was safe. Turned about, L ∧ F, it failed with the slip empty, though the two statements have one column. 2·comp said that the order of reading belongs to the program, not to the statement. Arrows say what kind of thing the program then is.

Let U be the situations the program can be in. A check P that can be read everywhere in U gives an arrow p : U → T(UP), where T is the maybe wrapper of ∞3 and UP is the part of U where P holds: p passes a situation along when P holds there, and fails when it does not. A check Q that can be read only where P holds gives q : UP → T(UPQ).

Guard-row technique: the row q ⋆ p : U → T(UPQ) passes a situation exactly when P holds there and Q holds there, and it never reads Q where P fails. When q can be fed only from UP, there is no row p ⋆ q.

(q \star p)(w) = \text{failed} \iff p(w) = \text{failed, or } p(w) = w \text{ and } q(w) = \text{failed} @@ the maybe-row technique (∞3)
p(w) = \text{failed} \iff P \text{ is false at } w,\ \text{and then } q \text{ is not run} @@ how p was made; the row stops at the first failure
q \star p \text{ passes } w \iff P \text{ and } Q \text{ both hold at } w @@ the two lines above
q \star p:\quad U \xrightarrow{\ p\ } T(U_P),\quad U_P \xrightarrow{\ q\ } T(U_{PQ}) @@ the ends meet at U_P, so the row is made (47a1, ∞3)
\htmlClass{new}{p \star q:\quad U \xrightarrow{\ q\ }\ ?\qquad q \text{ takes } U_P,\ \text{not } U} \quad \blacksquare @@ the ends do not meet: no such row

So the ferry program is the row l ⋆ f, and its turned-about form is not a slower or a riskier row. It is no row at all. The turn-about technique of 1c3 is true of the things: the part of U where F and L hold is the part where L and F hold. It was never a claim about rows, and ⋆ has no turn-about.

What hides is the sequence. 2·comp had to follow the machine piece by piece to see why left comes first. Here the order is in the row itself, and ∞3’s third rule adds that a chain of guards needs no brackets: (r ⋆ q) ⋆ p = r ⋆ (q ⋆ p). At the toll gate of 2·comp4, reading B made a driver pay. That check is an arrow in ∞3’s state wrapper, and there both rows exist, g then b and b then g, and they are two different arrows.

infcomp.2The Checker That Cannot Exist

3·comp5 sketched why no program can read every program and always tell whether it stops, and held the full argument in trust. It settled three loops first, each by an argument made for that loop. The sketch used none of them. ∞1 shows why: the argument is about naming, and loops do not come into it.

A = \text{the texts of programs},\qquad B = \{\text{stops},\ \text{runs on}\} @@ a program is fed a text, and a program has a text
\varphi : A \times A \to B,\quad \varphi(p, t) = \text{what program } p \text{ does, fed the text } t @@ each program p names the function φ(p, −)
\text{a checker would make } g(t) = \text{the opposite of } \varphi(t, t) \text{ a program’s behaviour} @@ 3·comp5’s program that asks about itself and does the opposite
\text{then } \varphi \text{ names } g,\ \text{and “opposite” has a fixed point} @@ the fixed-point technique (∞1), as at inf1.5
\htmlClass{new}{\text{opposite}(\text{stops}) = \text{runs on},\ \ \text{opposite}(\text{runs on}) = \text{stops}:\ \text{no fixed point}} \quad \blacksquare @@ so no checker

What hides is the arrangement: what a program is made of. The lines never ask whether a program has loops, or what language it is written in. They need two things only. Programs can be fed their own texts, so one set A serves as both the names and the inputs. And there is a function from B to B with no fixed point. The same four lines, with another A and B, are 2e14’s outsider set and 38k2’s truth that cannot be defined.

infcomp.3An Adder Is Boxes in a Row

4·comp built an adder from switches. Take as things the whole numbers 0, 1, 2, …, read as numbers of wires, and as arrows from m to n the tables that give n bits out for each m bits in. Running one circuit into the next is the row ∘, and setting two circuits side by side is ⊕, as in 47·eng. Write 1ₖ for k wires left alone. An arrow here is its table. Two circuits with one table are the same arrow, whatever gates are inside them.

The two-bit adder of 4·comp4 is HA : 2 → 2, sending (A, B) to (carry, sum). 4·comp5 made the full adder from two of them and an OR. As arrows that is one line: FA = (OR ⊕ 1₁) ∘ (1₁ ⊕ HA) ∘ (HA ⊕ 1₁), an arrow 3 → 2 sending (A, B, Cin) to (Cout, S). Let R₁ = FA, and for n above 1 let Rₙ = (FA ⊕ 1ₙ₋₁) ∘ (1₂ ⊕ Rₙ₋₁), an arrow from 2n + 1 wires to n + 1.

Ripple-row technique: Rₙ adds two numbers of n bits and a carry: fed (aₙ₋₁, bₙ₋₁, …, a₀, b₀, c), it gives the n + 1 bits of a + b + c. Any box with the table of FA may stand in for FA, and Rₙ is the same arrow.

\varphi(n):\ R_n \text{ gives bits } (c_n, s_{n-1}, \dots, s_0) \text{ with } a + b + c = 2^n c_n + \textstyle\sum 2^k s_k @@ the claim, for whole n ≥ 1
\varphi(1):\ a_0 + b_0 + c = 2c_1 + s_0 @@ the full-adder technique (4·comp5)
1_2 \oplus R_{n-1}:\ \text{the low } n - 1 \text{ places give } (c_{n-1}, s_{n-2}, \dots, s_0) @@ φ(n − 1); the top two wires wait
FA \oplus 1_{n-1}:\ a_{n-1} + b_{n-1} + c_{n-1} = 2c_n + s_{n-1} @@ the full adder on the top place and the carry that arrived
a + b + c = 2^{n-1}(a_{n-1} + b_{n-1} + c_{n-1}) + \textstyle\sum_{k \lt n-1} 2^k s_k = 2^n c_n + \sum_{k \lt n} 2^k s_k @@ put the two together
\htmlClass{new}{\forall n\ \varphi(n)} \quad \blacksquare @@ induction (4c); ∘ and ⊕ are functions of the arrows, so a box with the same table gives the same Rₙ

What hides is the arrangement inside each box. 4·comp7 showed that one gate is enough. In arrows: every table is a composite, by ∘ and ⊕, of NAND : 2 → 1, plain wires, a crossing of two wires, and a wire that forks, 1 → 2. The fork is a box too. NOT is NAND ∘ fork, one wire fed to both inputs. The ripple, that the twos place cannot finish before the ones place, does not hide: it is the order of the row.

infcomp.4The Fewest States a Pattern Needs

12·comp7 proved that no machine with no memory checks the strings aⁿbⁿ, by feeding a machine of q states q + 1 strings and catching two in one state. It also built machines: three states for the remainder by 3, and k + 2 states for brackets nested up to k deep. It did not ask whether those machines are the smallest. ∞7 answers all three at once. For a language L and a string u, the leftover of L after u is the set of strings w with uw in L: what may still follow.

Leftover-count technique: a machine with no memory that checks L has at least as many states as L has different leftovers. So a language with endlessly many leftovers is checked by no such machine, and a machine with exactly that many states is a smallest one.

\text{drop the states no string reaches: the machine still checks } L @@ they are never entered
\text{each state } x \mapsto L(x),\ \text{the strings accepted from } x @@ the one map into the last machine (∞7)
\text{the image is the set of leftovers of } L @@ the state reached by u accepts exactly the w with uw in L
\htmlClass{new}{\text{states} \ge \text{leftovers}} \quad \blacksquare @@ the least-machine technique (∞7): a map onto a set has at least as many inputs
  
a^nb^n:\ \text{the leftover after } a^i \text{ holds } b^i \text{ and no other } b^j @@ so the leftovers after a⁰, a¹, a², … all differ: endlessly many, no machine
\text{remainder by } 3:\ \text{after remainder } 0 \text{ the empty string may follow; after } 1,\ \text{“1” may and the empty string may not; after } 2,\ \text{neither} @@ three leftovers: three states is the fewest
\htmlClass{new}{\text{depth up to } k:\ \text{after } d \text{ openings, exactly } d \text{ closings may follow alone; and the dead leftover is empty}} @@ k + 2 leftovers: k + 2 states is the fewest

What hides is the arrangement of a machine: the names of its states and its table. The pigeonhole of 12·comp7 is still there, inside “a map onto a set”. But it is no longer run on strings chosen for one language. The plan is the single map into the last machine, and every machine for L has it.

infcomp.5Every Sort Is One Map

17·comp counted the comparisons of three ways to sort and found three counts. It did not need to say that the three give the same sorted list, since that is what sorting means. Arrows say why there is only one answer to give, and where the three ways differ.

Write x ++ y for the list x followed by the list y. For sorted lists u and v, merge(u, v) is 17·comp4’s merge: compare the two fronts, move the smaller out, repeat. A sorted list is fixed by its items, counted with repeats. So merge(u, v) is the sorted list of the items of u and v together.

One-sort technique: there is exactly one function s from lists to sorted lists with s([a]) = [a] for every item a and s(x ++ y) = merge(s(x), s(y)) for all lists x and y that are not empty. So however a list is bracketed into pieces, merging the sorted pieces gives the same list.

\mathrm{sort}(x) = \text{the sorted list of the items of } x @@ a sorted list is fixed by its items
\mathrm{sort}([a]) = [a],\qquad \mathrm{sort}(x \mathbin{+\!\!+} y) = \mathrm{merge}(\mathrm{sort}(x), \mathrm{sort}(y)) @@ both sides are sorted and hold the same items, so sort is such a function
s \text{ any such function}:\quad s([a]) = [a] = \mathrm{sort}([a]) @@ lists of length 1
s(x \mathbin{+\!\!+} y) = \mathrm{merge}(s(x), s(y)) = \mathrm{merge}(\mathrm{sort}(x), \mathrm{sort}(y)) = \mathrm{sort}(x \mathbin{+\!\!+} y) @@ induction on the length (4c): x and y are shorter
\htmlClass{new}{s = \mathrm{sort}} \quad \blacksquare @@ every list of length 2 or more is some x ++ y

A bracketing of the items is a tree, as in ∞11, and each tree is a way to sort: sort the leaves below each split, then merge. The bracketing a(b(c(d))) merges one item at a time into a sorted rest, which is insertion sort. The bracketing that halves at every split is merge sort. By the technique the tree hides from the answer. It shows only in the cost.

\text{a split with } \ell \text{ leaves left and } r \text{ right costs at most } \ell + r - 1 \text{ comparisons} @@ merging (17·comp4)
a(b(c(\cdots))):\quad \textstyle\sum_{j=2}^{n} (1 + (j - 1) - 1) = \tfrac{n(n-1)}{2} @@ insertion sort’s worst count (17·comp3)
\text{halving}:\quad M(n) = n\log_2 n - n + 1 @@ the merge-count technique (17·comp4)
\htmlClass{new}{\ell + r - 1 \le \ell r,\ \text{and the } \ell r \text{ add to } \tfrac{n(n-1)}{2} \text{ on every tree}} @@ the leaf-product technique (∞11): no tree costs more than selection sort

What hides is the arrangement: the tree. Lists with ++ are the free way to join things in a row (∞3), and that is why one map out of them is fixed by what it does to single items. The plan of sorting is that one map. A sorting method is a choice of brackets, and the brackets are where the comparisons are spent.

The accepted names

The arrows A → T(B) of a wrapper, with ⋆, are the Kleisli category of the monad T; the maybe wrapper is the option or maybe monad, and stopping early is short-circuit evaluation. A check as an arrow that passes its input or fails is a guard, and an arrow not defined everywhere is a partial function. The argument of the second footing is the halting problem read through Lawvere’s fixed-point theorem. The category of the third footing, with numbers of wires as things, ∘ and ⊕, is a PROP, a kind of strict monoidal category; the fork is copying, or fan-out, and a set of boxes from which every table can be made is functionally complete. A leftover is a left quotient, or Brzozowski derivative, or residual language; the leftover-count technique is the Myhill–Nerode theorem, and the smallest machine is the minimal deterministic finite automaton. Lists with ++ are the free monoid, or with no empty list the free semigroup; sorted lists with merge are a commutative monoid, the multisets; and the one-sort technique says that sort is the unique homomorphism that extends the map on single items, the universal property of the free semigroup.

What the arrows let hide

In the ladder’s four words for a move that fails: the first footing hides sequence, and the other four hide arrangement. In each the plan is what is left, and it is one arrow or one row: q ⋆ p; φ : A × A → B; Rₙ; the map into the last machine; the map out of the lists. No dated claim is made on this page.
