40·eng · engineering

How Do You Know the Compiler Is Right?

40j proved that a compiler built right shape by shape keeps every run. Real compilers are millions of lines, and nobody has proved most of them. This annex shows how engineers test them anyway, and what a test can and cannot show.

Compile one program two ways and run both. A disagreement proves a fault; agreement only fails to find one.

40eng1A Second Opinion

Second-opinion technique: if two compilers turn one program into runs that end in different states from the same start, at least one of them breaks 40j’s demand; if they agree, neither is shown right.

Only one final state is right for the program, so two different states cannot both be right. Agreement leaves open that both are wrong the same way.

40eng2Programs Made at Random

A program that writes random programs, all of them with one meaning fixed by the language, feeds the compilers endless tests that nobody had to write. Each disagreement is cut down by hand to the smallest program that still shows it, and that small program goes to the compiler’s makers.

Testing of this kind has found hundreds of faults in the most used compilers. When it was run against a compiler whose middle had been proved right, it found no wrong-code faults in the proved part.

40eng3Tests Count Rows, Proofs Do Not

A compiler takes endless programs, so testing tries some rows of an endless table, as 1g warned. A proof covers every row at once. Tests find faults cheaply and proofs rule them out at a price, so engineers use both.

The accepted names

Comparing two implementations is differential testing, and generating random programs is fuzzing. Csmith is the best-known random generator of C programs, and CompCert is the C compiler whose middle had been proved right.
