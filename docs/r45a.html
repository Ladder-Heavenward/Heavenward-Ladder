45a · proof

Machines That Only Talk

Until now one machine did the work. From here many machines share it, and they share nothing but messages. This step sets down what a machine can know in such a network, and the one fact that every later impossibility leans on.

A machine knows its own state and the messages it has received, nothing more. Two runs that look the same to it get the same move from it.

45a1The Model

There are n machines joined by links. Each machine follows its own program, as in rung 40. A message sent may arrive after any delay, may be lost, and may arrive after a message sent later. There is no clock that all machines share.

A machine’s view is its own state and the list of messages it has received so far. Its next move is a function of its view and of nothing else.

45a2Runs That Look the Same

Same-view technique: if two runs give a machine the same view, the machine makes the same move in both.

Its move is a function of its view (45a1), and a function gives one value for one input (9a). So any argument that a machine must act differently in two runs must first show that its views differ.

45a3Slow or Dead

When delays have no bound, no machine can tell a crashed machine from a slow one. Take any run in which B has crashed, and stop it at any moment. Now take the run in which B is alive but every message B sent is still on its way. A has received the same messages in both, so by the same-view technique it acts the same in both.

So any rule of the form “if B has not answered, B is dead” is wrong in some run. Waiting longer only moves the moment.

45a4Bounds Change the Model

If every message arrives within a known time d, and every machine takes its steps at a known pace, then silence for longer than d means a crash. That is a different model, with bounds. Real networks lie between the two: the bounds usually hold, and sometimes do not.

The rest of the rung says which model each result needs, because a result proved with bounds can fail without them.

The accepted names

The model without bounds is the asynchronous model; with bounds it is synchronous; the usual case between is partial synchrony. The same-view technique is the indistinguishability argument, and a machine that stops for good has a crash fault.
