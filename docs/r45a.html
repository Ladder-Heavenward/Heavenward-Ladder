45a · proof

Numbers for Every Machine

Before machines can agree they must find each other, and before a message can be lost it must be addressed. This step sets down the one protocol every later step rides on: a number of fixed width for every machine, a cut in that number that names its network, and a packet that each router passes one hop onward by the longest prefix it knows. What the protocol promises is little, and the little is exact.

Every machine carries a number of fixed width. A router reads the destination, finds the longest prefix it matches, and passes the packet one hop on. Nothing else is promised.

45a1A Number of Fixed Width

The internet is a network of networks. Every machine on it, or every link a machine has, carries one number, and the whole design rests on the number having a fixed width: 32 bits in the older protocol, 128 in the newer. A 32-bit number has 2³² values, which is 4,294,967,296; a 128-bit number has 2¹²⁸, about 3.4 × 10³⁸.

People do not read 32 bits at a glance, so the number is written in groups. The 32-bit form is four groups of 8 bits, each written in decimal and separated by dots: 192.0.2.17. The 128-bit form is eight groups of 16 bits, each written in hexadecimal and separated by colons: 2001:0db8:0000:0000:0000:0000:0000:0001. The grouping is for the eye. The machine sees one number.

Fixed-width technique: a written number of fixed width can be read back whatever is left out of it, as long as what is left out can be counted from the width. The next footing spends this.

45a2Why Two Colons Can Stand for Zeros

Most 128-bit addresses hold a long run of zero groups, and writing eight groups out is tiresome. The rule is this. Leading zeros in a group may be dropped, because a group is a number and 0db8 is db8. One run of consecutive all-zero groups may be replaced by a double colon. So the address above is 2001:db8::1.

Here is why the double colon can be read back. There are always eight groups. The written form shows some of them, say s. Then the double colon stands for exactly 8 − s groups of zeros, and nothing is lost. In 2001:db8::1 three groups show, so the colon stands for five.

And here is why it may appear only once. Suppose two double colons stood for k missing groups between them. The k could be split as 1 and k − 1, or 2 and k − 2, and so on: k − 1 ways, every one a different address. One double colon has one reading; two have many. So the rule is a theorem of fixed width, not a convention.

The accepted written form adds three choices so that every address has one spelling: the double colon stands for the longest run, the first if two are equal, and never for a single zero group, which is written 0. Letters are lower case. The 32-bit form has no such rule, since 192.0.2.0 is short already.

45a3The Cut: Prefix and Host

A router cannot hold a line for every machine in the world. So the number is cut at a chosen bit. The first p bits are the prefix, which names a network; the rest name a machine within it. The cut is written after a slash: 192.0.2.0/24 is every address whose first 24 bits are those of 192.0.2.0, which is 256 addresses, 192.0.2.0 to 192.0.2.255. A prefix of length p covers 2³²⁻ᵖ addresses, or 2¹²⁸⁻ᵖ in the longer form.

The cut gives the number a shape that counting alone does not. Every machine on one network shares one prefix, so a router far away needs one line for all of them: where to send anything beginning 192.0.2. A network can be cut again at a deeper bit, so that one prefix holds many smaller ones, each a prefix in its own right. The lines a router holds are prefixes, never single machines, unless a prefix is all 128 or all 32 bits long.

Two prefixes either nest or are disjoint. If one address lies in both, the shorter is a beginning of the longer, so the longer lies wholly within the shorter. That is the fact that makes the next footing's rule well defined.

45a4Best Effort, One Hop at a Time

A message is cut into packets. Each packet carries a header and a load. The header holds the source number, the destination number, the length, a hop count, and a few marks; the load is whatever the layer above wrote. Each router reads only the destination. It looks through its lines for the prefixes the destination matches and chooses the longest, which is the most specific; it passes the packet to the next hop that line names; and it lowers the hop count by one. A packet whose count reaches 0 is thrown away, so that a loop between routers cannot carry a packet for ever.

Longest-prefix technique: send toward the next hop of the longest prefix the destination matches; a more specific line beats a shorter one. The prefix of length 0 matches everything and is the default route, used when nothing longer matches. By 45a3 the matching prefixes nest, so the longest is unique, and the rule always names one hop.

Notice what no router knows: the path. Each knows a next hop, and the path is the sum of choices no one sees whole. And notice what the protocol promises: that each router will try. A packet may be lost, delayed, delivered twice, or delivered after one sent later. This is best effort, and it is exactly the model of 45b. Everything a machine can rely on beyond it is built above, in 45c's handshakes and 45d's counters.

45a5What the Number Does Not Say

The number says where, not who. It belongs to a place in the network, so it changes when a machine moves, a machine with two links has two, and many machines may stand behind one, as 45·comp tells. Nothing in the header proves the source number is true, since any machine may write any number there; that is the door 45g's liars come through. And since no router keeps the packet, nothing in the network remembers that a packet passed. Whatever is to be sure, the ends must make sure of, by messages of their own.

So the protocol is small on purpose. It names, it cuts, it forwards, and it drops. Every certainty the rest of the rung wins is won on top of a floor that promises nothing but a try, and the proofs that follow are sharp because the floor is.

The accepted names

The protocol is the Internet Protocol, IP, specified for 32-bit addresses in RFC 791 (1981) and for 128-bit addresses in RFC 2460 (1998), now RFC 8200 (2017). The 32-bit written form is dotted decimal; the 16-bit groups of the 128-bit form are hextets, and their one spelling is laid down in RFC 5952 (2010). The cut is the prefix length, and the slash form is CIDR notation; the older form of the same cut was the subnet mask. A packet is a datagram, the hop count is the time to live in the older protocol and the hop limit in the newer, and the rule of 45a4 is longest-prefix match. The promise of a try is best effort, and the claim of 45a5 that certainty lives at the ends is the end-to-end argument.
